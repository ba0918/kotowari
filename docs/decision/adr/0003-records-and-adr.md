# ADR-0003: 判断の記録と ADR を両方残し、ADR は判断の番号を指す

- 状態: 承認済み（2026-09-13）
- 日付: 2026-09-13
- 判断の記録: `brainstorm/records.md` の A3、A22、A23、A35、A43、R1、R2（A22 の節の構成は A43 で改めた）
- 改訂: 2026-09-17 の [decision-log の A5](../brainstorm/2026-09-17-decision-log.md#A5) で、新しい ADR を書く義務をやめた（既存の ADR は残す）。却下した案の「判断の記録だけにして ADR をやめる」はその範囲で改められている

## 状況

判断の記録（brainstorm で決めたことを1行1決定で並べたもの）と ADR は、どちらも意思決定の記録で、内容がほぼ重なって見える。
実験002の IR の出典291件のうち ADR を指す69件のほぼ全部は「決定」と「結果」の節で、判断の記録の言い直しだった。
また、判断の記録を1つのファイルにすると、次の brainstorm で上書きされる。

## 決定

判断の記録の A22（節の構成は A43 で改めた後）、A23 と、ファイル名は A3 のとおり。

## 理由

- 判断の記録はすべての決定を1行ずつ持ち、ADR は重要、後から変更コストが高く取り返しがつかない、文脈がないと初見の人が混乱する、トレードオフの結果、の4つの基準に当たる判断だけを、状況と理由と却下した案と結果とともに持つ（A43）。役割が違う
- ADR の「決定」の節が判断の番号を指して振る舞いを繰り返さなければ、重なりは構造で消える
- ADR にしなかった判断も判断の記録に残るので、後から追える（利用者）
- 判断の記録を brainstorm ごとに別ファイルにすれば、上書きされない。設定の判断の記録の置き場はディレクトリで、その下のどのファイルの決定も出典に指せる（A48）

## 却下した案

- ADR だけにして判断1件ごとに ADR を切る: 002 なら52本になり、理由の無い ADR が大半になる
- 判断の記録だけにして ADR をやめる: 1ファイルに全部入り、粒度の考え方と衝突する

## 結果

初見の人は「なぜ記録が2種類あるのか」と思いうる。この ADR がその文脈を残す。
