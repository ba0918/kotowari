# ADR-0004: IR の形はコードに固定し、スキーマのファイルは作らない

- 状態: 承認済み（2026-09-13）
- 日付: 2026-09-13
- 判断の記録: `records/records.md` の A6、A17、A25、A42、A43、R4、R5、U24

## 状況

IR は Markdown で、自由な形式なので曖昧な指定しかできないのが弱点である（利用者）。
形を守らせるには、形を宣言して検証する仕組みが要る。
既存の道具として mdschema、mdvalidate、document-schema があり、スキーマを宣言して Markdown の構造を検証する発想は実在する（調べて分かった事実。A43）。

## 決定

判断の記録の A25 と A42 のとおり。

## 理由

- 形は今1つしかなく、変えられるようにする需要がまだ無い
- スキーマのファイルを読む形にすると、ミニ・スキーマ言語を作ることになり、題材の上限に響く
- 外部の道具を前段に置くと、利用者に別の言語の道具の導入を求めることになる

## 却下した案

- スキーマのファイルを CLI が読む: ミニ・スキーマ言語を作ることになる
- 外部の mdschema を前段に使う: Go の道具の導入を求める

## 結果

形を変えるには CLI のコードと仕様書の両方を変える。
Markdown のスキーマを宣言して検証する道具を Rust で作る案は、この題材の次の道具の候補として残す（U24）。形式手法の対象になりうる。
