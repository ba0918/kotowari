# IR の形の契約

- 判断の記録: `records.md` の A25、A27、A28、A30、A31、A33、A38、A40、A42、A47、A50、A52〜A57、A61、A62〜A73、A81〜A84、A87〜A97、A98〜A161
- 日付: 2026-09-13
- 改訂: 2026-09-16。IR の置き場を再帰で読む変更（`2026-09-16-ir-tree.md` の A1〜A20）に合わせて、文書・ID・項目・出典・文書名の参照・検査の種類・出力の節を改めた。改めた箇所には T1 のように同記録の番号を添える

このファイルは、`kotowari check` が読む IR（`docs/ir/*.md`）の形と、検査の種類と、出力の形を定めた契約である。
判断の記録の一部として出典に使える（A52）。正規化を行う LLM にも渡す。

## 文書

- IR の置き場の下のディレクトリを深さに制限なく辿って `*.md` を読む（ir-tree A1）。どのディレクトリでも `CONTEXT.md` は用語集、`FLAGS.md` は問題の記録、それ以外は話題ごとの文書（ir-tree A8）
- 文書から見える用語は、その文書のディレクトリから置き場の根までの各 `CONTEXT.md` の用語の合計（連鎖。根に近い方が先）。隣の枝の `CONTEXT.md` の用語は見えない。連鎖に `CONTEXT.md` が1つも無ければ用語集が無いものとして扱う（ir-tree A3）
- 各文書は `# ` の題名を1つだけ持つ
- 題名の後、最初の `## ` か `### ` より前の空でない行を「文書が扱う範囲」とし、話題ごとの文書は1行以上持つ。`CONTEXT.md` と `FLAGS.md` は持たなくてよい
- 話題ごとの文書は `## 要求`、`## 決定表`、`## 性質`、`## 具体例` の節を持ち、要らない節は省く。要求は `## 要求` の下に、決定表は `## 決定表` の下に、性質は `## 性質` の下に、シナリオは `## 具体例` の下に置く
- 行は `\n` で数え、`\r\n` は1行、最後の行に改行が無くても1行に数える。行は1始まり。文字コードは UTF-8
- コードブロック（行頭の3つ以上の `` ` `` か `~` で始まる行から、同じ文字で同じ数以上の行まで。A108）の中は、Gherkin のブロック以外すべて検査の対象外。閉じられずに文書が終われば `unclosed_code_block`
- 読むのは拡張子が小文字の `.md` のファイルだけ。ファイルのシンボリックリンクは読む。先頭の BOM は読み飛ばす（A102、A107）。隠しディレクトリとディレクトリのシンボリックリンクはどの深さでも辿らず、空のディレクトリには指摘を出さない。置き場の下のディレクトリが読めなければ停止（ir-tree A13、A16）
- 読めない・壊れている・形に合わない入力は、必ず停止か指摘にする。読まないものは仕様に列挙した除外（隠しディレクトリ、ディレクトリのシンボリックリンク、ディレクトリでも通常のファイルでもないもの、`.md` 以外、`.kotowari` という名前のファイル、形に合わない見出しの下の行、コードブロックの中、Gherkin の外の `Scenario:`、`## ` の直下で最初の `### ` より前の行、題名より前の行、テストの外と本体の途中の印、二重引用符の中、奇数の二重引用符の後ろ、用語の検査の対象外の行）だけ（A100、A102、A145）。先の無いシンボリックリンクは読めないファイルとして停止（A146）

## ID

- ID は `REQ-`、`TBL-`、`PROP-`、`EX-`、`FLAG-` のいずれかに3桁以上の数字を続けたもの（`REQ-001`、`REQ-1000`）。4桁以上のときは先頭を `0` にしない（`REQ-0001` と `REQ-1` は形に合わない）。以下の `nnn` はこの数字を表す（ir-tree A6、A11）
- ID は文書をまたいで一意

## 項目

- 要求は `### REQ-nnn: 名前` の見出しの下に `- 種類:`、`- 出典:`、`- 検証:` の行と文を持つ。種類は `event_driven`、`state_driven`、`ubiquitous`、`prohibition`、`invariant`、`algorithm` の6つ。検証は `unit`、`property`、`proof`、`review` の4つ。`algorithm` は文を持たず、`- 定義:` の行で決定表と性質の ID を指す。`algorithm` 以外の要求に `- 定義:` があってもよい。文が EARS の型に沿うかは検査しない
- 決定表は `### TBL-nnn: 名前` の見出しの下に `- 出典:` の行と Markdown の表を持つ
- 性質は `### PROP-nnn: 名前` の見出しの下に `- 出典:` の行と文を持つ
- シナリオは ```` ```gherkin ```` のコードブロックの中の `Scenario:` で、直前の行にタグ `@id=EX-nnn`、`@about=ID,...`、`@source=出典,...` を持つ。タグはこの3つだけ。値が空のタグは無いものとして扱う（A97）。タグの行は `Scenario:` の直前の行だけを結び付け、`@` で始まらない語は `unknown_tag`。ブロックの中の行は行頭の空白を除いて見て、タグ・`Scenario:`・ステップ・`#` の注釈・空行以外の行（`Feature:` や `Examples:` やデータ表を含む）、`Scenario:` に続かないステップ、`Scenario:` が直後に無いタグの行は `invalid_gherkin_line`（A132、A133、A155）。`@id` の値が `EX-nnn` の形でなければ `invalid_id` で、定義に数えない（A109、A110）
- 用語集は各ディレクトリの `CONTEXT.md` の `| 用語 | 意味 | 出典 |` の表。意味の列は用語と曖昧語の検査を受けない。同じ用語集の前の行か、連鎖の根に近い側の用語集に同じ用語があれば、その行に `duplicate_term` を出し、その行は定義に数えないが語は根に近い側の定義で見えたまま（ir-tree A4）
- 問題の記録は各ディレクトリの `FLAGS.md` の `### FLAG-nnn: 名前` の見出しの下に `- 種類:`（`contradiction`、`gap`、`ambiguity`）、`- 関係:`（ID をコンマ区切り）、`- 出典:` の行と本文を持つ。本文は用語と曖昧語の検査を受けない
- 見出しの下に置ける `- xxx:` の行は、項目の種類ごとに上に挙げたものだけ（性質は `- 出典:` だけ。A81）。知らない行は `unknown_field` にし、その中身（ID など）は読まない（A87）。見出しの下の `- ` の行は順不同で、空行を挟んでよい。必須の行が無いときは、検証の行なら `verification_missing`、出典の行なら `missing_source`、それ以外（要求の種類、問題の記録の種類と関係）なら `missing_field`（A92）。決定表に表が無ければ `missing_table`。Gherkin のブロックの外の `Scenario:` はシナリオと見なさない。`- 定義:` と `- 関係:` の ID、`- 出典:` の出典はコンマで区切って複数書ける
- 文は、見出しの下の、一覧でも表でもない空でない行

## 出典

- `パス#印` で、最初の `#` で分ける。パスに `#` は書けない。パスは基準のディレクトリ（リポジトリ直下）からの相対で、`docs/decision/records/records.md#A12` のように置き場からの全体を書く（A84。置き場は ir-tree A2 で移した）
- パスが判断の記録（決定の節の見出しを1つ以上持つファイル。A134）なら、印は決定の番号（`A26`、`P1` の形）で、そのファイルの決定の節（Agreements、Prohibitions、Delegated、Rejected）に `- A26 ` で始まる行か `- A26` だけの行があること（A91）
- パスが判断の記録の置き場か ADR の置き場にあるそれ以外の Markdown（ADR、形の契約、補足の文書）なら、印は `## 見出し` の文字で、前後の空白を除いた完全一致
- 用語集の出典の列と、シナリオの `@source` も同じ検査を受ける

## 用語と曖昧語

- 検査の対象は、要求の文、性質の文、Gherkin の `Given`、`When`、`Then`、`And`、`But` の行。`Scenario` の行、`- ` の行、タグの行は対象外（`Feature:` は IR に書かない。A133）
- バッククォートで囲んだものは、例外なく用語集の用語か ID でなければならない。二重引用符の中は見ない（A145）。パスやコード片も同じ。具体的な値は二重引用符で書く。用語を囲み忘れたことは検出しない。用語集が無くても ID は通る
- 曖昧語は設定の `vague_words` の語の部分一致
- 指摘は出現ごとに1件

## 文書名の参照

- コードブロック（Gherkin のブロックを含む）の外にある、並びの先頭の直前が英数字・`_`・`-`・`/`・`.`・バッククォートのいずれでもなく（行頭を含む。空白・句読点・日本語の文字は境界。ir-tree A21）、要素（「英小文字と数字とハイフン」の並び、`.`、`..` のいずれか）を `/` で区切って1つ以上並べ、最後の要素が「英小文字と数字とハイフン」に `.md` が続く並びを文書名の参照とする。`/` を含まない並びは参照を書いた文書と同じディレクトリの文書を指し、上へは辿らない。`/` を含む並びは IR の置き場からの相対パスを指す。`.` か `..` の要素を含む並びは解決せず `missing_document`。文書の有無は読んだ IR の文書の中に有るかで見る（ir-tree A5、A17、A18）。二重引用符の中の並びは参照に数えない（置き場の外のパスや ADR のファイル名は二重引用符で書く。ir-tree A15）。`.md` の直後に英数字、`_`、`-`、`#`、`/` が続けば参照ではない（出典の `パス#印` は参照にならない。ir-tree A14）。行の中の二重引用符が奇数なら最後の引用符から行末までを引用の中と見なす（A118）

## 検査の種類

誤り（終了コード1）。`detail` は指摘を特定する短い文字列で、右の列のものを入れる。

| 種類 | 意味 | `detail` |
|---|---|---|
| `missing_title` | `# ` の題名がない | 文書名（ディレクトリを除いたファイル名。ir-tree A19） |
| `multiple_titles` | `# ` の題名が2つ以上ある | 2つ目の題名 |
| `missing_scope` | 話題ごとの文書に、文書が扱う範囲の行がない | 文書名 |
| `unknown_heading` | `### ` の見出しが、REQ、TBL、PROP、FLAG の ID に名前を続けた `### ID: 名前` の形でない（EX の ID を見出しに使ったとき、`#### ` より深い見出しを含む。A82、A111） | 見出しの文字 |
| `unknown_field` | 見出しの下に知らない `- xxx:` の行、または `xxx:` の形でない一覧の行（`- `、`* `、`+ `、数字と `.`、`-` だけ）がある（A111） | 読んだ行の文字そのまま |
| `missing_field` | 見出しの下に必須の `- xxx:` の行がない | 行の名前 |
| `missing_table` | 決定表に表がない | 決定表の ID |
| `duplicate_field` | 見出しの下に同じ `- xxx:` の行が2つ以上ある | 行の名前 |
| `missing_source` | 出典の行がない、または空の要求、決定表、性質、問題の記録。`@source` のないシナリオ。出典の列が空の用語 | 項目の ID か用語。`@id` の無いシナリオでは `Scenario:` の行の文字（A90） |
| `source_invalid` | 出典が判断の記録の置き場か ADR の置き場の中を指していない、書式が違う、決定の番号が判断の記録の決定の節にない、ADR のファイルか `## 見出し` がない | 出典の文字列 |
| `unknown_term` | バッククォートで囲んだものが用語集にも ID にもない。用語集が無ければすべて | 囲んだ文字列 |
| `missing_document` | 文書名の参照の先が、読んだ IR の文書の中にない（ir-tree A5、A17、A18） | 文書名の参照の文字列 |
| `missing_statement` | `algorithm` 以外の要求、または性質に文がない | 項目の ID |
| `verification_missing` | 検証の行のない要求 | 要求の ID |
| `verification_invalid` | 検証の値が4つ以外 | 値 |
| `unknown_kind` | 要求か問題の記録の種類が決まった値でない | 値 |
| `duplicate_id` | 同じ ID が2か所以上にある。2つ目以降の場所ごとに、その見出しの行（シナリオは `Scenario:` の行）に出す | ID |
| `unresolved_reference` | 定義の行、`@about`、問題の記録の関係、文の中でバッククォートで囲んだ ID、印が、存在しない ID を指す。印の中の ID の形でない要素も同じ（A89） | ID |
| `algorithm_without_definition` | `algorithm` の要求が定義の行で決定表も性質も指していない | 要求の ID |
| `missing_tag` | シナリオに `@id` か `@about` がない | 無いタグの名前 |
| `unknown_tag` | シナリオのタグが3つ以外 | タグの名前 |
| `vague_word` | 対象の行に `vague_words` の語が含まれる | 語 |
| `requirement_without_test` | 検証が `review` 以外の要求で、その ID を含む印が1つもない | 要求の ID |
| `test_without_id` | テストなのに印がない | 関数の名前 |
| `invalid_marker` | テストに結び付く印が空か区切りだけ、または同じ行に閉じ括弧がない。テストの外の印は見ない（A121） | 読んだ行の文字そのまま |
| `unparsable_file` | テストのファイルを tree-sitter で読めない（構文の誤りが1つでもある）。そのファイルは飛ばす | ファイルのパス |
| `unclosed_code_block` | コードブロックが閉じられずに文書が終わる（A108） | 開始の行の文字そのまま |
| `invalid_gherkin_line` | Gherkin のブロックの中の、タグ・`Scenario:`・ステップ・注釈・空行以外の行（A109） | 読んだ行の文字そのまま |
| `invalid_id` | `@id` の値が `EX-nnn` の形でない（A110） | 値 |
| `glossary_invalid` | 用語集の文書があるのに `| 用語 | 意味 | 出典 |` の表が無い（A112）。その用語集の用語を0語として扱い、連鎖のほかの用語集は見えたまま（ir-tree A3） | 文書名 |
| `unclosed_backtick` | 対象の行のバッククォートが奇数（A116） | 読んだ行の文字そのまま |
| `invalid_glossary_row` | 用語集の表の中の、セルが3つ未満か用語のセルが空の行（A153、A163） | 読んだ行の文字そのまま |
| `duplicate_term` | 同じ用語集の前の行か、連鎖の根に近い側の用語集に同じ用語がある。その行は定義に数えない（A154、A162、ir-tree A4） | 用語 |

注意（終了コードを変えない。severity は notice）:

| 種類 | 意味 | `detail` |
|---|---|---|
| `too_many_lines` | 文書の行数が `limits.lines` を超える | 行数 |
| `too_many_requirements` | 文書の要求の数が `limits.requirements` を超える。`CONTEXT.md` と `FLAGS.md` は数えない | 要求の数 |

`missing_title`、`multiple_titles`、`missing_scope`、`too_many_lines`、`too_many_requirements` は文書全体への指摘、`unparsable_file` はファイル全体への指摘、`glossary_invalid` は用語集の文書全体への指摘で、`line` を null にする（A83、A112）。

## 出力

- `--format json`（既定）は、標準出力に1つの JSON を出す。最上位は `files`（読んだ IR の文書の数。用語集と問題の記録を含む）、`lines`（IR の行数の合計）、`findings`（指摘の一覧）、`counts`（種類ごとの数。0件の種類は含まない）、`tests`（読んだテストのファイルの拡張子ごとの数と、その拡張子が問い合わせのある言語か。check-reach A8）。各指摘は `kind`、`severity`（`error` か `notice`。notice A1）、`path`（基準からの相対。置き場と、置き場からの文書の相対パスをつなぐ。ir-tree A13）、`line`（文書全体への指摘は null。1始まり）、`detail`
- `findings` は `path` のバイト順、`line`（null が先、その後は小さい順）、`kind` のバイト順、`detail` のバイト順に並べる
- `--format text` は1指摘1行で `パス:行 [error|notice] 種類 詳細`（warning は notice に改めた。notice A1）。`[error]` と `[notice]` は角括弧ごと出す。`line` が null なら行を `-` と書く
- 終了コードは、0 が誤りなし（注意だけを含む。`--help` と `--version` も0）、1 が誤りあり、2 が停止。オプションは `check` の前後どちらでもよい（A103）
- 停止のとき標準エラーの1行目は `<理由>: <詳細>` で、理由は `config error`、`argument error`、`unreadable file`、`non-UTF-8 file` の英語の固定文言。詳細のパスは基準のディレクトリからの相対。出力の文言は英語。`--help` と `--version` はほかの引数に勝ち、`check` 無しでもよい（A104、A136、A137）
- 設定の値のパスと出典のパスは、末尾の `/` と先頭の `./` を除き `\` を `/` に直して正規化してから比べる（A106）
- 停止の理由は、設定の誤り（`vague_words` の空の文字列を含む。A93。YAML の構文の誤り、同じキーの2回目、null の値、絶対パス、`vague_words` の重複、glob の構文の誤りを含む。A105、A135）、引数の誤り、読めないファイル（IR や決定の置き場が無いとき、または読めないとき、IR と決定の置き場の下のディレクトリやテストの走査のディレクトリが読めないときを含む。A95、A96、ir-tree A16）、UTF-8 でないファイルの4つ。テストのファイルの走査ではディレクトリのシンボリックリンクを辿らず、ファイルのシンボリックリンクは読む（A94 を A102 で改めた）。停止のときは標準出力に何も出さず、理由を標準エラーに出す
