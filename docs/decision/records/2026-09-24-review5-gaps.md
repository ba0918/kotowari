# 壁打ちの記録: 5回目の外部レビューで見つかった kotowari の仕様の穴

## Context

5回目の外部のレビュー（GPT、2026-09-24。範囲は kotowari-core の `lib.rs`、`sources.rs`、`terms.rs`）で、3つが見つかった。二重引用符を挟んだバッククォートの囲みが崩れて後の囲みと組み違えること（[REQ-core-064](../../ir/core/terms.md#REQ-core-064)）、改行を含むファイル名で文字の出力の1つの指摘が複数の行に分かれること（[REQ-core-025](../../ir/core/output.md#REQ-core-025)）、decisions.records と decisions.adr が親子に重なるときにどちらの置き場のファイルとするかを IR が決めていないこと（[TBL-core-012](../../ir/core/sources.md#TBL-core-012)）である。どれも利用者が「ほぼ答えが決まっているものは推奨で決めてよい」とした範囲で決める。

Position: A1〜A3 を決めた。承認済み（2026-09-24）。

## Agreements

- A1 二重引用符の外のバッククォートを行の左から順に対にし、対の間の元の文字（二重引用符を含んでよい）を囲みの中身にする。二重引用符で区切った断片ごとには対にしない
  - why: 今は断片ごとに対にするので、`未知 "値" 未知` のような囲みが崩れ、後の囲みと組み違えて囲みでない文字を unknown_term にし、本当に知らない語を見逃す。奇数かどうかの判定（[REQ-core-116](../../ir/core/terms-form.md#REQ-core-116)）は既に断片をつないで数えているので、対にするのも同じ見方に揃える
  - rejected: 断片をつないでから対にし、中身から二重引用符の中を除く。detail が書いた文字と違う文字になる
  - decided_by: 利用者（推奨を採用）

- A2 文字の出力では、パスと detail の中の改行（"\n" と "\r"）を、バックスラッシュと "n" または "r" の2文字で書く。JSON の出力は変えない
  - why: 「1つの指摘を1行で出す」（REQ-core-025）はファイル名が改行を含むと守れない。行で読む道具の前提が崩れないように、見た目の1行を保つ
  - decided_by: 利用者（推奨を採用）

- A3 パスが decisions.records と decisions.adr の両方の中にあるとき（一方の置き場が他方の下にあるとき）は、深い方の置き場の中のファイルとして判定する。今の振る舞いを IR に書く
  - why: 下に置いた置き場は、その場所のファイルをその種類として読ませたい意図と読むのが自然で、浅い方の設定だけで判定が変わらない。置き場の重なりを設定の誤りにすると、"." のような置き場の下に別の置き場を置く今の使い方ができなくなる
  - rejected: 置き場の重なりを設定の誤りにする
  - decided_by: 利用者（推奨を採用）
