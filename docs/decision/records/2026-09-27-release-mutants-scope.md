# 壁打ちの記録: タグの push で回す変異テストの範囲

## Context

タグを push するときは pre-push のフックが変異テストを全体で回す（[A26（変異テスト）](./2026-09-17-mutation-tests.md#A26)）。A26 は全体の実走を「十数分」と見込んでいた。
2026-09-26 の kotowari-v0.1.0 の push では変異 1,800 件の全体の実走に 8,175 秒（約2時間16分）かかり、その間 push が止まった（見逃し0、時間切れ33、コンパイルできない変異206、等価4）。
main への push ごとに origin/main との差分の変異はすでに回している（[A25（変異テスト）](./2026-09-17-mutation-tests.md#A25)）。見込みが外れたので、リリースのときに何を回すかを決め直す。

Position: 承認済み（2026-09-27）。第1ラウンドで A1〜A4 を決めて木が尽きた。変異テストの記録の A26 を A1 で改めた。

## Agreements

- A1 タグを push するときは、同じ製品の1つ前のリリースのタグ（kotowari なら "kotowari-v*"）との差分に入る変異だけを回し、前のタグが無いときだけ全体を回す
  - why: 全体の実走は見込みの十数分ではなく約2時間16分かかった。リリースの範囲の変更は main への push ごとに差分の実走を通っていて、前のリリースからの変更をまとめて1回確かめ直せば、ふだんの push の差分の基準のずれも拾える。LLM がリリースの手順を飛ばしても止まる関門は残る
  - rejected: 全体の実走を続ける（A26）。2時間を超える待ちが関門にあると、リリースを避ける理由になる
  - decided_by: 利用者（推奨を採用）

- A2 変更していないコードの見逃し（そのコードの変異を捕まえていたテストを消したり弱めたりしたときに生まれるもの）は関門にせず、全体の実走は人が "scripts/mutants.sh full" で好きなときに回す。その回し方と、差分の実走ではこの見逃しが見つからないことを PROJECT.md に書く
  - why: 2時間を超える待ちは関門に置けない。この見逃しはテストを消す差分のレビューで気づける範囲。関門で止めるものだけをガードレールと呼ぶ（[A25（変異テスト）](./2026-09-17-mutation-tests.md#A25)）考えから一歩下がるので、その判断として残す
  - decided_by: 利用者（推奨を採用）

- A3 全体の実走を速くする工夫（並列数、テストの走らせ方）は今回はしない
  - why: 並列数1はメモリを食い尽くす変異への備えで、上げるならメモリの上限と一緒に測り直す別の仕事になる
  - decided_by: 利用者（推奨を採用）

- A4 この決まりは IR に書かず、この記録と "scripts/mutants.sh" の選び方、"lefthook.yml" のコメント、PROJECT.md に書く
  - why: 0件の強制はフックの設定で、IR の要求にはしない（[A27（変異テスト）](./2026-09-17-mutation-tests.md#A27)）
  - decided_by: 利用者（推奨を採用）
