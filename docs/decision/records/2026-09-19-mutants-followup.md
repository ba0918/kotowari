# 壁打ちの記録: 変異テストの後始末

## Context

[変異テストの取り込み](./2026-09-17-mutation-tests.md) の後、全体の実走で残った見逃し30件を調べた（調べの記録は `.agents/artifacts/mutants/` に置いた追跡外の作業ファイル）。
30件の内訳: 20件はコードの単純化で変異そのものを消し、2件はその単純化の副作用で既存のテストが捕まえるようになり、3件は反証の席（別の文脈の LLM に落とすテストを書かせる）を通して等価の一覧に載せた。
残った5件は、仕様が定めていない境界に掛かっていた: `src/lib.rs` の `split_outside_quotes` の戻り値だけが変わる4件（[TBL-core-014](../../ir/terms.md#TBL-core-014) は引用符の文字の帰属や空の部を定めていない）と、`src/sources.rs` の `parse_links` でリンクとして読めた後の再開位置が変わる1件（[TBL-core-023](../../ir/revision-link.md#TBL-core-023) は読み飛ばすときの再開位置しか定めていない）。ほかに、[A17（kotowari-skill）](./2026-09-14-kotowari-skill.md#A17) が列挙で決めた発火語に変異テストの語が無く、取り込みの記録の Position が残る判断として挙げていた。
今決めるのは、見逃しが1件でも残る間は push の前のフックがタグの push を止め（[A26（mutation-tests）](./2026-09-17-mutation-tests.md#A26)）、次のリリースに進めないため。仕様が定めていない境界をテストで固定するのは避ける（[A5（mutation-tests）](./2026-09-17-mutation-tests.md#A5)）ので、先に仕様を決める。
決めたいのは、「等価」の観測の範囲、リンクの再開位置、発火語の追加。

Position: 承認待ち（2026-09-19）。2ラウンド（A1〜A6、A7〜A11）で木は尽き、品質と照合のレビューの指摘から第3ラウンド（A12、A13）を足した。実装は A10 のとおり2つの iterate に分ける。

## Agreements

- A1 「等価」の「観測できる振る舞い」は kotowari の出力（指摘、集計、終了コード、停止）だけ。pub 関数の戻り値や内部の状態は含めない
  - why: 言語に依存し始めると取り扱う問題が多くなり、設計がだるま式に膨らむ。lib は CLI のための crate で、公開 API を約束していない
  - rejected: pub 関数の戻り値も観測に含める（結合テストが pub 関数を直接呼ぶ以上、実装の形を固定するテストが増える）
  - decided_by: 利用者（推奨を採用）
  - superseded_by: [A13](#A13)（出力の列挙の部分だけ。戻り値と内部の状態を含めない本体はそのまま）

- A2 `split_outside_quotes` の4件の見逃しは等価として既存の手順（[A22](./2026-09-17-mutation-tests.md#A22) の単純化 → [A28](./2026-09-17-mutation-tests.md#A28) の反証の席 → 一覧）に流す。[TBL-core-014](../../ir/terms.md#TBL-core-014) の文言は変えない
  - why: どの入力でも指摘に差が出ないので、TBL-core-014 に足す文は検証できない文になる
  - rejected: TBL-core-014 に「引用符の文字自体は中」と書く（今それを読む要求が無く、検証できない）
  - decided_by: 利用者（推奨を採用）

- A3 [TBL-core-023](../../ir/revision-link.md#TBL-core-023) で、リンクとして読めた後の走査はその ")" の次の文字から続ける。リンクの中の "["（href の中を含む）から別のリンクを読み始めない。`[]([)]()` はリンク1つ（href は "["）で、順2の誤り1件
  - why: 「リンクは "[" から ")" まで」の文と整合する。1つのリンクの中身をもう一度リンクとして読むのは、その定義と矛盾する
  - rejected: "[" の次から続ける（読み飛ばしと同じ規則に揃う。`[]([)]()` で href が "[" と空の2件が出る）
  - decided_by: 利用者（推奨を採用）

- A4 A3 を TBL-core-023 に文として足す。具体例（シナリオ）は足さない
  - why: `[]([)]()` の形を人が superseded_by に書く場面を名指しできず、具体例は証拠の条件（運用上の生産者）を満たしにくい。文があれば見逃しの変異をその文を根拠にした単体テストで落とせる
  - decided_by: 利用者（推奨を採用）

- A6 この3つの判断は新しい記録1本（この記録）にまとめ、A17（kotowari-skill）、用語集の「等価」、TBL-core-023 の改訂はここから指す
  - why: この束が1回の改訂だったことが履歴で分かる
  - rejected: 発火語だけを取り込みの記録に A61 として足す
  - decided_by: 利用者（推奨を採用）

  - why: A1 を用語の定義に落とす。定義文が2か所にあると、片方だけ直したときにずれる

  - rejected: 全部を1回で（安いが、仕様の差分とコードの単純化の差分が1つのレビューに混ざる）
