# 壁打ちの記録: 7回目の外部レビューで見つかった仕様の穴

## Context

7回目の外部のレビュー（GPT、2026-09-24。範囲は kotowari-core の `config.rs`、`record_form.rs`、`finding_map.rs` と、mds の `document.rs`、`main.rs`）で、4つが見つかった。置き場の設定に "a/.." があると置き場の中のファイルが外に見えること（[REQ-core-110](../../ir/core/base-directory.md#REQ-core-110)）、見出しの打ち消し線の中の文字が名前から消えること（[REQ-schema-024](../../ir/schema/document-structure.md#REQ-schema-024)）、2つ目の題名の後の行が前の項目に入ること（[REQ-schema-022](../../ir/schema/document-structure.md#REQ-schema-022)）、"kotowari-mds" で同じオプションを2回渡したときの扱い（[TBL-schema-009](../../ir/schema/cli.md#TBL-schema-009)）である。どれも利用者が「ほぼ答えが決まっているものは推奨で決めてよい」とした範囲で決める。

Position: A1〜A4 を決めた。承認済み（2026-09-24）。

## Agreements

- A1 パスの正規化（REQ-core-110）で "a/.." を畳む。畳む相手の無い ".." は残し、基準の外を指すパスのままにする。設定ファイルの値のパスにも出典のパスにも同じ正規化をかける
  - why: 今は "a/.." を畳まないので、置き場を "docs/decision/../decision/records" と書くと、その中の記録を指す出典も改訂のリンクも置き場の外と判定された。改訂のリンクの先のパスは既に ".." を畳んでいて、置き場の側だけ畳まないので食い違っていた
  - decided_by: 利用者（推奨を採用）

- A2 見出しの名前は、インラインの記法を除いた文字とし、打ち消し線の中の文字も残す
  - why: 強調、太字、リンク、コードの中の文字は残していたのに、GFM の打ち消し線だけ中の文字ごと捨てていた。宣言した名前と同じ見出しが宣言していない`節`になり、必須の`節`の欠落も出ていた
  - decided_by: 利用者（推奨を採用）

- A3 2つ目以降の`題名`は、それまでの`節`と`項目`を終える。その後の行は、次の`節`までは`前置部`の行として読む
  - why: 要素の範囲（[REQ-schema-062](../../ir/schema/extraction.md#REQ-schema-062)）は既に`題名`を区切りにしていて、`項目`の最後の行は`題名`の手前だったのに、木を組むときだけ`題名`の後の行を前の`項目`に入れていた。区切り方を1つに揃える
  - rejected: 後の行を前の`項目`に入れる今の組み方を書き、要素の範囲の方を変える。題名の後の行が前の項目の本文として出る
  - decided_by: 利用者（推奨を採用）

- A4 "kotowari-mds" で同じオプションを2回渡したときは、引数の誤りの`停止`にする。今の振る舞いを IR に書く
  - why: どちらの値を採るかを決めるより、書き間違いに気づける。kotowari の CLI も同じオプションの2回目を引数の誤りにしている
  - decided_by: 利用者（推奨を採用）
