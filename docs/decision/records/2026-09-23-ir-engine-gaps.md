# 壁打ちの記録: 読み取りの置き換えで変わった振る舞いを1件ずつ決める

## Context

IR の読み取りをエンジンに置き換えた（[置き換えの判断](./2026-09-22-ir-engine.md)）。置き換えの証拠は「このリポジトリの IR に対する出力の差分が0」に絞っていた（[A85](./2026-09-22-ir-engine.md#A85)）。差分は0だったが、置き換えのあとのレビューで、このリポジトリの IR には現れない形の入力で振る舞いが変わっていることが分かった。検査が緩くなった場面（黙って通る）と、1つの原因から指摘が連鎖する場面がある。

[A5](./2026-09-22-ir-engine.md#A5) は「利用者から見える振る舞いを変えない。変わるものが見つかったら1件ずつ決める」と定めている。この記録はその1件ずつを決める。あわせて、仕様の中の食い違い2件と、置き換えの範囲の外で見つかった3件を扱う。

Position: 承認済み（2026-09-23）。A1〜A42 に続き、実装のレビューのあとで A43〜A45 を足した（CommonMark / GFM に寄せる利用者の指示）。

## 実測（置き換えの前 bbc2211 と後 af8bb62 の kotowari check）

同じ入力を、置き換えの前と後のバイナリに食わせた。入力は作業用の一時ディレクトリに作り、リポジトリには残していない。

| 場面 | 前 | 後 |
|---|---|---|
| `- 確かめ方: 見る` の次の行に空行なしで`文` | 指摘なし | missing_statement |
| `- 検証: review` の次の行に空行なしで`文` | 指摘なし | missing_statement、verification_invalid（値が "review\n文である。"）、requirement_without_test |
| `フィールド行`のあと空行を挟み、字下げした閉じないバッククォートの行 | unclosed_backtick | **指摘なし** |
| `用語集`の正しい表のあとに、ヘッダの違う2つ目の表 | 指摘なし（1つ目の表の`用語`を読む） | glossary_invalid、invalid_glossary_row、その用語を使う文書に unknown_term |
| `## 問題の記録` の節の無い `FLAGS.md` の `### FLAG-001` | 指摘なし（`項目`として読む） | unknown_heading、unknown_field 3件、unknown_line |
| `要求`の下の引用・HTML の行にある閉じないバッククォート | unclosed_backtick 2件 | **指摘なし** |
| `用語集`の表の4列の行 | 指摘なし（先頭3列で`用語`にする） | invalid_glossary_row、その用語を使う文書に unknown_term |
| 題名が2つある文書 | multiple_titles、detail は2つ目の題名 | multiple_titles、detail は1つ目の題名 |

## Agreements

- A1 `フィールド行`の直後に空行なしで続く行を`文`として読む（置き換えの前と同じ）
  - why: `文`の定義（見出しの下の、一覧でも表でもない空でない行）は空行を条件にしていない。今は`フィールド行`の値に吸われ、的外れな missing_statement と verification_invalid が出る
  - decided_by: 利用者（推奨を採用）

- A2 `フィールド行`のあと空行を挟んで字下げした行を`文`として読む（置き換えの前と同じ）
  - why: 今は`継続段落`になって`文`の検査を受けず、閉じないバッククォートが黙って通る。IR の`フィールド行`で複数行の値を使う場面は無い
  - decided_by: 利用者（推奨を採用）

- A3 `用語集`の1つ目の表の`用語`を読み、2つ目以降の表は`用語`にも`指摘`にもしない（置き換えの前と同じ）
  - why: [REQ-core-117](../../ir/core/terms-form.md#REQ-core-117) は2つ目の表を`用語`にしないと述べるだけで、`用語集`を無効にするとは述べていない。今は`用語集`が丸ごと無効になり、その`用語`を使う全文書に unknown_term が連鎖する
  - decided_by: 利用者（推奨を採用）
  - superseded_by: [A25](#A25)

- A4 `## 問題の記録` の節があっても無くても、`FLAGS.md` の `### FLAG-nnn` を`項目`として読む（置き換えの前と同じ）
  - why: [TBL-core-011](../../ir/core/ir-items.md#TBL-core-011) と[判断の記録](./ir-form.md)は置き場を `FLAGS.md` としか定めておらず、節を求めていない
  - decided_by: 利用者（推奨を採用）

- A5 `要求`などの見出しの下の、引用・水平線・HTML・画像だけの行を`文`として読む（置き換えの前と同じ）
  - why: 今は`文`にも`指摘`にもならず黙って消える。[REQ-core-120](../../ir/core/cli-environment.md#REQ-core-120) は`除外`に列挙していない入力を黙って読み飛ばすことを禁じている
  - decided_by: 利用者（推奨を採用）

- A6 `用語集`の表の4列以上の行は、先頭の3列で`用語`にする（置き換えの前と同じ）
  - why: [REQ-core-122](../../ir/core/terms-form.md#REQ-core-122) が崩れた行とするのは3列未満の行と`用語`のセルが空の行だけ。今は崩れた行になり unknown_term が連鎖する
  - decided_by: 利用者（推奨を採用）

- A7 multiple_titles は2つ目以降の題名ごとに1件出し、detail はその題名にする（置き換えの前と同じ）。[TBL-core-030](../../ir/core/finding-map.md#TBL-core-030) の行を直す
  - why: [TBL-core-008](../../ir/core/findings.md#TBL-core-008) は「2つ目の題名」と定め、TBL-core-030 は「`抽出`の`題名`」（1つ目）と定めていて食い違う。指摘を読む人が知りたいのは消すべき方の題名
  - decided_by: 利用者（推奨を採用）

- A8 [REQ-schema-008](../../ir/schema/cli.md#REQ-schema-008) を直し、`規則種別`を undeclared_line に加えて`出現回数`の下限と上限の`指摘`にも付けると述べる
  - why: [REQ-schema-057](../../ir/schema/document-structure.md#REQ-schema-057) は後の決定（[A86](./2026-09-22-ir-engine.md#A86)）で、kotowari の写し分けに要る。REQ-schema-008 の「にだけ」が古い
  - decided_by: 利用者（推奨を採用）

- A9 `query` が本文の範囲を生の行の `### ` と `## ` で決める経路も、[REQ-core-169](../../ir/core/form-contract.md#REQ-core-169) の禁止の対象にする。本文の範囲はエンジンの`抽出`の行番号から決め、kotowari は行を切り出すだけにする
  - why: 禁止の範囲を `ir.rs` に限ると、同じ読み取りが別のモジュールに残っても検査を素通りする
  - decided_by: 利用者（推奨を採用）

- A10 PROJECT.md の `mds check docs/ir/schema` の段落を、`docs/ir/schema/` も `kotowari check` だけで検査するという今の事実に書き換える。IR の要求にはしない
  - why: frontmatter を外したので `mds check` は $schema の無い文書で停止する。使えなくなるのは計画のステップ7で想定済み。段落が古いだけ
  - decided_by: 利用者（推奨を採用）

- A11 エンジンは、要素オブジェクトの外（節の直下など）の`配置パス`の衝突も検査し、スキーマの誤りとして停止する
  - why: 今は黙って上書きされ、値が消える
  - decided_by: 利用者（推奨を採用）

- A12 エンジンの既定の振る舞いを変えるのは、不具合と見なせる2つ（余ったセルの扱いを GFM に合わせる A16、multiple_titles を違反ごとに出す A17）だけにする。CommonMark どおりの読み方（段落、`継続段落`、引用などを`文`に数えない）は mds の既定として残し、IR が要る読み方はスキーマの宣言で選ぶ
  - why: mds は公開済みで、既定の読み方を変えると mds の利用者の結果が変わる。IR の`文`の定義は行単位で、CommonMark の段落とは別の読み方
  - decided_by: 利用者（推奨を採用）

- A13 スキーマで「行で読む」読み方を宣言できるようにする。宣言したときは、見出しの下の、一覧の行でも表の行でもない空でない行を1行ずつ`文`にし、一覧の行は1行で終わって続く行（空行なしの行も、空行のあとの字下げした行も）を吸わず、引用・水平線・HTML・画像の行も`文`にする。IR の3つのスキーマ（ir、ir-context、ir-flags）はこれを宣言する
  - why: A1・A2・A5 を、kotowari に生の行を読ませずに（[REQ-core-169](../../ir/core/form-contract.md#REQ-core-169)）実現する。既定を変えない（A12）
  - rejected: kotowari が生の行を読んで`文`を補う（「Markdown を読まない」に反する）。エンジンの既定を行単位に変える（A12 に反する）
  - decided_by: 利用者（推奨を採用）

- A14 `用語集`の2つ目以降の表（ヘッダが1つ目と同じものも違うものも）を`除外`の列挙に足す
  - why: A3 で`用語`にも`指摘`にもしないと決めた。[REQ-core-120](../../ir/core/cli-environment.md#REQ-core-120) は`除外`に列挙していない入力を黙って読み飛ばすことを禁じている
  - decided_by: 利用者（推奨を採用）
  - superseded_by: [A25](#A25)

- A15 スキーマで、節を挟まずに文書の直下に置く`項目`を宣言できるようにする。flags.yaml は節の下と文書の直下の両方を宣言し、同じ文書にどちらの形があってもよい
  - why: A4 を実現する。今のスキーマの言葉は`項目`を節の下にしか宣言できない。置き換えの前は節を見ていなかった
  - decided_by: 利用者（推奨を採用）

- A16 エンジンは、表の行のセルがヘッダより多いとき余ったセルを捨てて`指摘`にしない。足りないときは今のまま`指摘`にする
  - why: GFM の表の定めは余ったセルを捨てる。A6 を実現する。足りない行は [REQ-core-122](../../ir/core/terms-form.md#REQ-core-122) が崩れた行と定めている
  - decided_by: 利用者（推奨を採用）

- A17 エンジンは multiple_titles を2つ目以降の題名ごとに1件、その題名の行と`生の行`を付けて出す。kotowari は detail を題名の文字（"# " を除いたもの）にし、"line" は置き換えの前と同じく null にする
  - why: A7 を実現する。今のエンジンは題名がいくつあっても1件しか出さない
  - decided_by: 利用者（推奨を採用）

- A18 エンジンの`導かれる値`に「その要素の最後の行」を足す。ir.yaml の`項目`はこれを抽出し、query は`抽出`の行番号の範囲の行を切り出すだけにする
  - why: A9 を実現する。今の`抽出`には`項目`がどこで終わるかが無い
  - decided_by: 利用者（推奨を採用）

- A19 `配置パス`の衝突は、要素オブジェクトの中で使っている規則（[TBL-schema-009](../../ir/schema/extraction.md#TBL-schema-009)）をスキーマ全体に広げて判定する。同じパス同士と、一方が他方の手前の段にあたるもの（`a` と `a.b`）は衝突、途中まで同じで先が分かれるもの（`a.b` と `a.c`）は衝突ではない
  - why: A11 の衝突の範囲を、既にある規則と同じにする
  - decided_by: 利用者（推奨を採用）

- A20 最上位に `reading` の鍵を足し、値は `paragraph`（既定。CommonMark の読み方）と `line` の2つにする。IR の3つのスキーマは `reading: line` を書く
  - why: A13 の宣言の形。`open` と同じ最上位の設定として読め、読み方を足すときに鍵を増やさずに済む
  - decided_by: 利用者（推奨を採用）

- A21 `reading: line` のときは "#" で始まる行だけを見出しにする。`文`の次の "---" や "===" だけの行（CommonMark の下線の見出し）は、2行とも`文`になる
  - why: 置き換えの前の kotowari は "#" で始まる行だけを見出しと見ていた（A5 の原則）
  - decided_by: 利用者（推奨を採用）

- A22 `reading: line` のときは "```" で囲んだコードブロックだけをコードブロックにする。空行のあとの4つ以上の空白で字下げした行は`文`になる
  - why: 置き換えの前は`文`だった。A2 の字下げした行と同じ扱い
  - decided_by: 利用者（推奨を採用）

- A23 文書の直下の`項目`は `document.item` に、節の下の `item` と同じ形で宣言する。これを宣言したスキーマでは、`前置部`は最初の "## " か "### " の見出しの手前で終わる。宣言しないスキーマでは今のまま、最初の "## " より前の "### " は見出しの誤りになる
  - why: A15 の宣言の形。宣言しない ir と ir-context の振る舞いを変えない
  - decided_by: 利用者（推奨を採用）

- A24 「要素の最後の行」の`導かれる値`の名前は `end`。次の、同じ深さかそれより浅い見出しの手前の行（無ければ文書の最後の行）で、空行を含む。宣言できるのは`項目`と`節`だけ。query は切り出した範囲の頭と末尾の空行を落とす
  - why: A18 の形。[TBL-core-027](../../ir/core/query.md#TBL-core-027) の本文の範囲（次の "### " か "## " の見出しの前まで）と同じ範囲になる
  - decided_by: 利用者（推奨を採用）

- A25 `用語集`の表は、ヘッダの形（用語・意味・出典）が合う最初の表にする（置き換えの前と同じ）。それ以外の表は、ヘッダが合っても合わなくても`除外`に入れる。合う表が1つも無いときは今までどおり glossary_invalid にする
  - why: 置き換えの前は、ヘッダの合わない1つ目の表を飛ばして2つ目の合う表の`用語`を読んでいた（実測）。A3 の「1つ目の表」は実物の振る舞いより狭かった
  - decided_by: 利用者（推奨を採用）

- A26 見出しの下の、表にならない "|" で始まる行（区切りの行の無いもの）は`文`として読む。置き換えの後の今の振る舞いを残し、`reading: line` でも同じにする
  - why: A5 の原則（前に戻す）の例外。置き換えの前は`文`にも`指摘`にもせず黙って飛ばしており、[REQ-core-120](../../ir/core/cli-environment.md#REQ-core-120) に反し、`文`の定義（一覧でも表でもない空でない行）にも合っていなかった
  - decided_by: 利用者（推奨を採用）

- A27 エンジンの`表`の規則に、「ヘッダが合う最初の表だけをこの規則の表にし、それ以外の表は宣言の外の表にする」選び方を宣言できるようにする。既定は今のまま（ヘッダの合わない表は`指摘`）。ir-context はこの選び方を宣言し、kotowari は`用語集`で宣言の外になった表を`指摘`を出さずに捨てる（A14 の`除外`）。[TBL-core-030](../../ir/core/finding-map.md#TBL-core-030) にその行を足す
  - why: A25 を実現する。`抽出`には表のヘッダ行の文字が入らないので（[TBL-schema-008](../../ir/schema/extraction.md#TBL-schema-008)）、kotowari の側ではヘッダの合う表を見分けられない。既定を変えない（A12）
  - decided_by: 利用者（推奨を採用）

- A28 A27 の選び方は、`表`の規則に `select: first` と書く。`header` と一緒に宣言したときだけ有効で、`header` なしで書いたらスキーマの誤りにする。ir-context は `header: [用語, 意味, 出典]` と `select: first` を書く
  - why: A27 の宣言の形。ヘッダを持たない表の規則では「ヘッダが合う」が決まらない
  - decided_by: 利用者（推奨を採用）

- A29 `reading: line` でコードブロックにするのは、"```" か "~~~" のフェンスで囲んだブロック
  - why: CommonMark のフェンスは両方で、`コードブロック`の用語もフェンスで囲んだブロックと定めている。A22 の "```" はその一方だけを挙げていた
  - decided_by: 利用者（推奨を採用）

- A30 "reading" に "paragraph" でも "line" でもない値が書かれたら、スキーマの誤りとして停止する
  - why: 知らないキーの扱い（[REQ-schema-018](../../ir/schema/schema-language.md#REQ-schema-018)）と同じにする
  - decided_by: 利用者（推奨を採用）

- A31 flags.yaml は、文書の直下の`項目`を "flags" に、節の下の`項目`を "flags_in_section" に抽出する。kotowari は両方を読み、行の順に並べる
  - why: 同じ`配置パス`に置くと A19 の衝突で停止する
  - decided_by: 利用者（推奨を採用）

- A32 flags.yaml の`問題の記録`の`項目`も "end" を抽出する
  - why: query は`問題の記録`の`項目`も出し、A9 は生の行から本文の範囲を決めることを禁じる
  - decided_by: 利用者（推奨を採用）

- A33 [REQ-schema-032](../../ir/schema/block-rules.md#REQ-schema-032) に、"paragraph" のとき HTML の行も`文`に数えないと書き足す
  - why: エンジンの実装と実測の振る舞いを仕様に書くだけで、振る舞いは変わらない
  - decided_by: 利用者（推奨を採用）

- A34 `項目`の本文のコードブロックの中に "## " の行があるとき、query の本文の範囲はエンジンの "end" に従い、その行で切らない
  - why: コードブロックの中は見出しではない。今の query がその行で切るのは不具合寄りで、直る方向の変化として受け入れる
  - decided_by: 利用者（推奨を採用）

- A35 `reading: line` のとき、字下げした一覧の行も一覧の行のままにする
  - why: 置き換えの前も後も unknown_field で同じ（実測）
  - decided_by: 利用者（推奨を採用）

- A36 [TBL-core-030](../../ir/core/finding-map.md#TBL-core-030) の写し先に「出さない」を足す。使えるのは`除外`に列挙した入力の行だけで、[REQ-core-172](../../ir/core/finding-map.md#REQ-core-172) にそう書く
  - why: A27 を書くのに要る。`除外`に載っているものだけに限れば、黙って捨てる経路は増えない
  - decided_by: 利用者（推奨を採用）

- A37 docs/ir/schema/block-rules.md と extraction.md の too_many_lines、それらと docs/ir/core/ir-items.md の too_many_requirements の注意は残す
  - why: 分割の単位は責務で行数ではない。3つとも範囲の行が述べる責務から外れた要求は無い（書き手が読み直した）
  - decided_by: 利用者（推奨を採用）

- A38 `reading: line` のときに見出しにするのは、1つ以上の "#" のすぐ後に空白が続く行だけ。"#foo" と "#" だけの行は`文`になる
  - why: 置き換えの前の kotowari は "# "、"## "、"### "、"#### " のように "#" の直後に空白がある行だけを見出しにしていた（bbc2211 の ir.rs）。A21 の「"#" で始まる行」はこの条件を落としていた
  - decided_by: 利用者（推奨を採用）
  - superseded_by: [A43](#A43)

- A39 `用語集`の表は、題名の後、最初の "## " の見出しより前にある、ヘッダの合う最初の表とする
  - why: ir-context のスキーマは節を宣言しないので、"## " の見出しは`指摘`になりその下の表は宣言の外になる。エンジンの "select: first" は規則を置いた`前置部`の中でしか選ばない。kotowari 側の「文書で最初に現れる」とそろえる
  - decided_by: 利用者（推奨を採用）

- A40 multiple_titles の detail は、題名の行から "# " を除き、前後の空白を除いた文字にする
  - why: 置き換えの前と同じ（bbc2211 の ir.rs は line[2..].trim()）
  - decided_by: 利用者（推奨を採用）

- A41 文書の直下の`項目`を宣言しないスキーマでは、最初の "## " より前の "### " の見出しと、その内側の行（`フィールド行`も`文`も）を`指摘`にする
