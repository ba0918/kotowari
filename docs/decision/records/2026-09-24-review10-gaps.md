# 壁打ちの記録: 10回目の外部レビューで見つかったテストの見つけ方の仕様の穴

## Context

10回目の外部のレビュー（GPT、2026-09-24。範囲はテストの見つけ方を ast-grep に寄せた直後のコード: `test_queries.rs`、`comment_block.rs`、`tests_discovery.rs`、同梱のルール）で、不具合2つと、IR が決めていない振る舞い4つが見つかった。不具合は "it(...)" が別の呼び出しの呼ぶ側にあると数えないこと（[TBL-core-032](../../ir/core/test-queries.md#TBL-core-032) のとおりに直す）と、全角空白や NBSP の後のコメントが`直前のコメントの塊`に入らないことである。後者と4つの穴は、利用者が「ほぼ答えが決まっているものは推奨で決めてよい」とした範囲で決める。

Position: A1〜A4 を決めた。

## Agreements

- A1 コメントだけの行を決める「前後の空白」は Unicode の空白（全角空白と NBSP を含む）とする
  - why: [TBL-core-035](../../ir/core/test-markers.md#TBL-core-035) は空白の範囲を書いておらず、実装は ASCII の空白だけを除いていた。名前が null の`テスト`の detail の「前後の空白を除く」（[A42（multi-language-tests）](./2026-09-24-multi-language-tests.md#A42)）は Unicode の空白を除いており、同じ語で範囲が違っていた
  - decided_by: 利用者（推奨を採用）
- A2 同じ節に複数の`問い合わせ`が当たったとき、`テスト`の名前は、"$NAME" を捕まえた`問い合わせ`のうち、同梱の`問い合わせ`、"tests.rules" の並びの順で最初のものの名前とする。どれも捕まえなければ null
  - why: [REQ-core-181](../../ir/core/test-discovery.md#REQ-core-181) は1つと数えることだけを決め、名前を決めていなかった。実装は最初に当たった`問い合わせ`の名前を採り、"$NAME" を捕まえない`問い合わせ`が先にあると名前が null になって、"tests.rules" の並びで detail が変わっていた
  - decided_by: 利用者（推奨を採用）
- A3 Python のクラスの中のメソッドは、そのクラスが関数の中にあっても数える。今の振る舞いを IR に書く
  - why: [TBL-core-033](../../ir/core/test-queries.md#TBL-core-033) は「クラスの中のメソッド」を数え「関数の中に入れ子になった関数」を数えないとしていて、両方に当たる配置を決めていなかった。メソッドはクラスの中にある限りクラスの規則に従うのが素直
  - decided_by: 利用者（推奨を採用）
- A4 "tests.rust.macros" のマクロの中で数える「最上位の関数」は、マクロの中身のうち、ほかの関数の本体の中にない関数とし、"mod" や "impl" の中の関数を含む。今の振る舞い（置き換える前のエンジンから同じ）を IR に書く
  - why: [TBL-core-017](../../ir/core/test-queries.md#TBL-core-017) の「最上位の関数」は "mod" や "impl" の中を含むかを決めていなかった。置き換える前のエンジンも関数でない節の中は辿っていた
  - decided_by: 利用者（推奨を採用）
