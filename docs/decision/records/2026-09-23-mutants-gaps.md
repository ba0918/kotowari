# 壁打ちの記録: 変異テストで見つかった欠陥の疑いと仕様の穴

## Context

kotowari-core を別の crate に分けてから変異テストがルートの tests/ を走らせていなかった不具合を直し、差分の変異を回し直したところ、74件が生き残った。テストの追加とコードの簡素化で56件を片付け、残りは仕様の判断が要る18件になった。内訳は、欠陥の疑い2つ（単独の CR の行の数え方、縦棒の無い GFM の表を行の読み方が表と読まない）と、IR に規則が無いために変異を区別するテストを書けない6項目である。

これらを片付けないまま変更を main に入れると、次の push の変異テストで止まる。どう直すかを決める。

Position: 第1ラウンドで欠陥の疑い2つの直し方と、IR の6項目を今回決めることを決めた（A1〜A3）。第2ラウンドで6項目の中身を決めた（A4〜A9）。IR を書いて今の振る舞いを実測したところで出た4つを第3ラウンドで決めた（A10〜A13）。木は尽きた。照合は3回目で裏付けの無い項目が0件になった。承認待ち（2026-09-23）。

## Agreements

- A1 kotowari は単独の CR（"\r"）も1つの行の終わりに数える。[TBL-core-010](../../ir/core/ir-document.md#TBL-core-010) にその行を足し、行の分け方を mds と揃える
  - why: kotowari は mds で IR を読むので、単独の CR を含む文書では2つの行番号がずれ、指摘の行や閉じないコードブロックの範囲がずれる（閉じないコードブロックより前の要求が落ちることを実測した）。mds は CommonMark に合わせて単独の CR を行の区切りに数える
  - decided_by: 利用者（推奨を採用）

- A2 行の読み方でも、縦棒で始まらない GFM の表を表と読むように実装を直す。IR は変えない
  - why: [TBL-schema-011](../../ir/schema/extraction.md#TBL-schema-011) は既に「GFM の表。縦棒で始まらなくてもよい」を両方の読み方に求めていて、行の読み方の実装だけが追いついていない
  - decided_by: 利用者（推奨を採用）

- A3 IR に規則が無い6項目（見出しと表のセルのインラインの記法、フィールド行の子の行を本文に含めるか、停止の説明の文言、URL のスキーマの大きさの上限、values の text の字下げ、キャッシュの置き場）を今回決める
  - why: 決めないまま変更を main に入れると、それらを区別するテストが無いため次の push の変異テストで止まる
  - rejected: 等価の一覧に仕様が未決として一時的に載せる。一覧は観測できない変異の置き場で、観測できるが仕様が無いものを置くと一覧の意味が崩れる
  - decided_by: 利用者（推奨を採用）

- A4 mds は見出しの名前と表のセルの値を、インラインの記法の記号を外した文字で読む。強調、太字、リンク、参照リンクは中の文字をつなげ、インラインコードは中身を残す
  - why: 見出しの名前やセルの値として使うのは記号でなく文字の方。今の振る舞いの追認
  - decided_by: 利用者（推奨を採用）

- A5 項目の本文にフィールドの行を含めるとき、宣言したフィールド行はその行だけを本文に入れ、子の行は入れない。宣言していない行は子の行まで入れる
  - why: 宣言したフィールドの子の行はそのフィールドの値として別に取り出されるので、本文にも入れると同じ中身が二重になる。今の振る舞いの追認
  - decided_by: 利用者（推奨を採用）
  - superseded_by: [A10（mutants-gaps）](#A10)（継続段落は本文に入れる）

- A6 停止の説明の文言は契約にしない。スキーマか frontmatter の値の型や語が違って停止するとき、説明には問題のあった欄の名前と、期待した型か受け付ける語の一覧を含める
  - why: 文言を契約にすると言い回しの手直しでテストが壊れる（TODO の ID 38 / 60 と同じ問題）。中身だけを決めれば、テストはその中身を確かめられる
  - rejected: 今の文言をそのまま契約にする
  - decided_by: 利用者（推奨を採用）

- A7 URL のスキーマの取得は、応答が 4MiB を超えるか、取得全体が10秒を超えたら停止する
  - why: 壊れたサーバにメモリを食い潰されたり、応答しないサーバで無期限に止まったりしないための上限で、大きなスキーマが使えないことは利用者から見える振る舞い
  - decided_by: 利用者（推奨を採用。タイムアウトも同じ仲間として含める）

- A8 values の text 出力は、入れ子が1段深くなるごとに空白2つで字下げし、配列の要素には1から始まる番号と "." を付ける
  - why: 人間向けの出力でも、形が決まっていないとテストが書けない。今の振る舞いの追認
  - decided_by: 利用者（推奨を採用）

- A9 URL のスキーマのキャッシュは、基準のディレクトリ（今のディレクトリから上に向かって最初に見つかった ".mds/" のあるディレクトリ。無ければ今のディレクトリ）の下に置く
  - why: 基準のディレクトリの探し方は既に決まっていて、キャッシュもそれに揃える。今の振る舞いの追認
  - decided_by: 利用者（推奨を採用）

- A10 項目の本文にフィールドの行を含めるとき、宣言したフィールド行はその行と継続段落を本文に入れ、子の箇条書きは入れない。宣言していない行は子の行まで入れる
  - why: A5 の「子の行」は用語集では継続段落も含むが、実測では継続段落は本文に残り、子の箇条書きだけが落ちる。継続段落はフィールドの値の一部として読まれるもので、今の振る舞いの追認として A5 を改める
  - decided_by: 利用者（推奨を採用）

- A11 URL のスキーマの応答が 4MiB を超えたときと取得全体が10秒を超えたときの停止は、停止の理由「スキーマが見つからない」の「URL の取得に失敗した」に数える
  - why: 今の実装も同じ理由（schema_not_found）で止まる。追認
  - decided_by: 利用者（推奨を採用）

- A12 mds の用語集の「基準のディレクトリ」の意味に、".mds/" のあるディレクトリが見つからなければカレントディレクトリとすることを足す
  - why: A9 のキャッシュの置き場を含め、基準のディレクトリを使う要求すべてに効くのは定義の側。今の実装も見つからなければカレントディレクトリを使う
  - decided_by: 利用者（推奨を採用）

- A13 kotowari スキルの references の行の数え方の記述は、A1 の実装と同じ変更で単独の CR を含む形に直す。変異の結果のファイルの行の数え方は既に TBL-core-010 を指すので変えない
  - why: references は IR の外で、A1 の振る舞いが入るまで直すと実物と食い違う
  - decided_by: 利用者（推奨を採用）

- A14 docs/ir/schema/cli.md が行数と要求の数の上限を越える注意は残し、文書を分けない
  - why: 新しく足した2つの要求（停止の説明の中身と values の text の字下げ）はどちらも cli.md の範囲（出力の形と、検査を行えないときの振る舞い）に入り、責務は混ざっていない。行数や件数を理由に分けない
  - decided_by: 主セッション（ir-form.md の「上限と分ける単位」の指針どおり）
