# 壁打ちの記録: 2回目の外部レビューで見つかった mds の仕様の穴

## Context

2回目の外部のレビュー（GPT、2026-09-23）で、仕様が決めていない mds の振る舞いが2つ見つかった。1つは、`題名`が2つ以上ある文書で、1つ目の`題名`の正規表現の照合をしないこと。[REQ-schema-022](../../ir/schema/document-structure.md#REQ-schema-022) は複数の`題名`の`指摘`の出し方だけを決めている。もう1つは、"ast --schema" がスキーマの "name" を出力の "type" の鍵に置いたあと、同じ鍵に`抽出`の値を置くと "name" が消えること。どちらも利用者が「ほぼ答えが決まっているものは推奨で決めてよい」とした範囲で決める。

Position: A1 と A2 を決めた。承認済み（2026-09-24）。

## Agreements

- A1 `題名`が2つ以上ある文書でも、`スキーマ`が`題名`に正規表現を宣言していれば、1つ目の`題名`を照合し、合わなければ正規表現に合わない`指摘`も出す
  - why: 複数の`題名`と正規表現に合わない`題名`は別の問題で、片方を出したらもう片方を隠す理由が無い。隠すと、2つ目の`題名`を消したあとで初めて1つ目の誤りに気づくことになる
  - rejected: 今のまま、複数の`題名`があるときは照合しない
  - decided_by: 利用者（推奨を採用）

- A2 "name" を宣言した`スキーマ`で、文書の値の根に置く`配置パス`が "type" か "type." で始まるものは、`配置パス`の衝突と同じく`スキーマ`が形に合わない`停止`にする
  - why: "ast --schema" は根の "type" の鍵に "name" を置くので、同じ鍵に`抽出`の値を置くと "name" が黙って消える。今の衝突の検査（[TBL-schema-009](../../ir/schema/cli.md#TBL-schema-009)）と同じ形で止めれば、出力の形を変えずに済む
  - rejected: 出力の形を変え、"name" を値と別の鍵（例: 抽出の値を1段下に置く）に分ける。"ast --schema" の出力を読む側が壊れる
  - rejected: "name" を宣言しない`スキーマ`でも "type" を禁じる。"values" には "type" が出ないので、衝突しない`スキーマ`まで止めることになる
  - decided_by: 利用者（推奨を採用）
