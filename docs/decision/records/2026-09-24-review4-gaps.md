# 壁打ちの記録: 4回目の外部レビューで見つかった mds の仕様の穴

## Context

4回目の外部のレビュー（GPT、2026-09-24。範囲は mds の `schema.rs`、`validate.rs`、`extract.rs`）で、IR とエンジンの食い違いと、IR が決めていない振る舞いが5つ見つかった。題名の規則を持たないスキーマの題名（[REQ-schema-022](../../ir/schema/document-structure.md#REQ-schema-022)）、出現回数を書かない項目の欠落（[REQ-schema-056](../../ir/schema/document-structure.md#REQ-schema-056)）、同じ名前の節やフィールド行の2度の宣言、表のヘッダの同じ列の名前、空の名前を含む配置パス（[REQ-schema-036](../../ir/schema/extraction.md#REQ-schema-036)）である。利用者が「ほぼ答えが決まっているものは推奨で決めてよい」とした範囲のものを決め、表のヘッダの列の名前は既存のテストが別の振る舞いを固定していたので未決に残す。

Position: A1〜A4 を決め、U1 を未決に残した（2026-09-24）。

## Agreements

- A1 題名の規則（REQ-schema-022）は、`スキーマ`が`題名`を宣言したときだけ適用する。宣言しないときは`題名`を求めず、`題名`があれば閉じた世界の宣言していない見出しにする。今の振る舞いを IR に書く
  - why: IR は「常に題名をちょうど1つ求める」と書きながら、[REQ-schema-001](../../ir/schema/closed-world.md#REQ-schema-001) の閉じた世界では題名を宣言しないスキーマの題名は宣言していない見出しになり、2つの要求が両立しない。エンジンは宣言したときだけ求めていて、題名を持たない形式の文書も書ける
  - rejected: 題名を宣言しないスキーマでも題名を求める。題名を持たない形式を表せなくなる
  - decided_by: 利用者（推奨を採用）

- A2 `項目`が足りないときは、`出現回数`を書いたかどうかを問わず、下限を割った`指摘`にする。書かなければ既定のちょうど1個（[TBL-schema-005](../../ir/schema/schema-language.md#TBL-schema-005)）の下限を割ったものとする。今の振る舞いを IR に書く
  - why: 項目には欠落を表す`指摘`の種類が無く、既定の出現回数もちょうど1個という出現回数なので、下限の`指摘`で表すのが一貫する。IR の「出現回数を宣言した項目」が、書かない場合を除くように読めた
  - decided_by: 利用者（推奨を採用）

- A3 同じ置き場に同じ名前の`節`、または同じ名前の`フィールド行`を2度宣言した`スキーマ`は、`スキーマ`が形に合わない`停止`にする
  - why: 今は検査が1つ目の宣言だけを使い、抽出は両方の宣言を使うので、2つ目の宣言の正規表現は黙って効かず、抽出には検査を通っていない値が入る。どちらの宣言が効くかを決めるより、書けなくする方が誤りに気づける。配置パスの衝突（[TBL-schema-009](../../ir/schema/cli.md#TBL-schema-009)）と同じ扱いにする
  - rejected: 2つ目以降の宣言を無視する。書いた規則が黙って効かない
  - decided_by: 利用者（推奨を採用）

- A4 `配置パス`のドットで区切った名前は、どれも空であってはならない。空の名前を含む`配置パス`（空文字列、"a..b"、".a"、"a."）は`スキーマ`が形に合わない`停止`にする
  - why: 今は空文字列の JSON の鍵を作り、`配置パス`の「ドット区切りの名前」（REQ-schema-036）として意味を持たない。書き間違いにすぐ気づける
  - decided_by: 利用者（推奨を採用）

## Undecided

- U1 表のヘッダに同じ列の名前を2度書いたときの扱い。今は検査を通り、抽出では後の列の値が前の列を上書きする。この上書きは実装のときのテスト（`table_extract_keys_by_header_and_later_column_overrides`）が固定している。停止にするか、上書きを仕様として書くか
  - decides: 同じ名前の列を持つ表の形式をスキーマで表せるかと、抽出で値が黙って消えるか。決めるのは利用者
