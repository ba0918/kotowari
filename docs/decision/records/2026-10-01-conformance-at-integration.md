# 変更照合を取り込み前だけで要求する

## Context

[変更照合の方針 A8](./2026-10-01-change-conformance.md#A8) は、pre-commit で毎コミットの実装側の記録を、cycle の最終検査と CI でブランチ全体の独立 review の記録を要求していた。
毎コミットの要求は、版上げや変更履歴のように判断を含まない変更にも記録を求め、リリースの準備と確定を分ける仕組み、途中用の記録の置き換え、整形後の index の再ステージといった派生作業を連鎖させた。
実装中に生まれた判断を拾う働きは、最終の独立 review が根拠と意味を確認すること（[A6](./2026-10-01-change-conformance.md#A6)、[A10](./2026-10-01-change-conformance.md#A10)）が担い、途中の機械検査はその保証を増やさない。
照合の要求を取り込み前に絞り、派生した仕組みを取り下げる。

Position: 利用者が pre-commit をやめる案を採用した。A2 は既存機能を残す具体化として LLM が決めた。

## Agreements

- A1 変更照合は pre-commit で要求しない。cycle の最終検査と CI だけが、指定された比較元から対象ブランチ全体の変更について、実装側と別の review による照合までを要求する。途中のコミットには照合記録も変更照合の合格も要求しない。
  - why: 毎コミットの要求は判断を含まない変更にも記録を求めて派生作業を連鎖させた一方、判断の取りこぼしを拾うのは最終の独立 review であり、途中の機械検査はその保証を増やさない
  - decided_by: 利用者（推奨を採用）
- A2 "--staged" は HEAD とステージ済みの内容を比較する任意の自己検査として残す。導入例とスキルはこれをフックや必須の手順に置かない。
  - why: 実装済みの機能で、実装役がコミット前に自分の記録を確かめる用途に使える。取り除くと入力の契約とテストの変更が広がる
  - decided_by: LLM（既存機能を残す具体化）
- A3 導入例の照合記録は Git で管理する ".kotowari/changes/" の implementation.yaml と review.yaml の2つとし、途中用の commit.yaml を置かない。最終確認ではブランチの比較元と対象を固定し、実装側と review 側が別々に作り直す。各件は現在の変更意図を表し、日付・SHA 別のファイルや過去の件を蓄積しない。
  - why: 途中のコミットに記録を要求しないので、途中用の記録は使われない
  - decided_by: 利用者（A1 の採用に伴う）
- A4 リリースの版上げは変更照合のために特別に扱わない。scripts/release.sh は[リリースの流れ](./2026-09-26-release-flow.md#A4)のとおり、書き換え・検査・コミット・タグを一度に行う。
  - why: pre-commit で照合を要求しないので、版上げのコミットに記録を用意する時点が要らない
  - decided_by: 利用者（リリースの準備と確定の仕組みの削除を指示）

## Rejected

- R1 照合記録の追加・更新だけを許す確定の段を release.sh に足す
  - why: pre-commit の照合を残す前提の案であり、A1 で前提が無くなった
