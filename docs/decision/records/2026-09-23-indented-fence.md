# 壁打ちの記録: 行で読むときの字下げしたフェンス

## Context

外部のレビュー（GPT、2026-09-23）で、`reading: line` のとき、4つ以上の空白で字下げした "```" の行もフェンスの開始として読むと指摘された。[TBL-schema-011](../../ir/schema/block-rules.md#TBL-schema-011) には「空行の後に4つ以上の空白で字下げした行は`文`」と「"```" か "~~~" のフェンスで囲んだブロックは`コードブロック`」の2行があり、字下げしたフェンスの開始の行がどちらに当たるかが書かれていない。今のエンジンは字下げを問わずフェンスとして読む。どちらにするかを決める。

Position: A1 を決めた。承認済み（2026-09-23）。

## Agreements

- A1 `reading: line` のとき、"```" か "~~~" のフェンスの開始の行は、字下げの深さを問わずフェンスの開始として読み、そのブロックを`コードブロック`にする。今のエンジンの振る舞いを仕様に書く。`reading: paragraph` の読み方は変えない
  - why: 行で読むときは字下げのコードブロックを作らない（[A22（ir-engine-gaps）](./2026-09-23-ir-engine-gaps.md#A22)）ので、字下げしたフェンスの行が意味するものはフェンスしか無い。一覧の行も続く行を吸わない（[A13（ir-engine-gaps）](./2026-09-23-ir-engine-gaps.md#A13)）ので、一覧の下に字下げして書いたフェンスは、字下げを問わないことでしかコードブロックにならない。CommonMark に合わせて字下げを3つまでにすると、字下げしたフェンスの開始と閉じの行とその中身が、1行ずつ`文`になる
  - rejected: CommonMark と同じく、字下げが3つまでの行だけをフェンスの開始にする。上の理由で、一覧の下のフェンスが壊れ、誤りに気づきにくい
  - decided_by: 利用者（推奨を採用）
