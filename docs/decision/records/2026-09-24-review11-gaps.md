# 壁打ちの記録: 11回目の外部レビューで見つかったテストの見つけ方の仕様の穴

## Context

11回目の外部のレビュー（GPT、2026-09-24。範囲は10回目と同じテストの見つけ方のコードとそのテスト）で、不具合2つ（"tests.rust.macros" の "()" と "[]" のマクロの中身を読まない、"it" の後の名前を ASCII の文字だけで判定し間のコメントを許さない）、弱いテスト1つ、IR が決めていない振る舞い1つが見つかった。不具合は [TBL-core-017](../../ir/core/test-queries.md#TBL-core-017) と [TBL-core-032](../../ir/core/test-queries.md#TBL-core-032) のとおりに直す。IR が決めていない1つは、利用者が「ほぼ答えが決まっているものは推奨で決めてよい」とした範囲で決める。

Position: A1 を決めた。

## Agreements

- A1 TS/JS のタグ付きテンプレート（"test.each`表`" のように、引数の括弧でなくテンプレートの文字列を続ける形）は、それだけでは`テスト`と数えない。"test.each`表`(名前, 関数)" のように結果を呼ぶ形は、外側の呼び出しを数える
  - why: TBL-core-032 は「呼び出し」の形だけを数え、タグ付きテンプレートを決めていなかった。実装はそれだけの "test.each`foo`" をテストと数え、テンプレートの中身を名前にしていた。jest と vitest ではタグ付きテンプレートは表を渡す形で、テストを定義するのは結果の呼び出しの側
  - decided_by: 利用者（推奨を採用）
