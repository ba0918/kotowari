# 壁打ちの進捗: IR の置き場を再帰で読む

目的: kakoi-net の壁打ち1回で IR が69文書・4004行・要求199件・シナリオ335件になり、置き場の直下に並べる形では管理できないと利用者が判断した。kotowari 本体を、IR の置き場をディレクトリの深さに制限なく再帰で読む形に変え、用語集・参照・ID の規則をそれに合わせる。判断の記録 A32 は「直下のファイル数の肥大化を考慮し、設計で塞がない」と残していた。

対象: kotowari 本体の IR（`docs/ir/`）。スキル `kotowari` の references は本体の変更の後に追従して更新する（スキルの記録 A1）。

Position: 第1〜第4ラウンド（A1〜A20）は承認・コミット済み。cycle の実装の席からの差し戻しで A21 を足した（TBL-014 の条件2）

## Agreements
- A1 IR の置き場はディレクトリを再帰で読み、深さに制限を付けない。分割の深さは要件による（ネットワークのように概念が多いものは深く、単純なものは浅く）（利用者、2026-09-16）
- A2 判断の記録の置き場は `docs/decision/records`。設定の `decisions.records` をそこに向け、`experiments/003-cli/brainstorm/records.md` と `ir-form.md` を `git mv` で移し、IR の出典のパス（22文書・564か所）を機械的に書き換える。書き換えの正しさは `kotowari check` が0に戻ることで確かめる（推奨を採用）
- A3 文書から見える用語は、その文書のディレクトリから置き場の根までの各 `CONTEXT.md` の用語の合計（連鎖）。「用語集が無いとき」（REQ-065）は「連鎖に `CONTEXT.md` が1つも無いとき」に読み替える。隣の枝の `CONTEXT.md` の用語は見えない（unknown_term）（推奨を採用）
- A4 連鎖の中で同じ用語が2回定義されたら、既存の duplicate_term を深い方のファイルの行に出す。用語は見えるままにし、新しい種類は作らない（推奨を採用）
- A5 文書名の参照は2形だけ。素の `xxx.md` は同じディレクトリだけを見て上へ辿らない。`/` を含む `network/dns/xxx.md` は置き場からの相対。`..` を含む並びは解決せず missing_document。隣の枝への参照が長くなるのは深く切った代償として受け入れる（推奨を採用）
- A6 ID は接頭辞に「3桁以上」の数字。`REQ-001` はそのまま、`REQ-1000` は通り、`REQ-1` は通らない。今は用語集の ID の行とコード（`is_valid_id`）にしかない「ちょうど3桁」を要求として明文化する。印の検査も同じ関数なので一緒に動く（推奨を採用）
- A7 `README.md` は置かない。各ディレクトリの `CONTEXT.md` の題名の後の範囲の行にそのディレクトリの説明を書く。本体は README を特別扱いせず（置けば話題ごとの文書として読まれ missing_scope になる）、置かない約束はスキルの write の reference に書く（推奨を採用）
- A8 `FLAGS.md` はどの階層にも置ける。`CONTEXT.md` と同じく名前で役割が決まり、階層で例外を作らない。FLAG の ID は全体で一意（推奨を採用）
- A9 粒度の目安（スキルの write の reference に書く。本体は見ない A17）: ディレクトリを切るのは「そのまとまり専用の用語が出たとき」。要求1〜2件の文書は、同じ範囲の行で説明できる隣の文書と1つにする（推奨を採用）

- A10 ADR も `docs/decision/adr/` に `git mv` で移し、設定の `decisions.adr` をそこに向ける。実験の箱（`experiments/003-cli/`）の散文の中のパスは歴史として書き換えない（推奨を採用）
- A11 ID の数字は3桁以上で、4桁以上のときは先頭を 0 にしない。`REQ-001` と `REQ-1000` は正しい形、`REQ-0001` は形に合わない（見出しなら unknown_heading、"@id" なら invalid_id）（推奨を採用）
- A12 本体はディレクトリ名を制約せず読む。参照で指せる名前（英小文字・数字・ハイフン）にするのは書き手の責任で、スキルの write の reference に書く（推奨を採用）
- A13 A1〜A8 から導いたこと（第2ラウンドで提示し異論なし）: 除外（隠しディレクトリ、ディレクトリのシンボリックリンク、".md" 以外、".kotowari" という名前のファイル）はどの深さでも同じに働き、空のディレクトリは指摘なし。出力の path は基準のディレクトリからの相対のままで、置き場からの相対パスを "/" でつなぐ（REQ-110 の文言を改める）。指摘の並べ方は path のバイト順のまま。files と lines は全階層の文書を数え、duplicate_id は階層をまたいで検出する

- A14 TBL-014 の条件3に「".md" の直後が "#" でもない」を足す。出典の "パス#印" を参照と取らないため。素の形にも同じく効く（推奨を採用）
- A15 置き場の外のリポジトリのパスを引用符なしで書くと、"/" を含む形の参照として missing_document になる。具体的な値は二重引用符で書く規則（REQ-104）があるので受け入れ、EX-014 をその例に書き換える（推奨を採用）

- A16 IR の置き場の下のディレクトリが読めないときは、判断の記録と ADR の置き場の下と同じく、読めないファイルを理由に停止する（A1 と REQ-120「列挙に無い読み飛ばしの禁止」からの導出。敵対的レビューの指摘で足した）

- A17 文書名の参照の並びの要素として "." と ".." も認め、どちらかを含む参照は解決せず missing_document にする。".md" の直後に禁じる文字に "/" を足す（"a.md/b.md" は参照にならない）（推奨を採用。敵対的レビューで A5 の ".." が到達不能と分かり改めた）
- A18 "/" を含む参照の先が、kotowari が読まない場所（ディレクトリのシンボリックリンクの下）にあるときは missing_document。参照の先の有無は「読んだ IR の文書の中に有るか」で見る（推奨を採用）
- A19 missing_title、missing_scope、glossary_invalid の detail はディレクトリを除いたファイル名のまま。区別は path が付ける（推奨を採用）
- A20 出典の先になっている形の契約 `docs/decision/records/ir-form.md` は、今回の決定に合わせて書き換える。先頭に 2026-09-16 の記録で改めた旨を書き、変えた節に決定の番号を添える（推奨を採用）

- A21 TBL-014 の条件2を列挙から否定に改める: 並びの直前が、英数字、"_"、"-"、"/"、"."、バッククォートのいずれでもない（行頭を含む）。理由: (1) "." を境界に数えると "a.md/b.md" の中の "md/b.md" が語の途中から参照として拾え、EX-031 と矛盾する（実装の席が発見）。語の中に出る文字を全部非境界にすれば途中から拾えない。(2) 句読点の列挙には日本語の文字が無く、「設定はnetwork-x.mdで定義する」のように助詞に直接つなげた参照が黙って素通りしていた（kakoi の IR で34か所）。(3) バッククォートを非境界に入れるのは、囲んだパスが用語の検査だけを受ける今の振る舞いを変えないため（推奨を採用、2026-09-16）
