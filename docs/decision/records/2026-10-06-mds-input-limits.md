# mds の入力の深さとスキーマの取得元

## Context

2026-09-22 に TODO.md の ID 64 と ID 65 として決めた2件は、判断の記録に無く TODO.md にだけ残っていた。TODO.md を棚卸しした 2026-10-06 に、決めた内容と理由をここに移した。決めた人の記録は TODO.md に無い。

- ID 64: 入れ子の深い文書で mds の処理時間が超線形に伸びる。実測（release、`mds ast`）で、入れ子の深さ 200 で 0.06 秒、400 で 0.42 秒、800 で 3.84 秒、2000（約 4MB）で 66 秒。支配的なコストは依存クレート `markdown` のパースにあり、mds 自身のコードではない。
- ID 65: `$schema` に `http://` の URL を書くと平文で取得する。経路上で差し替えられたスキーマは、正規表現・enum・必須の宣言を通じて検証の合否を左右する。キャッシュに期限が無いのは [REQ-schema-013](../../ir/schema/schema-resolution.md) の振る舞いで、欠陥ではない。

Position: 2件とも 2026-09-22 に決まっていた内容の転記で、新しく決めたことは無い。

## Agreements

- A1 mds は入力の大きさと入れ子の深さに上限を設けない。上限が要るという要求が実際に出てから決める。
  - why: mds の側で打てる手は上限だけで、上限は正当な文書を弾く可能性を仕様に持ち込む。人が手で書く文書でも LLM が書く文書でも、この深さは意図して用意しない限り現れない
  - decided_by: 2026-09-22 の判断（TODO.md の ID 64 から転記。決めた人の記録は無い）
- A2 mds は `$schema` の `http://` を禁止しない。取得元の信頼は利用者の責任として扱う。
  - why: `https://` だけを許すと、社内の平文配布や手元の検証用サーバを使えなくなる。どこから取るかは利用者が決めることである
  - decided_by: 2026-09-22 の判断（TODO.md の ID 65 から転記。決めた人の記録は無い）
