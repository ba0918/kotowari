# 判断の記録: リリース準備と変更照合の受け渡し

## Context

変更照合を要求する pre-commit は、リリーススクリプトが自動生成する版・lock・変更履歴の変更にも適用される。
従来の一括実行は開始時の clean-tree と固定ファイルの staging のため、LLM が判断と照合記録を追加する時点を持たない。
独立 review で発見した追加範囲として、同じ変更照合の計画にリリースの受け渡しを追加する。
リリース固有の操作は IR 外に置き、[既存のリリース判断](./2026-09-26-release-flow.md)と[操作仕様](../../release/change-conformance.md)から追えるようにする。

Position: A1 と A10 は利用者承認済み。A2〜A9 は LLM の根拠に基づく具体化で、独立 quality/conformance の2観点 review を経て今回採用済み。実リリースを行う承認ではない。

## Agreements

- A1 新しい変更照合のフックを維持し、リリースを「変更を準備する→LLM が照合と記録を行う→確定する」という受け渡しにする。独立 review が発見した追加範囲として、既存の変更照合の計画へ追加し、リリース固有の操作は IR 外の記録と操作仕様に置く。
  - why: 自動生成された版変更にも根拠と独立した照合が必要であり、フックの免除では今回の保証を失う。
  - decided_by: 利用者（release の受け渡しを今回追加する推奨を承認）
- A2 既存の「scripts/release.sh <製品> <版>」は準備だけを行う入口として維持し、明示的な「prepare <製品> <版>」も同じ準備として受ける。確定は「finalize <製品> <版>」を明示し、status と abort の操作も用意する。準備の成功をタグ作成の成功として表示しない。
  - why: 既存の製品・版の入力を維持しながら、LLM の記録前にコミットやタグ作成が進むことを防ぐ。自動確定する旧動作は A1 により変更される。
  - decided_by: LLM（既存2引数の入口と承認された受け渡しの具体化）
- A3 準備は main と clean-tree を要求し、製品ごとの正本・追随版・Cargo.lock・変更履歴の生成規則と公開済みタグの拒否を維持する。開始 HEAD と生成ファイルの変更前後の内容を固定し、準備だけでは staging、commit、tag、push を行わない。
  - why: 開始条件と版の整合を維持し、準備後に別の変更が混入したことを検出できるようにする。
  - decided_by: LLM（既存スクリプトの開始条件と生成規則を維持した具体化）
- A4 確定へ渡せる変更は、準備が生成したファイルの固定内容と、設定された照合記録の新規ファイルだけとする。記録はリポジトリへ残し、実装側と独立 review 側が開始 HEAD を base として照合する。根拠や IR の追加が必要で、この境界を超える場合は確定を止め、追加判断を通常の変更として先に完了してから準備し直す。
  - why: 版上げへの別作業の混入を防ぎ、記録の格納場所だけを検査免除の隠し場所にしない。
  - decided_by: LLM（共有作業ツリーと照合記録の受け渡しの具体化）
- A5 確定は開始 HEAD の不変と変更境界を確認し、実装段階の staged 検査と既存の pre-commit を通して候補コミットを作る。その完全 SHA と予定した内容の一致を確認して、同じ checkout で版検査、check の終了0、全テスト、開始 HEAD からの review 段階の changes の終了0を要求し、その候補へだけ注釈付きタグを作る。タグ直前にも origin の同名タグの不在を確認し、公開済みタグと到達不能な origin は拒否する。
  - why: フックの整形後の内容と最終検証対象を一致させ、独立 review のない版変更を確定しない。
  - decided_by: LLM（既存の版・check・test・pre-commit と最終照合を維持した具体化）
- A6 準備状態は ignored な作業ツリー内に保存し、根拠そのものや照合記録の代わりとして使わない。未完了の準備は作業ツリーごとに1件とし、スクリプトの実行中は同時実行を拒否する。別製品の並行準備も同じ作業ツリーでは拒否する。
  - why: Cargo.lock と index を共有する2製品の混入を避ける。ignored 状態は操作再開のための識別と内容確認だけに使う。
  - decided_by: LLM（既存の2製品が共有する変更先に基づく具体化）
- A7 失敗や中断では、LLM が作った照合記録、他者の変更、候補コミットを自動削除・reset しない。候補コミット前の abort は、生成ファイルが保存済みの生成内容と一致し、HEAD が開始点のままの場合だけ生成ファイルを戻す。追加記録は保持する。候補コミット後の失敗はタグを作らず、同じ候補に対する再検証を可能にする。
  - why: 従来の EXIT trap の reset/restore は受け渡し後の他者の内容や記録を失わせうる。失敗した候補は公開されておらず、検証し直せるが、履歴の巻き戻しは別の操作である。
  - decided_by: LLM（共有作業の保護と既存の公開前失敗の境界の具体化）
- A8 確定済み状態への finalize は新しいコミットもタグも作らず、既存の結果を確認して報告する。中断後の finalize は保存した開始点・生成内容・候補 SHA と現在の Git 状態が一致するときだけ再開し、開始点の前進や別コミットへの変化は停止する。タグ作成の直後に中断した場合は、保存した候補を指す注釈付きローカルタグだけを今回の結果として照合する。
  - why: 二重確定と、意図しない新しい HEAD への再開を防ぐ。状態ファイルの進み方だけで Git の事実を推測しない。
  - decided_by: LLM（中断時の Git 状態と操作状態の照合の具体化）
- A9 tag の push、pre-push、公開済みタグの不変、GitHub Release の生成は既存の人による公開の境界を維持する。role と記録ファイルの位置だけでは根拠の意味や review の独立性を証明したと扱わない。
  - why: 今回の追加はローカルの受け渡しであり、公開の自動化や意味の機械証明を承認していない。
  - decided_by: LLM（既存公開境界と変更照合の限界を維持した具体化）

- A10 candidate または complete の abort は履歴・タグ・照合記録へ触れず、候補情報を保持して操作状態だけを aborted にする明示中止として終了0にする。現在 HEAD が保存候補と違ってもそれを採用・合格とせず、保存候補と現在 HEAD を報告する。利用者が通常の修正や手元履歴の処理で clean-tree に戻してから再準備できるようにし、次の prepare は終端状態を ignored な操作履歴へ保存してから新しい状態に置き換える。
  - why: 候補を修正したい場合にも未完了状態から安全に抜ける経路が必要で、内容を消す権限と操作中止を分ける。操作履歴は根拠の記録ではなく、tracked の照合と判断を保持する。
  - decided_by: 利用者（状態だけ中止にする推奨を明示承認）

- A11 設定された新規照合記録のパス判定は、scripts 内の Cargo example helper から既存 Config::parse と change_records::glob を呼び出す。root Cargo.toml には example の配置だけを宣言し、追加依存と公開 CLI は作らない。helper は引数の相対パスが設定の記録 glob に合うかを終了状態だけで返す。
  - why: shell で YAML/glob を再実装すると、変更照合と異なる生成境界を許しかねない。既存設定検査と同じ glob 判定を再利用する。
  - decided_by: 実装役（既存公開 helper の探索結果に基づく、承認済み操作境界を変えない具体化）

## Reuse

| 層 | 採用と根拠 |
|---|---|
| 版・lock・履歴の生成 | 既存 release.sh の製品対応、awk による変更と check-versions.sh を再利用する。新しい版計算は不要 |
| 内容と開始点の識別 | Git の object ID・tree と既存 changes の before/after を利用する。独自の差分解析は不要 |
| 照合と判断記録 | 既存 changes の YAML と独立 review を利用する。release 専用の根拠形式は作らない |
| 途中状態 | 既存シェルと jq による版付き JSON を作業ツリー内に保存する。Git の実状態との照合に限る小さな操作状態が必要 |
| 同時実行 | POSIX の mkdir による作業ツリー内の排他を利用する。共有 Cargo.lock のためスクリプト呼び出しは直列にする |
| 観測 | 一時 Git リポジトリとローカル bare origin、既存シェル検査を利用する。実公開は不要 |

## Rejected

- R1 release の commit だけフックを無効化する方式は採らない。
  - why: 自動生成の変更も記録と独立照合を要求するという A1 を失う。
- R2 失敗時に HEAD を自動 reset し、追加照合記録を削除する方式は採らない。
  - why: 受け渡し後の内容をスクリプト自身の生成物と区別できず、別作業を破壊しうる。

## 優先関係

この追加判断により、既存リリース判断の A4 のローカル一括処理と A9 の公開前ゲートを、この文書の A1〜A10 と操作仕様で具体化する。PROJECT.md の「失敗時にファイルを戻しコミットもタグも残さない」という従来の記述は、生成内容・記録・未公開候補を保持して安全に再開する A7 に置き換える。それ以外の配布、製品の版、公開・pre-push の契約は維持する。既存2引数がタグを作らず準備だけで終了することと失敗時に内容を保持することは、運用上の breaking change として CHANGELOG と PROJECT.md へ明記する。

## Revisions

- 既存のリリース判断 A4・A9 のローカル一括処理と失敗時の動作を今回の受け渡しへ具体化して採用した。旧決定の本文は上書きせず、旧記録へ superseded_by のリンクを追加する。
- 独立 review の指摘を受け、利用者が candidate/complete の状態だけを中止にする A10 を承認した。
