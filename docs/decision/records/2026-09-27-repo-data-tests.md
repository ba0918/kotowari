# 壁打ちの記録: このリポジトリの IR を確かめるシナリオを外す

## Context

tests/step5_findings.rs の ex_core_267 は、このリポジトリ全体にデバッグビルドの "kotowari check" を走らせ、シナリオ EX-core-267（kotowari 自身の IR では unknown_line、unknown_code_block、glossary_title_invalid が出ない）を確かめている。2026-09-27 の実測で 2.34 秒かかり、テストの残りはどれも 0.05 秒以下だった。
テストのバイナリの時間は一番遅いテストで決まり、変異テストは変異1件ごとにテスト全体を回すので、この 2 秒余りが変異の数だけ掛かる。
このテストが確かめるのは製品の振る舞いではなくこのリポジトリのデータで、同じことは pre-commit のフックの "kotowari check"（3つとも誤りなのでコミットで止まる）が既に保証している。

Position: 承認済み（2026-09-27）。A1 を決めた。

## Agreements

- A1 シナリオ EX-core-267 を IR から外し、それを確かめる ex_core_267 のテストを消す。3つの種類がそれぞれ誤りになることは、一時的なリポジトリで確かめる EX-core-266、EX-core-376、EX-core-377 が残る
  - why: 対象がこのリポジトリのデータで製品ではなく、テストの証拠の条件に当たらない。同じことはコミットの関門が保証していて二重になり、2 秒余りが変異テストの変異ごとに掛かる
  - decided_by: 利用者（推奨を採用）
