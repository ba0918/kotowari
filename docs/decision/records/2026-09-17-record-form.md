# 壁打ちの記録: 判断の記録の形を kotowari の check で検査する

## Context

判断の記録の形（決定の行に理由、Superseded の行に「改めた:」、「改めた:」のリンク先の実在）は [decision-log の A1](./2026-09-17-decision-log.md#A1)、[A3](./2026-09-17-decision-log.md#A3)、[A12](./2026-09-17-decision-log.md#A12) で決めたが、守らせる手段はスキルの手順と承認前のレビューだけで、kotowari の check は記録を出典の先としてしか読まない（[A7](./2026-09-17-decision-log.md#A7)、[U1](./2026-09-17-decision-log.md#U1)、[U2](./2026-09-17-decision-log.md#U2)）。
理由の無い決定と、置き換えられたのに現役の顔で残る決定は、利用者が防ぎたい事故（理由の無いログ、矛盾を抱えたままの出荷）の形そのもの。
2026-09-17 の実測では、8本の記録の決定 308 行のうち理由の行を持つのは decision-log の 22 行だけで、既存の記録は書き直さない（[A8](./2026-09-17-decision-log.md#A8)）ので、検査の適用範囲を決めないと初日から 286 件の誤りになる。
そこで、どの検査を kotowari に足すか、どの記録に適用するか、リンクの解決の規則、指摘の種類と重さ、Markdown の構造の取得を mds（利用者が実装中の Markdown スキーマの道具）に任せるかを決める。

Position: 承認済み（2026-09-17）。計画 docs/plans/record-form.md も承認済み（A44〜A46 を同時に確定）。次は cycle。実装役は Opus 5 の subagent（Codex は 9/23 まで使えない）

## Agreements

- A1 記録の形の検査は、`## 背景と目的` の節を持つ判断の記録だけに適用する。持たない記録は出典の先としてだけ読む（今までどおり）
  - why: 既存の記録は書き直さない（[decision-log の A8](./2026-09-17-decision-log.md#A8)）ので、全記録に適用すると初日から 286 件の誤りになる。`## 背景と目的` は新しい記録に必ず置くと決めた見出し（[A6](./2026-09-17-decision-log.md#A6)）で、追加の設定なしに新旧を分けられる（実測で持つのは decision-log だけ）。見出しが検査の切り替えになるのは暗黙的なので、用語集と references に「背景と目的の節を持つ記録が新しい形」と明記する
  - rejected: 設定に除外するファイルの一覧を足す（鍵が増えて設定のテストが動く）。旧記録は notice にする（記録によって重さが変わり分かりにくい）
  - decided_by: 利用者（推奨を採用）

- A2 必須の補足の行は節ごとに決定表で決める。Agreements と Prohibitions の決定の行は「理由」、Rejected と Delegated の行は「理由」、Undecided の行は「決める人」、Superseded の行は「改めた」。「理由: 記録なし」は通す
  - why: [decision-log の A1](./2026-09-17-decision-log.md#A1) と [A12](./2026-09-17-decision-log.md#A12) で決めた規則をそのまま表にする。中身は見ない（[REQ-062](../../ir/sources.md#REQ-062) と同じ線。[A2](./2026-09-17-decision-log.md#A2) の「記録なし」は無いことを見えるようにするための値）
  - decided_by: 利用者（推奨を採用）

- A3 「置き換えられた決定」の定義を機械的にする: `## Superseded` の節にあって「改めた:」を持つ行。Revisions の節の文（「X は Y を置き換える」）は人向けの説明で、検査の根拠にしない
  - why: Revisions の文は自然文で、機械で読む根拠が無い（R1）。置き換えの事実は行の置き場で表す
  - decided_by: 利用者（推奨を採用）

- A4 「改めた:」の行の規則: (i) Markdown のリンクを1つ以上持つ。素の番号だけは誤り。(ii) href はその文書からの相対パス（[decision-log の A10](./2026-09-17-decision-log.md#A10)）で、正規化（[REQ-110](../../ir/base-directory.md#REQ-110)）の後に decisions.records の中に収まる。(iii) `#` の後は決定の番号で、リンク先のファイルの決定の節か Superseded の節にその番号の行がある。(iv) 1行に複数のリンクがあれば全部を解決する
  - why: 5か所ある既存の「改めた:」はすべてリンクで、records.md の A54 は2つ持つ。Superseded の行を先として認めるのは、A54 → A21 → その先、の連鎖を許すため
  - decided_by: 利用者（推奨を採用）

  - why: 出典の判定と同じく、見るのは `- 名前:` の形で、字下げそのものは判定に関係しない（[workflow.md](../../../skills/kotowari/references/workflow.md) の記述と揃える）
