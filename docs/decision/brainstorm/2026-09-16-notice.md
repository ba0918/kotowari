# 壁打ちの進捗: 終了コードを変えない指摘の severity を notice にする

目的: too_many_lines と too_many_requirements の severity が "warning" だと、書き手（LLM も人も）が「対応必須」と読み、責務が同じ内容を行数で切ってしまう。kakoi-net の要件定義で実際に起きた。この段は最初から助言の意味でしか使われていない（A29: 警告はこの2種類だけ）ので、3段目を足すのではなく名前を改める。

Position: 1ラウンドで全部推奨を採用。IR を改訂し、実装する

## Agreements
- A1 severity の値は "error" と "notice" の2つ。JSON は "notice"、text 形式は "[notice]"。"warning" は使わない（利用者、2026-09-16）
- A2 用語集の「警告」を「注意」に改名する。意味は「終了コードを変えない指摘」のまま。IR の文中と見出しの「警告」はすべて「注意」にする（推奨を採用）
- A3 終了コードと counts は変えない。注意だけなら終了コード0、counts には種類ごとに出る（A29 の言い換え）（推奨を採用）
- A4 実装はメインセッションが直接行い、差分レビュー1本（調査役1体）で確かめる。フルレビューは行わない。理由: 名前の置換で、既存のテストが振る舞いを固定している（推奨を採用）

## Rejected
