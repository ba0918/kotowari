# 問題の記録

## 問題の記録

### FLAG-core-009: 宣言の外にある表とコードブロックの写し先が決まっていない

- 種類: gap
- 関係: REQ-core-044, REQ-core-174, TBL-core-030
- 出典: docs/decision/records/2026-09-22-ir-engine.md#A33, docs/decision/records/2026-09-22-ir-engine.md#A74

スキーマの側は、宣言の外にある`表`と`コードブロック`にも宣言の外の行の`指摘`を出す（実測）。REQ-core-044 の unknown_field は一覧の行を、REQ-core-174 の unknown_line は「一覧でも`表`でもない空でない行」を対象にしていて、どちらもこの2つを覆っていない。写し先が無いと REQ-core-172 で`停止`するが、`停止`にするのが正しいかも決まっていない。

### FLAG-core-010: 用語のセルが空の行を誰が見つけるか決まっていない

- 種類: gap
- 関係: REQ-core-122, REQ-core-173
- 出典: docs/decision/records/2026-09-22-ir-engine.md#A24

REQ-core-122 は、セルが3つ未満の行か`用語`のセルが空の行に invalid_glossary_row を出すと定める。スキーマの側は`表`のヘッダの不一致と列の数の不一致しか見ず、3列あって`用語`のセルだけが空の行には`指摘`を出さない。REQ-core-173 の kotowari に残す検査の列挙にもこの判定が無い。

### FLAG-core-011: 形に合わない見出しの下の指摘をどう扱うか決まっていない

- 種類: gap
- 関係: REQ-core-043, REQ-core-177, TBL-core-030
- 出典: docs/decision/records/2026-09-22-ir-engine.md#A75

REQ-core-043 は、形に合わない見出しの下の行を`項目`として読まないと定める。スキーマの側は`ID`の形に合わない見出しに`指摘`を出したうえで、その中の行を`項目`の規則で検証し続ける。置き換えると、形に合わない見出しの下に必須の行の欠落などの`指摘`が増える。REQ-core-177 が許す8つの差分にこれが無く、足すか、写す層で落とすかが決まっていない。
