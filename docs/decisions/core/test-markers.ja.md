# テストのマーカー

[English](test-markers.md) | 日本語

テストに書くマーカーの形と、マーカーをテストに結び付ける規則を扱う。テストをどう見つけるかは[テストの見つけ方](test-discovery.ja.md)で決める。マーカーの無いテストの誤りと、問い合わせの無い言語のマーカーの数え方は[テストとマーカーの対応](coverage.ja.md)で決める。マーカーがどの文書にも無い ID を指すときの誤りは、[check は、確認することの行ごとに、それを指すテストがあるかを数える](confirmations.ja.md#check-は確認することの行ごとにそれを指すテストがあるかを数える)で決める。

## マーカーは ID をコンマで並べた形で、行のどこにあってもよい

状態: 実装済み

### 問題

kotowari 自体は Rust で書くが、利用者のテストが何の言語で書かれるかは分からない。テストと仕様の対応は、言語に依存しない方法で見つけたい。また、マーカーの名前が短すぎると、ほかの道具の書き方とかぶる。

### 決めたこと

テストのマーカーは、次の形で書く。

| 部分 | 形 |
|---|---|
| 始まり | @kotowari[ |
| 中身 | ID をコンマで区切って並べる。コンマの前後に空白を置いてよい |
| 終わり | ] |

マーカーは行のどの位置にあってもよく、kotowari はコメント記号を見ない。1行の中にマーカーが複数あれば、すべて拾う。名前を "@spec" でなく "@kotowari" にしたのは、ほかとかぶる可能性があるからである。

### 確認すること

- C-core-markers-1 コンマの前後に空白を置いたマーカーから、check が ID を1つずつ読み、マーカーのある行を記録する
- C-core-markers-2 1行に2つのマーカーがあると、check が両方を拾い、テストは両方の ID に結び付く
- C-core-markers-3 コメント記号の種類を問わず、行のどの位置にあるマーカーも拾う

## 形の誤ったマーカーには invalid_marker の誤りを出し、マーカーの行を指す

状態: 実装済み

### 問題

マーカーの中が空だったり、閉じていなかったりする書き間違いがある。そう決めた理由は残っていない。

### 決めたこと

マーカーの中が空か区切り（コンマと空白）だけのとき、または同じ行に閉じ括弧が無いとき（行をまたぐマーカーを含む）、check は invalid_marker の誤りを出す。detail は、そのマーカーのある行の文字そのまま（字下げと末尾の空白を含み、作り直さない）にする。

マーカーから出す invalid_marker と unresolved_reference の "line" は、マーカーのある行（行をまたぐマーカーなら "@kotowari[" のある行）にする。

問い合わせのある言語では、テストに結び付かないマーカー（[マーカーは、テストの直前のコメントの塊にあるものだけをそのテストに結び付ける](#マーカーはテストの直前のコメントの塊にあるものだけをそのテストに結び付ける)）の形は見ない。

### 確認すること

- C-core-markers-4 テストの直前のコメントにある、中が空か区切りだけのマーカーに、check が invalid_marker の誤りを出す。同じ行の2つ目のマーカーでも出す
- C-core-markers-5 閉じ括弧が次の行にある、行をまたぐマーカーに、check が "@kotowari[" の行を "line" にした invalid_marker の誤りを出す
- C-core-markers-6 invalid_marker の detail は、マーカーのある行の文字そのままで、字下げを含む
- C-core-markers-7 マーカーから出す invalid_marker と unresolved_reference の "line" は、マーカーのある行になる。複数行のコメントの2行目や、マクロの中のマーカーでも同じである

## マーカーは、テストの直前のコメントの塊にあるものだけをそのテストに結び付ける

状態: 実装済み

### 問題

関数の本体の先頭のコメントのマーカーも結び付けようとすると、本体の先頭を言語に依存せずに決められない（関数の次の行に "{" を置く書き方や、Python のコメントが本体の節の手前に入る癖がある）。kotowari 自身のテストの1124個のマーカーのうち、本体の先頭にあったのは1個で、それも説明のコメントにマーカーの文字が入っていただけだった。結び付かないマーカーのテストにはマーカーの無いテストの誤りが出るので、マーカーが黙って消えることはない。

テストの中に別のテストがあるときは、結び付ける規則と無視する規則の両方が当たってしまう。1行に2つのテストが始まるとき、両方に結び付けると、1つのマーカーから指摘が2件出る。マクロの中の関数にだけ別の規則を当てると、結び付けの規則が2つになる。

### 決めたこと

問い合わせのある言語では、テストの直前のコメントの塊（[直前のコメントの塊は、空行までのコメントの行と、言語ごとの挟んでよい行でできる](#直前のコメントの塊は空行までのコメントの行と言語ごとの挟んでよい行でできる)）にあるマーカーだけを、そのテストに結び付ける。

| マーカーの位置 | 扱い |
|---|---|
| テストの直前のコメントの塊 | そのテストに結び付ける。最初の行が同じテストが2つ以上あるときは、その行で最初に始まるテストにだけ結び付け、ほかのテストはマーカーの無いテストとする |
| テストの節の中（関数の本体の先頭のコメントを含む）。ただし、節の中にある別のテストの直前のコメントの塊は除き、そのマーカーは内側のテストに結び付ける | 無視し、invalid_marker も unresolved_reference も出さない |
| どのテストの直前のコメントの塊にも無い | 無視し、invalid_marker も unresolved_reference も出さない |
| "tests.rust.macros" のマクロの中の関数 | 上と同じ規則を当てる |

### 見送った案

- 以前の決定: 関数の本体の先頭のコメントのマーカーも、直前のコメントのマーカーと合わせて結び付ける。本体の先頭を言語に依存せずに決められないので、やめた。

### 確認すること

- C-core-markers-8 関数の本体の先頭のコメントにあるマーカーはテストに結び付かず、直前にマーカーが無ければそのテストに test_without_id が出る。直前のマーカーにも足されない
- C-core-markers-9 どのテストの直前のコメントの塊にも無いマーカーと、本体の途中や先頭にあるマーカーは、形が誤っていても、存在しない ID を指していても、invalid_marker も unresolved_reference も出さない
- C-core-markers-10 テストの中の別のテストの直前にあるマーカーは、内側のテストに結び付く
- C-core-markers-11 1行に2つのテストが始まるとき、直前のマーカーは最初のテストにだけ結び付き、もう1つのテストに test_without_id が出る
- C-core-markers-12 "tests.rust.macros" のマクロの中の関数にも、直前のコメントの塊の規則が当たる

## 直前のコメントの塊は、空行までのコメントの行と、言語ごとの挟んでよい行でできる

状態: 実装済み

### 問題

コメントが構文木のどこに入るかは言語ごとに違う。4つの言語で実測すると、コメントはどれも tree-sitter の extra の節だった。行で決めれば、Python のようにコメントが構文木のどこに入っても同じ結果になる。

Java、C#、PHP、Kotlin のように、アノテーションや属性がテストの節の中に入る言語では、挟んでよい行の表は要らない。外に出るのは Rust と Python である。複数行を許さないと、"@pytest.mark.parametrize(...)" をよくある書き方で書いたときにマーカーが結び付かない。複数行の属性やデコレータの途中の空白だけの行で塊が切れると、複数行を許した趣旨に反する。

「コメントだけの行」の範囲が決まっていなかった。前後の空白の範囲が、名前の無いテストの detail の空白（Unicode の空白）と食い違っていた。マーカーはコメントに書くという約束を保ちたい。

### 決めたこと

直前のコメントの塊は、テストの節の最初の行の直前から上に向かって、空行が来るまで続く、コメントだけの行と、次の表の挟んでよい行の塊とする。

コメントだけの行は、前後の空白（Unicode の空白。全角空白と NBSP を含む）を除いた行の文字が、すべてコメント（tree-sitter の extra の節）の文字である行とする。複数行のコメントの途中の行を含み、コードと同じ行にあるコメントの行は含まない。

コメントだけの行と挟んでよい行は、空行なしで混ざってよい。複数行にわたる属性とデコレータは、その全部の行を挟んでよい行とする。複数行のコメント、属性、デコレータの途中にある空白だけの行は、塊を切らない。

塊の行のうち、マーカーを読むのはコメントの文字だけにする。属性やデコレータの本体（"#[doc = \"...\"]" の文字列を含む）にあるマーカーは読まず、指摘も出さない。

| 言語 | 挟んでよい行 |
|---|---|
| Rust | 属性（"#[...]"）の行 |
| Python | デコレータ（"@..."）の行 |
| そのほかの言語 | 無し |

設定でルールを足しただけの言語は、コメントの行だけで塊を作る。

### 確認すること

- C-core-markers-13 テストの直前に空行なしで続くコメントのマーカーはそのテストに結び付き（クラスの中のメソッドを含む）、マーカーとテストの間に空行があると結び付かない
- C-core-markers-14 マーカーとテストの間に Rust の属性か Python のデコレータ（複数行のものを含む）とコメントの行が空行なしで挟まっても、マーカーはテストに結び付く
- C-core-markers-15 複数行のコメント、属性、デコレータの途中にある空白だけの行では、塊が切れない
- C-core-markers-16 挟んでよい行の無い言語でコードの行が挟まると、また、コードと同じ行にあるコメントの行が挟まると、塊が切れてマーカーは結び付かない
- C-core-markers-17 全角空白の後に始まるコメントの行も、コメントだけの行として塊に入る
- C-core-markers-18 属性の本体の文字列にある "@kotowari[" は読まれず、存在しない ID でも unresolved_reference が出ない

## 問い合わせの無い言語のファイルでは、ファイルの中のマーカーをすべて拾う

状態: 実装済み

### 問題

問い合わせの無い言語のファイルでは、テストもコメントも見分けない（[問い合わせが1つも無い言語のファイルは構文木を読まない](test-discovery.ja.md#問い合わせが1つも無い言語のファイルは構文木を読まない)）。そのファイルのマーカーをどう拾うかを決める必要がある。そう決めた理由は残っていない。

### 決めたこと

問い合わせの無い言語のテストのファイルでは、コメントかどうかを問わず、ファイルの文字の中のマーカーをすべて拾う。形の誤ったマーカーには、ファイルのどこにあっても invalid_marker を出す。拾ったマーカーをどう数えるかは、[問い合わせの無い言語のファイルのマーカーも、確認することの行を満たす側に数える](coverage.ja.md#問い合わせの無い言語のファイルのマーカーも確認することの行を満たす側に数える)で決める。

### 確認すること

- C-core-markers-19 問い合わせの無い言語のファイルでは、コメントでない行にあるマーカーも拾われ、"line" はその行になる
- C-core-markers-20 問い合わせの無い言語のファイルにある形の誤ったマーカーに、invalid_marker の誤りが出る

## どの文書にも無い ID だけを指すマーカーでも、テストはマーカーのあるものと数える

状態: 実装済み

### 問題

マーカーが指す ID が仕様に無いときに、そのマーカーの結び付いたテストをどう数えるかを決める必要がある。そう決めた理由は残っていない。

### 決めたこと

マーカーがどの文書にも無い ID だけを指していても、そのマーカーが結び付いたテストは、マーカーのあるテストと数え、test_without_id を出さない。無い ID を指すことは、[check は、確認することの行ごとに、それを指すテストがあるかを数える](confirmations.ja.md#check-は確認することの行ごとにそれを指すテストがあるかを数える)で決めた unresolved_reference の誤りになる。

### 確認すること

- C-core-markers-21 どの文書にも無い ID だけを指すマーカーが結び付いたテストには、test_without_id が出ない

## 読んで確かめる行を指すマーカーは、誤りにしない

状態: 実装済み

### 問題

頭に「（読んで確認）」と書いた確認することの行は、テストで確かめない行である。その行の ID をマーカーが指したときに、どう扱うかを決める必要がある。そう決めた理由は残っていない。

### 決めたこと

マーカーが、頭に「（読んで確認）」と書いた確認することの行の ID を指しても、check は誤りにしない。その行には、それでもテストを求めない。

### 確認すること

- C-core-markers-22 頭に「（読んで確認）」と書いた確認することの行の ID を指すマーカーには、check が誤りを出さない
