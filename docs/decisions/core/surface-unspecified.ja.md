# 未記載の面の一覧

[English](surface-unspecified.md) | 日本語

まだ仕様にしていない面を並べる、未記載の面の一覧を扱う。一覧の置き場と1件の形、一覧の1件がどの面を外すか、形の誤った1件と要らなくなった1件への指摘、一覧のファイルが読めないときの停止を決める。面をコードから取り出すことと、面が仕様に書かれているかの判定、外した件数の出力、面の設定の鍵の組み合わせの誤りは[面の検査](surface.ja.md)の話題で決める。

## まだ仕様にしていない面は、理由を付けて未記載の面の一覧に載せれば誤りにしない

状態: 実装済み

### 問題

仕様に書かれていない面を誤りにすると、既存のプロジェクトで面の規則を書いた直後に、大量の誤りが出て導入できない。一方で、誤りを出さない面を黙って増やせると、一覧に頼っている量が見えなくなる。変異テストの等価の一覧と同じ作りにすれば、1件ごとに理由が残り、一覧に頼った量を毎回見せられる。一覧を減らす作業は kotowari-adopt が拾う。

一覧の1件と面を比べるときに、前後の空白を除いたり、一部の一致を認めたりすると、書いた人の意図より広い面が黙って外れる。完全な一致にした理由は、等価の一覧と同じ作りにすることのほかは記録に残っていない。

### 決めたこと

まだ仕様にしていない面は、設定の "surface.unspecified" が指す YAML のファイルに、1件ずつ並べる。1件は種類の "kind"、名前の "name"、理由の "why" の3つを持ち、理由は必ず書く。

一覧の1件は、種類と名前の両方がその1件と同じ面だけを外す。比べるのは "kind" と "name" の値そのままで、前後の空白を除かない。外した面には、仕様に書かれていなくても surface_without_spec を出さない。設定に "surface.unspecified" の鍵が無ければ、一覧は無いものとして検査を続ける。

外した件数を check の出力に出すことは[未記載の面の一覧で外した面の数を、check の出力の最後に必ず出す](surface.ja.md#未記載の面の一覧で外した面の数をcheck-の出力の最後に必ず出す)で、面の規則が無いのに "surface.unspecified" の鍵だけがある設定の扱いは[面の設定の鍵が揃っていないときは、設定を読むどのコマンドも停止する](surface.ja.md#面の設定の鍵が揃っていないときは設定を読むどのコマンドも停止する)で決める。

### 確認すること

- C-core-unspec-1 一覧に載った面には、仕様に書かれていなくても surface_without_spec の誤りが出ない
- C-core-unspec-2 一覧の1件と、種類か名前が違う面は外れず、surface_without_spec の誤りが出る
- C-core-unspec-6 一覧の1件の "name" の後ろに空白があると、空白の無い名前の面は外れず、surface_without_spec の誤りが出る

## 形の誤った1件は誤りにし、要らなくなった1件は注意にする

状態: 実装済み

### 問題

一覧の1件が壊れているときと、もう要らなくなったときの扱いを決める必要があった。変異テストの等価の一覧では、形の誤った1件を誤りに、要らなくなった1件を注意にしている。同じ扱いにする。

形の誤りとする条件を狭くすると、壊れた1件や、空白だけの理由の1件が、形の正しい1件として面を外してしまう。条件の細かい決め方の理由は、等価の一覧と同じ作りにすることのほかは記録に残っていない。

### 決めたこと

鍵と値の組（YAML の対応付け）でない1件、"kind"、"name"、"why" の3つの形になっていない1件、理由が空の1件は形の誤りとし、surface_unspecified_invalid の誤りを1件ごとに出す。理由は、前後の半角空白とタブを除いて空になるとき、空とみなす。形の誤った1件では、どの面も外さない。

形の正しい1件のうち、その面がコードから消えたものと、その面が決定の文書に書かれるようになったものは、要らなくなった1件とし、surface_unspecified_stale の注意を1件ごとに出す。注意なので、終了コードは変えない。

### 確認すること

- C-core-unspec-3 理由が空白だけ、鍵が欠けている、3つ以外の鍵がある、値が文字列でない1件には surface_unspecified_invalid の誤りが出て、その1件の面は外れない
- C-core-unspec-4 面がコードから消えた1件と、面が決定の文書に書かれた1件には surface_unspecified_stale の注意が出て、注意のほかに誤りが無ければ終了コードは0のままである
- C-core-unspec-7 鍵と値の組でない1件（文字列だけの1件）にも surface_unspecified_invalid の誤りが出て、理由が半角空白とタブだけの1件は理由が空として surface_unspecified_invalid の誤りが出る

## 一覧のファイルが無いか読めなければ、check と status は停止する

状態: 実装済み

### 問題

面を読むのは check と status だけで、list、query、plan、mutants は面を読まない。一覧のファイルの誤りで、一覧を読まないコマンドまで止めることはしない。一覧のファイルが読めないときに検査を続けず停止すると決めた理由は残っていない。

読めない一覧を空の一覧として続けると、載せた面が黙って誤りになるか、壊れた一覧に気づけない。停止の理由を取り違えると、直す人が見るべきもの（ファイルがあるか、文字コードか、中身の形か）が分からなくなる。理由の種類を分けた理由は、等価の一覧と同じ作りにすることのほかは記録に残っていない。

### 決めたこと

設定の "surface.unspecified" が指すファイルが無いか、読めないか、一覧として読めない（UTF-8 でない、YAML として読めない、最上位が並びでない）とき、check と status は停止する。停止の理由は、ファイルが無いか読めなければ読めないファイル（unreadable file）、UTF-8 でなければ UTF-8 でないファイル（non-UTF-8 file）、YAML として読めないか最上位が並びでなければ設定の誤り（config error）にする。ほかのコマンドは一覧を読まないので、一覧のファイルの誤りでは止まらない（どのコマンドが面を読むかは[面を読むのは check と status だけにする](surface.ja.md#面を読むのは-check-と-status-だけにする)で決める）。

### 確認すること

- C-core-unspec-5 一覧のファイルが無いか、UTF-8 でないか、YAML として読めないか、最上位が並びでないとき、check と status は停止する
- C-core-unspec-8 停止の理由は、一覧のファイルが無ければ "unreadable file"、UTF-8 でなければ "non-UTF-8 file"、YAML として読めないか最上位が並びでなければ "config error" になる
