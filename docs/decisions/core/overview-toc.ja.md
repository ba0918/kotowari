# 全体像の目次

[English](overview-toc.md) | 日本語

全体像の目次（一覧のページで、全体像のページをどう束ね、どの順に並べるかを宣言するファイル）の置き場と読み方、形、全体像の元データとの食い違いの検査、目次を描画のエンジンに渡すことを決める。一覧のページを目次からどう描くかは、view の決定（[一覧は、目次に書いた順と入れ子のとおりに、1ページで描く](../view/rendering.ja.md#一覧は目次に書いた順と入れ子のとおりに1ページで描く)と、[一覧と移動](../view/navigation.ja.md)）で決める。目次の対は[ガイド、全体像の元データ、目次は、言語の一覧のすべての言語の側を持つ](translation-pairs.ja.md#ガイド全体像の元データ目次は言語の一覧のすべての言語の側を持つ)で決める。

## 一覧の束ね方と並びは、overview.toc の指す目次のファイル1つに書く

状態: 実装済み

### 問題

全体像のページは話題ごとに増えていき、ページの数は製品の規模で決まるので、非常に多くなりうる。一覧で迷うと、全体像の価値が落ちる。日本語の題名は、名前の文字の順に並べても読む側には順不同に見え、まとまりも無い。

一覧の地図（群の名前、入れ子、順番、各群に属するページ）は、1か所に書くのが読み手の意図に近い。目次は人が読むものではなくデータである。全体像の元データの置き場は拡張子が ".md" のファイルしか読まないので、YAML にすれば元データとぶつからない。目次の無い並べ方も残すと、どちらの一覧かを毎回考えることになる。

目次が UTF-8 でないときの停止の理由を落とすと、全体像の元データと止まり方が揃わない。目次の読み方は、元データの読み方に揃える。

### 決めたこと

一覧のページの束ね方（目次の群の名前、入れ子、順番、各群に属するページ）は、設定の "overview.toc" が指す YAML のファイル1つに書く。これを目次と呼ぶ。新しい全体像のページを作るときは、目次も直す。

設定に "overview" のキーがあるときは、"overview.toc" も必須にする。目次を使わずに並べる動きは持たない（"overview.toc" が無いときの設定の誤りは、[設定ファイルが YAML として読めないか、キーと値が決まりに合わなければ、設定の誤りで停止する](config.ja.md#設定ファイルが-yaml-として読めないかキーと値が決まりに合わなければ設定の誤りで停止する)で決める）。

"overview" のキーがあるとき、"kotowari check"、"kotowari status"、"kotowari overview build"、"kotowari overview serve" は目次を読む。目次のファイルが無いか読めないときは、読めないファイルを理由に停止する。UTF-8 でないときは、全体像の元データ（[全体像の元データは、リポジトリにコミットして保守し、overview.files の glob で選ぶ](overview-data.ja.md#全体像の元データはリポジトリにコミットして保守しoverviewfiles-の-glob-で選ぶ)）と同じく、UTF-8 でないファイル（"non-UTF-8 file"）を理由に停止する。

### 見送った案

- 元データのディレクトリで束ね方を表す。ディレクトリの名前は英数字なので、群の名前と順番を別の場所に書くことになり、書く場所が2つに割れる。
- 各元データの frontmatter に、群と番号を書く。順番が散らばり、1ページ足すたびに番号がずれやすい。
- 仕様の置き場のディレクトリから、束ね方を機械で作る。まとまりのディレクトリが3つしか無く、ほぼすべてのページが1つの群に入る。

### 確認すること

- C-core-ovtoc-1 "overview" のキーがあるとき、check は目次を読み、目次の誤りを、path を目次のファイルにした指摘として出す
- C-core-ovtoc-2 目次のファイルが無いと、check、status、overview build は、読めないファイルを理由に終了コード 2 で停止する
- C-core-ovtoc-3 目次のファイルが UTF-8 でないと、check は終了コード 2 で停止する
- C-core-ovtoc-16 目次のファイルが UTF-8 でないときの標準エラーの1行目は、"non-UTF-8 file: " と目次のパスになる

## 目次のファイルが元データ・ガイド・テストの置き場にも入れば、設定の誤りで停止する

状態: 実装済み

### 問題

目次を ".md" のファイルにして、全体像の元データの置き場に巻き込んでしまう書き間違いは、実際に起きうる。重なりの扱いと詳細の書き方は、全体像の元データとガイドの置き場の重なりと同じ形にそろえる。

重なりを glob の文字列で決めると、元データの glob が "dir/*" で目次が "dir/toc.yaml" のときのように、元データとして読まれないファイルまで誤りにする。この判定の仕方を落とすと、その誤りを防ぐ決まりが決定から消える。

### 決めたこと

目次のファイルが、全体像の元データ、ガイド、テストのどれかの置き場（"overview.files"、"guides.files"、"tests.files"）にも入るとき、設定の誤りで停止する。置き場に入るかは、glob の文字列ではなく、それぞれの置き場の走査で実際に読むファイルに目次のファイルが入るかで決める。全体像の元データの走査は、拡張子が小文字の ".md" のファイルだけを読む。詳細は、目次のパスに ": matched by both overview.toc and " と、当たったキーのうち "overview.files"、"guides.files"、"tests.files" の順で最初のものの名前を続けたものにする。

[全体像の元データとガイドかテストの置き場の重なり](overview-data.ja.md#全体像の元データがガイドかテストの置き場と重なると設定の誤りで停止する)と、[ガイドとテストの置き場の重なり](guides.ja.md#ガイドとテストの置き場が重なると設定の誤りで停止する)があれば、そちらを先に判定する。

### 確認すること

- C-core-ovtoc-4 "overview.files" が ".kotowari/overview/*.md" で "overview.toc" が ".kotowari/overview/toc.md" のとき、check は終了コード 2 で停止し、標準エラーの1行目は "config error: .kotowari/overview/toc.md: matched by both overview.toc and overview.files" になる
- C-core-ovtoc-5 目次のファイルが "guides.files" か "tests.files" の置き場に入ると、詳細の最後がそのキーの名前になった設定の誤りで停止する
- C-core-ovtoc-6 全体像の元データとガイドの置き場も重なっているときは、目次の重なりより先に、元データとガイドの重なりの設定の誤りが出る
- C-core-ovtoc-15 "overview.files" が "notes/*" で "overview.toc" が "notes/toc.yaml" のとき、check は重なりで止まらない

## 目次は、いちばん外側を1つの目次の群とする入れ子で書く

状態: 実装済み

### 問題

ページの数に上限を置かないので、1段で束ねるだけでは、群が増えたときに、群の見出しの並びが同じように読みにくくなる。1段は階層の特別な場合なので、小さい製品は1段のままでよい。いちばん外側も目次の群と同じ形にすれば、外側だけ形の違うものを作らずに済み、一覧に見出しと件数が付く。見出しの空な群は一覧で読めず、空の名前はどのページも指さない。

### 決めたこと

目次は次の形で書く。入れ子の深さは制限しない。

| 部分 | 形 |
|---|---|
| 目次の全体 | 1つの目次の群 |
| 目次の群 | "title"（必須。空でない文字列）、"note"（省いてよい。改行を含まない一行の説明）、"items"（必須。ページの名前と目次の群を順に並べた並び）だけを持つ |
| ページの名前 | 全体像の元データのファイル名から ".md" を除いた名前。空でない文字列 |

形に合わない所は、YAML として読めない、知らないキーがある、必須のキーが欠けている、型の違う値がある、"title" かページの名前が空、"note" が改行を含む、のどれかに当たる所で、その所ごとに overview_toc_invalid の誤りを出す。"items" が空の並びの群は形の誤りにせず、[全体像のページは、目次にちょうど1回ずつ置く](#全体像のページは目次にちょうど1回ずつ置く)の overview_toc_group_empty で扱う。

目次の指摘は、path を目次のファイルにし、line を null にする（[line は1始まりで数え、文書全体にかかる指摘は null にする](finding-order.ja.md#line-は1始まりで数え文書全体にかかる指摘は-null-にする)）。overview_toc_invalid の detail は、合わなかった場所の JSON Pointer にし、書き方は全体像の元データの部品の overview_part_invalid（[部品の中身は、kotowari の側が view の部品のスキーマで検査する](overview-data.ja.md#部品の中身はkotowari-の側が-view-の部品のスキーマで検査する)）と同じにする（目次の指摘の detail は[指摘の detail は、その指摘を特定する短い文字列にし、種類ごとに表で決める](findings.ja.md#指摘の-detail-はその指摘を特定する短い文字列にし種類ごとに表で決める)の表のとおり）。

### 見送った案

- 1段で束ねるだけにする。群が増えたときに、一段上で同じ読みにくさが起きる。

### 確認すること

- C-core-ovtoc-7 "title" か "items" の欠け、空の "title"、改行を含む "note"、空のページの名前、型の違う値、知らないキーを持つ群、YAML として読めない目次には、それぞれ overview_toc_invalid の誤りが出る
- C-core-ovtoc-8 "note" を持つ群と入れ子の群を含む、形の正しい目次には、overview_toc_invalid が出ない

## 全体像のページは、目次にちょうど1回ずつ置く

状態: 実装済み

### 問題

1つのページを複数の群に重ねて置くと、一覧の件数が合わず、直す場所も一意に決まらない。目次は全体像を書く LLM が直していくので、目次に無いページを黙って「未分類」に落とすより、止めたほうが直し忘れが無い。目次の誤りを、ほかの元データの誤りと同じく check と status の指摘に入れれば、build が「kotowari check を走らせて」と案内する流れがそのまま使える。

### 決めたこと

目次と全体像の元データが食い違うとき、次の誤りを出す。

| 食い違い | 指摘 |
|---|---|
| 全体像の元データがあるのに、その名前が目次のどこにも無い | overview_toc_page_missing |
| 目次の名前に、全体像の元データが無い | overview_toc_page_unknown |
| 全体像の元データのある名前が、目次に2回以上ある | 2つ目以降に overview_toc_page_duplicate |
| 目次の群（いちばん外側を含む）の "items" が空の並び | overview_toc_group_empty |

名前を照らすのは、先頭の言語の側の元データと目次だけである（[全体像の元データのほかの言語の側は、別のページとして数えない](translation-pairs.ja.md#全体像の元データのほかの言語の側は別のページとして数えない)）。

これらの誤りがあると、"kotowari overview build" と "kotowari overview serve" は何も書かずに止まる（止まるときの理由と詳細は[元データか目次に誤りがあれば、何も書かずに overview error で停止する](overview-commands.ja.md#元データか目次に誤りがあれば何も書かずに-overview-error-で停止する)）。

### 見送った案

- 目次に無いページを「未分類」の群に置いて見せる。直し忘れが見えにくい。

### 確認すること

- C-core-ovtoc-9 全体像の元データが "a.md"、"b.md"、"c.md" で、目次の名前が "a"、"z"、"a" の順のとき、"b" と "c" に overview_toc_page_missing、"z" に overview_toc_page_unknown、2つ目の "a" に overview_toc_page_duplicate の誤りが出る
- C-core-ovtoc-10 "items" が空の目次の群には、入れ子の群でも、いちばん外側の群でも、overview_toc_group_empty の誤りが出る
- C-core-ovtoc-11 目次の誤りがあると、overview build と overview serve は何も書かずに終了コード 2 で止まる

## 形の誤った目次は、元データと照らさない

状態: 実装済み

### 問題

形の崩れた目次で照らすと、ほぼすべてのページが目次に無いと出て、本当の原因が埋もれる。

### 決めたこと

目次に overview_toc_invalid の誤りが1件でもあるときは、その目次に、overview_toc_page_missing、overview_toc_page_unknown、overview_toc_page_duplicate、overview_toc_group_empty の検査をしない。

### 確認すること

- C-core-ovtoc-12 知らないキーを持つ群のある目次では、どの元データの名前も目次に無くても、overview_toc_invalid だけが出て、overview_toc_page_missing は出ない

## 目次は、書いたままの順と入れ子で描画のエンジンに渡す

状態: 実装済み

### 問題

一覧を製品の地図にするなら、使う順や工程の順という順番そのものが情報になる。日本語の題名は読みの順に並べる手段が無く、自動の並びでは順不同に見える。

### 決めたこと

"kotowari overview build" と "kotowari overview serve" は、目次の "title"、"note"、"items" を、書かれたままの順と入れ子で、描画のエンジンの目次として渡す。並べ替えない。

### 見送った案

- 題名や名前の文字の順で、自動に並べる。日本語の題名では順不同に見える。

### 確認すること

- C-core-ovtoc-13 目次に書いた項目の順と入れ子と "note" が、そのまま描画の入力の目次になる
- C-core-ovtoc-14 目次の "title" が "kotowari" で "items" が "b"、"a" の順のとき、overview build が書く一覧の見出しは "kotowari" で、"b" の題名が "a" の題名より前にある
