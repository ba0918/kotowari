[English](cli-environment.md) | 日本語

## "--help" と "--version" は、ほかの引数より先に受け、使い方か版を出して終わる

状態: 実装済み

### 問題

"--help" と "--version" を、ほかの引数や検査とどう組み合わせて扱うかを決める必要がある。ほかの引数に勝たせることと、"check" 無しで受けることは、レビューの指摘から決めた。理由は残っていない。

### 決めたこと

"--help" か "--version" を受けたとき、kotowari はほかの引数を見ず、検査を行わず、使い方か版の文字列を標準出力に出して、終了コード0で終わる。"kotowari --version" のように "check" が無くてもよい。

### 確認すること

- C-core-clienv-1 "kotowari --help" と "kotowari --version" は、"check" が無くても、標準出力に使い方か版を出して終了コード0で終わる
- C-core-clienv-2 "--help" か "--version" があれば、引数の誤り（例えば知らないオプション）が一緒にあっても、終了コード0で終わる

## 対象の OS は Linux と macOS で、Windows ではパスの区切りの正規化だけを約束する

状態: 実装済み

### 問題

どの OS で動くことを約束するかを決める必要がある。理由は残っていない。

### 決めたこと

kotowari は、Linux と macOS を対象にする。Windows では、パスの区切りの "\\" を "/" に直す正規化（[設定ファイルの値のパスは、比べる前と出力の前に正規化する](base-directory.ja.md#設定ファイルの値のパスは比べる前と出力の前に正規化する)）だけを行い、それ以外の動作を約束しない。

### 確認すること

- C-core-clienv-3 （読んで確認）Linux と macOS で `cargo test` が通る

## 読めない入力と壊れた入力は、停止か誤りの指摘にし、黙って読み飛ばさない

状態: 実装済み

### 問題

kotowari を汎用のツールとして提供するには、最低限のレベルを満たしていない、と利用者が判断した。実装のあとで仕様に無い振る舞いを調べると53件あり、その大半は、形の自由度ではなく、契約から外れた入力を黙って通すことから来ていた。黙って飛ばされた入力は、検査したつもりで検査されていない。

### 決めたこと

読めない入力、壊れている入力、契約の形に合わない入力に出会ったとき、kotowari は必ず、停止か、誤りの指摘のどちらかを行う。黙って飛ばす、黙って既定の値にする、黙って最後の指定を採る、黙って片方だけ読む、ことはしない。

どちらにするかは、次のように分ける。

| 入力 | 扱い |
|---|---|
| ファイルや設定を全体として読む前提が崩れる入力（読めない、UTF-8 でない、設定の構文・型・値の誤り、引数の誤り、glob の構文の誤り、変異テストの結果のファイルの誤り、等価の一覧と未記載の面の一覧の構文の誤り） | 停止する |
| 読めたが、局所的に形から外れる入力 | その場所への誤りの指摘を出す |

局所的に形から外れた所のある文書も、文書をまたぐ検査（例えば ID の重複の検査）の対象から外さず、取れた値で検査を続ける。

読まない入力は、除外として列挙したものだけにする（除外の中身は用語集にある）。列挙に無い読み飛ばしは、この決定の違反である。変異テストの結果か等価の一覧の1件が指すファイルが無い、読めない、UTF-8 でないときは、停止せず、誤りか注意の指摘にする（[一覧の1件は、ファイル、変更の説明、行の文面で変異を同定する](equivalents.ja.md#一覧の1件はファイル変更の説明行の文面で変異を同定する)と[文面がソースから無くなった1件には、equivalent_stale の注意を出す](equivalents.ja.md#文面がソースから無くなった1件にはequivalent_stale-の注意を出す)で決める）。

### 確認すること

- C-core-clienv-4 （読んで確認）入力を読むコードに、除外として列挙していない入力を、停止（StopReason）も指摘もせずに読み飛ばす経路が無い
- C-core-clienv-5 置き場の下のファイルやディレクトリが読めないとき、"kotowari check" は読み飛ばさず、unreadable file を理由に停止する
- C-core-clienv-6 局所的に形から外れた所のある文書も、文書をまたぐ検査（例えば ID の重複の検査）を受け、"kotowari check --format json" の出力に、形の誤りと文書をまたぐ誤りの両方が出る

## 停止の理由は、英語の固定の文言で示す

状態: 実装済み

### 問題

停止したとき、何が理由かを標準エラーの1行目で示す。kotowari は汎用のツールとして出すので、出力は英語にする（文書は日本語でよい）。理由を足すときは、ほかの理由に合わせて「〜の誤り」に当たる小文字の英語2語にする。

### 決めたこと

停止するとき、標準エラーの1行目は、次の理由の文言で始まる。

| 理由 | 文言 |
|---|---|
| 設定の誤り | config error |
| 引数の誤り | argument error |
| 読めないファイル | unreadable file |
| UTF-8 でないファイル | non-UTF-8 file |
| 変異テストの結果の誤り（[形の合わない結果のファイルでは、結果の誤りで停止する](mutants-input.ja.md#形の合わない結果のファイルでは結果の誤りで停止する)） | results error |
| 写しの誤り（[kotowari の中の写しの食い違いは、利用者の入力の誤りと分けて mapping error で止める](#kotowari-の中の写しの食い違いは利用者の入力の誤りと分けて-mapping-error-で止める)） | mapping error |
| 全体像の元データの誤り | overview error |
| ポートの誤り | port error |
| 全体像の置き場の誤り | cache error |

全体像の置き場（".kotowari/cache/overview/" とその上）に書けない、消せないときは、読めないファイルと分けて cache error にする。書けないことを読めないことと取り違えないためである。元データの誤り、ポートの誤り、置き場の誤りでいつ止まるかは、[元データか目次に誤りがあれば、何も書かずに overview error で停止する](overview-commands.ja.md#元データか目次に誤りがあれば何も書かずに-overview-error-で停止する)、[overview serve のポートが使えなければ、ほかのポートを試さずに port error で停止する](overview-commands.ja.md#overview-serve-のポートが使えなければほかのポートを試さずに-port-error-で停止する)、[置き場かその上がシンボリックリンクかディレクトリでなければ、何も書かずに cache error で停止する](overview-commands.ja.md#置き場かその上がシンボリックリンクかディレクトリでなければ何も書かずに-cache-error-で停止する)で決める。

### 見送った案

- 全体像の置き場に書けないときも、今ある unreadable file で止める。書けない置き場を読めないファイルとして止めると、読みの失敗と取り違える。

### 確認すること

- C-core-clienv-7 停止するとき、標準エラーの1行目は、表の理由に当たる文言で始まる

## 停止の詳細は、直す人が見るファイルを基準のディレクトリからの相対パスで示す

状態: 実装済み

### 問題

停止の詳細には、直す人が見るべきパスを出したい。壊れているのが設定ファイルから指した別のファイル（等価の一覧、ルールのファイル）なのに設定ファイルのパスを出すと、直す人が見るべきパスにたどり着けない。また、パスだけを出すと、ほかの設定の誤りと同じ形に見え、そのファイルが壊れた設定ファイルのように読める。

### 決めたこと

停止の詳細は英語で書き、パスを含めるときは基準のディレクトリからの相対パスにする。理由ごとの詳細は次のとおりにする。

| 理由 | 詳細 |
|---|---|
| 設定の誤り | 設定ファイルの相対パスと、誤りの説明。壊れているのが、設定ファイルから指した等価の一覧、"tests.rules" のルールのファイル、"surface.rules" のルールのファイルなら、設定ファイルでなく、そのファイルの相対パスと誤りの説明 |
| 引数の誤り | 問題の引数の文字。引数が1つも無いときと、1つ目の位置引数が無いときは "expected command: check, list, mutants, overview, plan, query or status" |
| 読めないファイル | 相対パスと、OS の誤りの文 |
| UTF-8 でないファイル | 相対パス |
| 変異テストの結果の誤り | [形の合わない結果のファイルでは、結果の誤りで停止する](mutants-input.ja.md#形の合わない結果のファイルでは結果の誤りで停止する)で決める |
| 写しの誤り | 写せなかった指摘の種類とノードの名前、または写せなかった値の説明 |

次の場合の詳細は、それぞれの話題で決める。

| 場合 | 決める所 |
|---|---|
| "guides.files" と "tests.files" の置き場の重なり | [ガイドとテストの置き場が重なると、設定の誤りで停止する](guides.ja.md#ガイドとテストの置き場が重なると設定の誤りで停止する) |
| "overview.files" と "guides.files" か "tests.files" の重なり | [全体像の元データがガイドかテストの置き場と重なると、設定の誤りで停止する](overview-data.ja.md#全体像の元データがガイドかテストの置き場と重なると設定の誤りで停止する) |
| "overview" の鍵が無いまま "kotowari overview build" か "kotowari overview serve" を実行したとき | [overview の鍵が無ければ、overview build と overview serve は設定の誤りで停止する](overview-data.ja.md#overview-の鍵が無ければoverview-build-と-overview-serve-は設定の誤りで停止する) |
| 元データの誤り、ポートの誤り、置き場の誤り | [全体像を作るコマンドと見せるコマンド](overview-commands.ja.md) |
| "kotowari query" に渡した ID が無いとき | [位置引数がちょうど1つの ID でないか、その ID が無ければ、引数の誤りで停止する](query.ja.md#位置引数がちょうど1つの-id-でないかその-id-が無ければ引数の誤りで停止する) |
| 未記載の面の一覧が壊れているとき | [未記載の面の一覧](surface-unspecified.ja.md) |

### 確認すること

- C-core-clienv-8 設定の誤りの詳細は、設定ファイルの、カレントディレクトリからでなく基準のディレクトリからの相対パスで始まる
- C-core-clienv-9 等価の一覧か、"tests.rules" か "surface.rules" のルールのファイルが壊れているときの config error の詳細には、設定ファイルでなく、そのファイルの相対パスが出る
- C-core-clienv-10 引数が1つも無いときと、オプションだけでコマンドが無いときは、標準エラーの1行目が "argument error: expected command: check, list, mutants, overview, plan, query or status" になる
- C-core-clienv-11 引数の誤りの詳細に、問題の引数の文字が入る（例えば "--verbose" を付けると、標準エラーの1行目が "argument error: unknown option: --verbose" になる）
- C-core-clienv-12 読めないファイルの詳細は相対パスと OS の誤りの文で、UTF-8 でないファイルの詳細は相対パスである

## kotowari の中の写しの食い違いは、利用者の入力の誤りと分けて mapping error で止める

状態: 実装済み

### 問題

kotowari は、Markdown や YAML の文書の一部を、自分で持つスキーマとエンジンで読み、エンジンが返した値と指摘を kotowari の型と指摘に写す。スキーマは kotowari が自分で持つので、写せないのは利用者の入力の問題ではなく、kotowari の中の食い違いである。利用者が直せない不具合と、利用者が直せる入力の誤りを混ぜたくない。また、写し先の無い指摘を黙って捨てると、将来スキーマに宣言を足したときに、検査が静かに緩む。

### 決めたこと

エンジンから受けた値を kotowari の型へ写せないとき、またはエンジンの指摘に写し先が無いとき、kotowari は停止の理由「写しの誤り」（mapping error）で停止する。詳細は、写せなかった指摘の種類とノードの名前、または写せなかった値の説明にする。理由の名前は、壊れているのがエンジンでも kotowari でもなく、その間の写しであることを指す。詳細に指摘の種類とノードの名前を入れるのは、写しのどこが足りないかを実行時に分かるようにするためである。

スキーマはバイナリに埋め込み、実行時にスキーマのファイルを読まない。そのため、スキーマが読めないことを理由とする停止は持たない。利用者の入力で起きる停止（例えば読めないファイルと UTF-8 でないファイル）の理由と文言は、エンジンで読むかどうかで変えない。

### 確認すること

- C-core-clienv-13 エンジンから受けた値を kotowari の型へ写せないとき、標準エラーの1行目が "mapping error: " で始まり、詳細に写せなかった値の説明が入る
