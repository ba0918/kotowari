# 1件の読み取り

[English](query.md) | 日本語

"kotowari query" が ID を1つ受け、その ID の決定か確認することの行を、[決定と確認することの一覧](list.ja.md)の1件の形に本文を足して出すところを扱う。確認することの ID を渡すと、それを指すテストのファイル・行・名前が返ること自体は、[check は、確認することの行ごとに、それを指すテストがあるかを数える](confirmations.ja.md#check-は確認することの行ごとにそれを指すテストがあるかを数える)で決める。

## query は ID を1つ受け、その ID の決定か確認することの行を、list の1件に本文を足して出す

状態: 実装済み

### 問題

list は全件を1件ずつ出す。さらに詳しい情報を取る置き場として、1件を読むコマンドが要る。LLM が1件を読むとき、文書を開き直さなくて済むようにしたい。それが list に無い query の値打ちである。

query の1件を list の1件に足した形にすれば、query は「list を1件に絞って詳しくしたもの」と読め、鍵の説明が二重にならない。

同じ ID の行が2つ以上あるのは、それ自体が check の誤りである。query がそれを隠す理由は無く、重複を直す人が全部を見られるほうがよい。

### 決めたこと

"kotowari query" は、"kotowari check" と同じ設定と置き場から決定の文書とテストのファイルを読み、位置引数と同じ ID を持つ決定と確認することの行を、すべて "items" に出す。指摘は出さず、終了コードを0にする。決定の文書に check の誤りがあっても、読めた1件は出す。同じ ID の確認することの行が2つ以上あれば、全部出す。

"items" の1件は、[list の1件](list.ja.md#確認することの行にはそれを指すテストを決定には指紋を付ける)と同じ鍵に、本文の行の並び（"body"）を足した形にする。確認することの行の本文は、その行の文字を、折り返した行も含めてそのまま並べたものである。決定を引いたときの本文の範囲は[決定を引いたときの本文は、決定の全体にする](#決定を引いたときの本文は決定の全体にする)で、逆引き（"referenced_by"）は[決定の逆引きには、その決定の見出しへリンクしている決定を入れる](#決定の逆引きにはその決定の見出しへリンクしている決定を入れる)で決める。

### 見送った案

- コマンドの名前を show にする。それまでの決定が、query の名前で語っていた。

### 確認すること

- C-core-query-1 確認することの ID を渡すと、その行が、list の1件と同じ鍵に "body" を足した1件で返り、"body" は行の文字を折り返した行も含めてそのまま並べたものである
- C-core-query-2 決定を指す ID を渡すと、その決定が、list の1件と同じ鍵に "body" を足した1件で返る
- C-core-query-3 同じ ID の確認することの行が2つ以上あれば、"kotowari query" はその全部を返し、終了コードは0である
- C-core-query-4 決定の文書に check の誤りがあっても、"kotowari query" は終了コード0で読めた1件を返し、出力に指摘を出さない

## 決定を引いたときの本文は、決定の全体にする

状態: 実装済み

### 問題

LLM が1件を読むときに文書を開き直さなくて済むことが、list に無い query の値打ちである。この決定の前の query は、決定を引いたとき、その決定の「決めたこと」と「確認すること」の節の行（ガイドの指紋を取る行）だけを "body" に返していた。何を決めたかは読めても、なぜそう決めたか（問題）と、何を退けたか（見送った案）を読むには、文書を開き直すことになる。

### 決めたこと

"kotowari query" で決定を引いたとき、"body" には、その決定の全体（問題、決めたこと、見送った案、確認すること）の行を入れる。

### 確認すること

- C-core-query-14 決定を指す ID を渡すと、"body" に、その決定の問題、決めたこと、見送った案、確認することの節の行が入る

## 決定の逆引きには、その決定の見出しへリンクしている決定を入れる

状態: 実装済み

### 問題

ある決定がどこから指されているかは、1件を読むときに query で引けるようにしていた（逆引き）。逆引きを持つのは query の側だけで、指す側には逆向きの情報を持たせない。新しい形では、決定はほかの決定を見出しへのリンクで指す（[ほかの決定を指すときは、見出しへリンクを張る](decision-documents.ja.md#ほかの決定を指すときは見出しへリンクを張る)）。この決定の前の query は、決定にも確認することの行にも、空の逆引きを返していた。

### 決めたこと

"kotowari query" で決定を引いたとき、"items" の1件の "referenced_by" には、その決定の見出しへリンクを張っている決定を入れる。"referenced_by" の並びは、list の並びと同じく、"path" の昇順、同じ "path" の中は "line" の昇順にする。

### 確認すること

- C-core-query-15 ほかの決定が、引いた決定の見出しへリンクを張っていれば、リンクを張っている決定が "referenced_by" に入り、どの決定からもリンクされていない決定の "referenced_by" は空の並びになる
- C-core-query-16 "referenced_by" の並びは、"path" の昇順、同じ "path" の中は "line" の昇順である

## 位置引数がちょうど1つの ID でないか、その ID が無ければ、引数の誤りで停止する

状態: 実装済み

### 問題

位置引数の数と形の誤りは、"kotowari mutants" の位置引数と同じ止まり方にする。渡した ID がどこにも無いとき、空の "items" と終了コード0を返すより、非0の終了コードと理由が出るほうが、LLM が読んで取り違えない。

### 決めたこと

"kotowari query" で、位置引数がちょうど1つでないとき、位置引数が確認することの ID の形でも決定を指す ID の形でもないとき、または位置引数と同じ ID を持つ決定も確認することの行も無いとき、引数の誤りを理由に停止する。ID を持つものが無いときの詳細は、"unknown id: " に位置引数の文字を続けた形にする。"--help" か "--version" があるときは、[ほかの引数より先に受ける](cli-environment.ja.md#--help-と---version-はほかの引数より先に受け使い方か版を出して終わる)。

ライブラリから呼んだときに、無い ID の失敗からその ID を取り出せることは、[未知の ID の問い合わせの失敗から、その ID を取り出せる](library-api.ja.md#未知の-id-の問い合わせの失敗からその-id-を取り出せる)で決める。

### 確認すること

- C-core-query-5 "kotowari query" に位置引数が無いとき、または2つ以上あるとき、引数の誤りで終了コード2になる
- C-core-query-6 位置引数が ID の形でないとき、"kotowari query" は引数の誤りで終了コード2になる
- C-core-query-7 どの決定の文書にも無い ID を渡すと、"kotowari query" は終了コード2で、標準出力は空、標準エラーの1行目は "argument error: unknown id: " に渡した ID を続けた行である

## query は check と同じ条件で停止し、ガイドと面は読まない

状態: 実装済み

### 問題

query は list と同じく check と同じ読み取りなので、受けるものと止まり方も check と同じにする。query は、ガイドと面を要らない。

全体像の元データも、query には要らない。読むと、全体像の元データの置き場の重なりや読めない元データのファイルで、1件を読むだけの query まで止まる。理由は記録に残っていない。

### 決めたこと

"kotowari query" は、list と同じ4つのオプション（"--format"、"--config"、"--help"、"--version"）だけを受ける。"kotowari check" が停止する条件（設定の誤り、読めないファイル、引数の誤り）が成り立つとき、check と同じ理由と文言で停止する。

ただし "kotowari query" はガイドを読まず、ガイドの置き場と読み込みによる停止はしない。面のファイル、面の規則のファイル、未記載の面の一覧も読まず、その読み込みによる停止はしない。全体像の元データも読まず、その置き場と読み込みによる停止はしない。

### 確認すること

- C-core-query-8 設定ファイルが YAML として読めないとき、"kotowari query" は終了コード2で、標準エラーの1行目が "kotowari check" と同じである
- C-core-query-9 ガイドのファイルが読めなくても、ガイドの置き場がテストのファイルの置き場と重なっていても、"kotowari query" は停止しない
- C-core-query-10 未記載の面の一覧のファイルが無くても、面のファイルが読めなくても、"kotowari query" は停止しない
- C-core-query-13 全体像の元データの置き場がガイドの置き場と重なっていても、元データのファイルが UTF-8 でなくても、"kotowari query" は停止しない

## 出力は json と text の2つにし、text は list の行に本文の行を続ける

状態: 実装済み

### 問題

list の "text" の上に足す形なら、読み方が1つ増えない。本文は文書の生の行なので、字下げだけで区別できる。

kotowari が決める固定の語は、停止の文言（[停止の理由は、英語の固定の文言で示す](cli-environment.ja.md#停止の理由は英語の固定の文言で示す)）と JSON の鍵が英語なので、それに揃える。

### 決めたこと

"kotowari query" の "--format" は "json" と "text" の2つだけを受け、既定を "json" にする。"json" では、最上位が "items" だけの JSON を1つ出す。

"text" では、1件ごとに、[list の "text"](list.ja.md#出力は-json-と-text-の2つにし絞り込みのオプションは持たない) と同じ1行目とテストの行を出し、そのあとに "body" の各行を2つの半角空白で字下げして出す。

出力のうち kotowari が決める固定の語は英語にする。決定の文書やテストから写す文字は、そのまま出す。

### 確認すること

- C-core-query-11 "json" の出力の最上位の鍵は "items" だけである
- C-core-query-12 "text" では、list の "text" と同じ1行目とテストの行のあとに、"body" の各行を2つの半角空白で字下げして出す
