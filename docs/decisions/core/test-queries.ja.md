# 同梱の問い合わせ

[English](test-queries.md) | 日本語

kotowari が言語ごとに同梱する問い合わせと、それぞれの言語で何をテストと数えるかを扱う。問い合わせをファイルにどう当て、テストの名前をどう取るかは[テストの見つけ方](test-discovery.ja.md)、設定で問い合わせを足す形は[設定で足す問い合わせ](query-rules.ja.md)で決める。見つけたテストにマーカーをどう結び付けるかは[マーカーは、テストの直前のコメントの塊にあるものだけをそのテストに結び付ける](test-markers.ja.md#マーカーはテストの直前のコメントの塊にあるものだけをそのテストに結び付ける)で、指摘の行の数え方は[line は1始まりで数え、文書全体にかかる指摘は null にする](finding-order.ja.md#line-は1始まりで数え文書全体にかかる指摘は-null-にする)で決める。

## 問い合わせを同梱するのは、利用者が使う4つの言語の系統だけにする

状態: 実装済み

### 問題

kotowari は多くの言語の文法を持つが、何をテストと数えるかの既定は言語ごとに決める必要がある。既定には「確実なものだけ既定にする」という方針が当たり、言語ごとに何が確実かを決める壁打ちと、仕様と、テストが要る。

### 決めたこと

kotowari は、Rust、TypeScript、Tsx、JavaScript、Python、Php の問い合わせを同梱する。利用者が使う言語に絞った。ほかの言語は、使う人が設定でルールを足す（[設定の tests.rules で問い合わせを足し、同梱の問い合わせは外せない](query-rules.ja.md#設定の-testsrules-で問い合わせを足し同梱の問い合わせは外せない)）。既定を増やすのは、後から言語ごとに決める。

TypeScript と Tsx は別の言語なので、同じ中身の問い合わせを両方に同梱する。

### 確認すること

- C-core-queries-1 Rust、TypeScript、Tsx、JavaScript、Python、Php の拡張子のファイルは、設定でルールを足さなくても問い合わせのある言語になり、".go" のファイルはならない
- C-core-queries-2 ".tsx" のファイルの "it(...)" が、同梱の問い合わせでテストと数えられる
- C-core-queries-3 ".js"、".jsx"、".mjs"、".cjs" のファイルの "it(...)" が、同梱の問い合わせでテストと数えられる

## Rust では、属性のパスの末尾が test の関数を必ず数え、属性とマクロを設定で足す

状態: 実装済み

### 問題

Rust で何をテストと数えるかは、採用しているライブラリで変わるので断言できず、常に「このプロジェクトでは」の但し書きが付く。"#[test]" だけは確実である、と利用者が判断した。kotowari 自身も "kani::proof" の属性と "proptest" のマクロのテストを持つ。

### 決めたこと

同梱の問い合わせは "#[test]" の付いた関数を確実な既定とし、それ以外の属性とマクロは、プロジェクトごとに設定の "tests.rust.attributes" と "tests.rust.macros" に書き足す。どちらも既存の設定を壊さないよう、設定の形を変えずに残す。

| 対象 | 数え方 |
|---|---|
| 属性のパスの末尾の要素が "test" の関数（"#[test]"、"#[ test ]"、"#[core::prelude::v1::test]"、"#[tokio::test]"） | 同梱の問い合わせに固定し、設定によらず常に数える |
| "tests.rust.attributes" の属性の付いた関数 | 属性から "#["、"]"、引数を除いたパスが完全一致すれば数える（"kani::proof" は "#[kani::proof(unwind = 3)]" にも当たる） |
| "tests.rust.macros" のマクロ | 設定には "!" を除いた名前で書く。マクロの名前の末尾の要素が一致すれば（"proptest::proptest!" も "proptest" に当たる）、中身を Rust の項目として読み直し、その中の最上位の関数ごとに数える。名前は関数の名前 |
| 上の行の関数とマクロが、ほかの関数の本体の中にあるとき | 置き場所によらず数える |

マクロの中の関数のマーカーは、マクロの外と同じ規則で結び付ける（[マーカーは、テストの直前のコメントの塊にあるものだけをそのテストに結び付ける](test-markers.ja.md#マーカーはテストの直前のコメントの塊にあるものだけをそのテストに結び付ける)）。

### 確認すること

- C-core-queries-4 属性のパスの末尾の要素が "test" の関数（"#[test]"、"#[ test ]"、"#[tokio::test]"）は、設定が無くてもテストと数え、関係の無い属性だけの関数は数えない
- C-core-queries-5 "tests.rust.attributes" の属性は、"#["、"]"、引数を除いたパスが完全一致すれば数え、その属性が無い関数は数えない
- C-core-queries-6 関数の本体の中にある、"#[test]" の付いた関数もテストと数える
- C-core-queries-7 "tests.rust.macros" のマクロは名前の末尾の要素で当て、中身の関数をそれぞれ関数の名前で数える。設定に無いマクロの中身と、マクロの中の関数のさらに中にある関数は数えない

## TypeScript と JavaScript では、it と test の呼び出しを数える

状態: 実装済み

### 問題

TypeScript、Tsx、JavaScript には、テストを書くライブラリが多くある。どのライブラリでも共通で確実な形を既定にする必要がある。

### 決めたこと

TypeScript、Tsx、JavaScript に共通で、次のとおり数える。主なライブラリで "it" と "test" は共通で確実で、skip したテストもテストの定義である、と利用者が判断した。

| 対象 | 数え方 |
|---|---|
| 呼ぶ側が "it" か "test" の呼び出し（"it(...)"、"test(...)"） | 数える。名前は最初の引数 |
| 呼ぶ側が "it" か "test" に "." と名前が1つ以上続く形の呼び出し（"it.only(...)"、"it.skip(...)"、"it.todo(...)"、"test.concurrent(...)"、"it.only.each(...)"） | 数える。名前は最初の引数。ただし次の行の内側の呼び出しは除く |
| 上の形のうち最後の要素が "each" の呼び出しの結果をさらに呼ぶ形（"it.each(表)(名前, 関数)"、"test.concurrent.each(表)(名前, 関数)"） | 外側の呼び出しだけを数える。名前は外側の最初の引数。内側の "it.each(表)" を数えると、1つのテストを2つに数えてしまう |
| "describe(...)" と、その "." の形 | 数えない。中の呼び出しは上の行のとおり数える |
| 呼ぶ側が "it"、"test" でない呼び出し（"regex.test(s)"） | 数えない |

名前の引用符の外し方と、"describe" の名前を付けないことは、[テストの名前は、問い合わせが捕まえた文字から取る](test-discovery.ja.md#テストの名前は問い合わせが捕まえた文字から取る)で決める。

### 確認すること

- C-core-queries-8 "it(...)"、"test(...)" と、"." と名前が続く形（"it.only"、"it.skip"、"it.todo"、"test.concurrent"）の呼び出しを数え、名前は最初の引数になる
- C-core-queries-9 "it.each(表)(名前, 関数)" と "it.only.each(表)(名前, 関数)" は、外側の呼び出しの1つだけを数える
- C-core-queries-10 "describe(...)" と、呼ぶ側が "it"、"test" でない呼び出し（"regex.test(s)"）は数えない

## Python では、名前が test で始まる関数とメソッドを数える

状態: 実装済み

### 問題

Python のテストは、"test" で始まるファイルの最上位の関数と、クラスの中の "test" で始まるメソッドの2通りで書かれる。主なテストのライブラリの既定の探し方の両方を拾える既定が要る。

### 決めたこと

| 対象 | 数え方 |
|---|---|
| 名前が "test" で始まる、ファイルの最上位の関数 | 数える。名前は関数の名前 |
| 名前が "test" で始まる、クラスの中のメソッド | 数える。名前はメソッドの名前 |
| 上の関数とメソッドにデコレータが付いたもの | 数える |
| 関数の中に入れ子になった関数 | 数えない |

### 確認すること

- C-core-queries-11 名前が "test" で始まる、ファイルの最上位の関数とクラスの中のメソッドを数え、関数の中に入れ子になった関数は数えない
- C-core-queries-12 デコレータの付いた、名前が "test" で始まる関数とメソッドも数える

## Php では、メソッドと test の呼び出しを数える

状態: 実装済み

### 問題

Php のテストは、"test" で始まるメソッド、"Test" の属性、docblock の "@test"、Pest の関数の呼び出しのいずれかで書かれる。docblock の "@test" は主なテストのライブラリの新しい版で無くなったが、書いてあるコードは多い。

### 決めたこと

| 対象 | 数え方 |
|---|---|
| 名前が "test" で始まるメソッド | 数える。名前はメソッドの名前 |
| パスの最後の要素が "Test" の属性の付いたメソッド（"#[Test]"、"#[\PHPUnit\Framework\Attributes\Test]"） | 数える。名前はメソッドの名前 |
| 直前の "/**" で始まるコメントに "@test" のあるメソッド | 数える。名前はメソッドの名前 |
| 呼ぶ側が "test" か "it" の関数の呼び出し（Pest の "test('...', fn)"） | 数える。名前は最初の引数。テストのファイルで "test('...', fn)" を呼んでいれば Pest でほぼ確実 |

### 確認すること

- C-core-queries-13 名前が "test" で始まるメソッドと、パスの最後の要素が "Test" の属性（"#[Test]"、"#[\PHPUnit\Framework\Attributes\Test]"）の付いたメソッドを数え、ほかの属性だけのメソッドは数えない
- C-core-queries-14 直前の "/**" で始まるコメントに "@test" のあるメソッドを数え、"/*" のコメントや "@testdox" だけのメソッドは数えない
- C-core-queries-15 呼ぶ側が "test" か "it" の関数の呼び出しを数え、名前は最初の引数になる。"describe" の呼び出しは数えない
