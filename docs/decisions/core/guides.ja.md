# ガイドのマーカー

[English](guides.md) | 日本語

ガイド（製品を使う人が読む、使い方の文書）の置き場と読み方、ガイドのマーカーの形と指紋、古くなった節の見つけ方を扱う。ガイドは仕様を読んで人か LLM が書く文書で、kotowari は仕様から生成しない。マーカーが指す決定のどこが変わったら古いとするかは、[ガイドは、決めたことと確認することが変わったら古いとする](languages-and-guides.ja.md#ガイドは決めたことと確認することが変わったら古いとする)で決める。check の JSON と status に出す "guides" の群は、[check の JSON の最上位には、指摘と種類ごとの数と、読んだものの数を出す](output.ja.md#check-の-json-の最上位には指摘と種類ごとの数と読んだものの数を出す)と[集計は、テストのマーカー、ガイド、全体像、面、指摘の数を群ごとに出す](status.ja.md#集計はテストのマーカーガイド全体像面指摘の数を群ごとに出す)で決める。

## 古い節は、マーカーに書いた指紋を今の決定の指紋と照らして見つける

状態: 実装済み

### 問題

仕様を直すたびにガイド全体を見直すと、手間が大きい。見直すべき節だけを機械で絞り込みたい。仕様を変えた変更の中だけで絞る形では、その変更でガイドを直し忘れると、あとから気づく手段が無い。

### 決めたこと

ガイドの節に、その節が説明している決定と、書いたときのその決定の指紋を、マーカーとして書く。check は、書かれた指紋を今の決定の指紋と照らし、古い節がある間は指摘を出し続ける。仕様を変えた時点に限らず、いつでも絞り込める。手順の順守を当てにせず機械で確かめる、という kotowari の方針と揃う。

指紋は、kotowari list と kotowari query の1件の "fingerprint" に出し、見直した人か LLM がマーカーに書き写す。kotowari はガイドを書き換えない。書き写しにすれば、kotowari がファイルを書くコマンドを持たずに済む。kotowari list は決定ごとに1件を出し、その "id" がマーカーに書く行き先になる。kotowari query にその行き先を渡すと、その決定の指紋が返る。

指紋は、指紋を取る行を "\n" でつないだ文字列の SHA-256 を、16進の小文字で書いた先頭の8文字とする。行の終わりの文字（"\r\n" の "\r" を含む）は行に入れない。アルゴリズムを決めておかないと、Rust の版を上げただけで値が変わりうる。8文字は書き写しやすさを優先した長さで、1つのプロジェクトの数百件では偶然の一致を気にしなくてよい。行の終わりの文字を入れると、checkout の改行の形で、同じ内容の指紋が変わる。

### 見送った案

- 指紋を持たず、仕様を変えた変更の差分から、直した項目を取って絞る。直し忘れが残る。

### 確認すること

- C-core-guides-1 kotowari query に決定への行き先を渡すと、kind が "decision" の1件が返り、"fingerprint" にその決定の指紋が出る
- C-core-guides-2 kotowari list が、決定ごとに、マーカーに書く行き先を id にした1件を出す
- C-core-guides-3 kotowari list か kotowari query の指紋を書き写したマーカーには、check が guide_stale を出さない
- C-core-guides-4 改行が "\r\n" の決定の文書と "\n" の決定の文書で、同じ内容の決定の指紋が同じになる

## ガイドは guides.files の glob で選び、check と status だけが読む

状態: 実装済み

### 問題

ガイドを持たないプロジェクトもある。ガイドの置き場の書き方がテストの置き場と違うと、覚えることが増える。置き場ごとに読み方の規則が違うと、覚えにくい。

### 決めたこと

設定の "guides.files" に glob の一覧を書き、当たるファイルをガイドとして読む。書き方は "tests.files" と同じにする。鍵が無いか空の一覧なら、ガイドを1つも読まず、ガイドの検査は何もしない。ガイドを持たないプロジェクトに影響しない。

ガイドのファイルの読み方の失敗は、"tests.files" と同じに扱う（[テストのファイルは tests.files の glob で選ぶ](test-discovery.ja.md#テストのファイルは-testsfiles-の-glob-で選ぶ)）。glob として読めない要素は設定の誤り、読めないファイル・UTF-8 でないファイル・先の無いシンボリックリンクは停止で、何にも当たらない glob は誤りにしない。

"guides.files" の glob が決定の文書の置き場のファイルに当たっても、停止しない。そのファイルを、決定の文書としてもガイドとしても読む。テストの置き場との重なりを止める理由（[ガイドとテストの置き場が重なると、設定の誤りで停止する](#ガイドとテストの置き場が重なると設定の誤りで停止する)）が、決定の文書には無く、両方として読んでも害が無いからである。

ガイドを読むのは check と status だけにする。status は check と同じ検査をするからである。kotowari list と kotowari query はガイドを読まず、ガイドの置き場と読み込みでは停止しない。list の指紋は決定の文書だけから決まり、ガイドは要らない。

### 確認すること

- C-core-guides-5 設定に "guides.files" の鍵が無いと、check はガイドを1つも読まず、マーカーを書いたファイルがあっても guide_stale を出さない
- C-core-guides-6 "guides.files" に当たるファイルが UTF-8 でないか読めないと、check は停止する
- C-core-guides-7 "guides.files" の glob が決定の文書の置き場のファイルに当たっても check は停止せず、そのファイルは決定の文書としても、ガイドとしても数えられる
- C-core-guides-8 kotowari list と kotowari query は、"guides.files" に当たるファイルが UTF-8 でなくても停止しない

## ガイドとテストの置き場が重なると、設定の誤りで停止する

状態: 実装済み

### 問題

問い合わせの無い言語のテストのファイルでは、ファイルの中の "@kotowari[" をすべてマーカーとして拾う（[問い合わせの無い言語のファイルでは、ファイルの中のマーカーをすべて拾う](test-markers.ja.md#問い合わせの無い言語のファイルではファイルの中のマーカーをすべて拾う)）。ガイドがテストのファイルにも当たると、ガイドのマーカーがテストのマーカーとして読まれる。どちらか片方を黙って優先しない（[読めない入力と壊れた入力は、停止か誤りの指摘にし、黙って読み飛ばさない](cli-environment.ja.md#読めない入力と壊れた入力は停止か誤りの指摘にし黙って読み飛ばさない)）。

言語が2つ以上のときは、"guides.files" の glob に当たらなくても、当たったファイルと同じ対にあるためにガイドとして読む側がある。その側もテストのファイルに当たれば、ガイドとしてもテストとしても読まれ、ガイドのマーカーがテストのマーカーとして黙って数えられる。また、glob に当たった側を、先頭の言語の側が無いことを理由に重なりの判定から外すと、glob の重なりという設定の誤りが、対の側が無いという誤りの陰に隠れる。

### 決めたこと

1つのファイルが "guides.files" と "tests.files" の両方の glob に当たるとき、check と status は設定の誤りを理由に停止する。

言語が2つ以上のとき、重なりを見るガイドには、"guides.files" の glob に当たったファイルに加えて、当たったファイルと同じ対にあるためにガイドとして読む側（glob に当たらなくても）を数える（対の側の見分け方は[対の側は、ファイル名と設定だけで見分ける](translation-pairs.ja.md#対の側はファイル名と設定だけで見分ける)で決める）。glob に当たったファイルは、先頭の言語の側が無くても数える。

停止の詳細は、重なったファイルの基準のディレクトリからの相対パスに ": matched by both guides.files and tests.files" を続けた文字列にする。相対パスだけだと、ほかの設定の誤り（設定ファイルのパスと説明）と同じ形に見え、そのファイルが壊れた設定ファイルのように読めるからである。重なったファイルが2つ以上あれば、パスのバイト順で最初の1つだけを出す。停止の詳細は1行で、直して実行し直せば次が出る。

### 確認すること

- C-core-guides-9 1つのファイルが "guides.files" と "tests.files" の両方に当たると、check と status は終了コード2で停止し、停止の詳細はそのファイルの相対パスに ": matched by both guides.files and tests.files" を続けたものになる
- C-core-guides-10 重なったファイルが2つあると、停止の詳細には、パスのバイト順で先の1つだけが出る
- C-core-guides-23 言語が2つ以上のとき、"guides.files" に当たったガイドと同じ対にある側が、"guides.files" に当たらなくても "tests.files" に当たれば、check はその側の相対パスで同じ停止をする
- C-core-guides-24 言語が2つ以上のとき、先頭の言語の側が無い側が "guides.files"、"tests.files"、"overview.files" の3つに当たると、check と status はその側の相対パスに ": matched by both guides.files and tests.files" を続けた詳細で停止する

## ガイドのマーカーは、HTML のコメントの中だけから読む

状態: 実装済み

### 問題

マーカーが描画したガイドに出ると、読者が戸惑う。HTML のコメントは描画したガイドに出ない。一方で、マーカーの書き方を説明するガイドは、例をコードブロックに書く。ファイルの中の "@kotowari[" をすべて拾うと、例がマーカーとして読まれる。

また、CommonMark の HTML ブロックは "-->" を含む行の終わりまで続くので、ブロック単位で判定すると、コメントの外の文字まで読む。

### 決めたこと

ガイドのマーカーは、HTML のコメントの中に、テストのマーカーと同じ "@kotowari[" で始まる形で書く。テストのマーカーと見た目が揃う。

check はガイドを CommonMark として読み、"<!--" から "-->" までの中にある "@kotowari[" だけをマーカーとして読む。CommonMark のコードブロック（字下げの形とフェンスの形）とコードスパンの中、および "-->" より後ろの文字（"<!--" で始まる HTML ブロックの、同じ行の残りを含む）にある "@kotowari[" は読まない。

### 確認すること

- C-core-guides-11 段落の中の HTML のコメントと、行をまたぐ HTML のコメントの中のマーカーを、check が読む
- C-core-guides-12 コードブロック（字下げの形とフェンスの形）の中、コードスパンの中、コメントの外の本文にある "@kotowari[" は、check がマーカーとして読まず、invalid_marker も guide_stale も出さない
- C-core-guides-13 "-->" より後ろにある "@kotowari[" は、同じ行にあっても、check がマーカーとして読まない

## ガイドのマーカーの1件は、決定への行き先と指紋をコロンでつなぐ

状態: 実装済み

### 問題

1つの節が複数の決定を説明することがある。どの決定が変わったかを分かるようにしたい。また、括弧の内側やコロンの前後に空白があるだけで誤りにする理由は無い。一方で、形そのものが壊れているのは書き間違いなので、黙って飛ばさずに止めたい。テストのマーカーも、形の誤りを誤りにしている。

### 決めたこと

ガイドのマーカーは、決定の文書の決定を指す。形は次の表のとおりにする。1件ごとに指紋を持つので、どの決定が変わったかが分かる。

| 部分 | 形 |
|---|---|
| 始まり | @kotowari[ |
| 中身 | 1件を "<行き先>:<指紋>" の形で書き、コンマで区切って並べる。1件の前後、行き先の前後、指紋の前後に空白を置いてよい。同じ行き先の1件が2つ以上あっても、1件ずつ扱う |
| 行き先 | 決定の文書のパスと、その決定の見出しへのリンクの行き先の名前を "#" でつないだもの（"<文書のパス>#<見出しの行き先の名前>"） |
| 指紋 | 16進の小文字（"0" から "9" と "a" から "f"）の8文字 |
| 終わり | 始まりと同じ行の "]" |

見出しの行き先の名前は、決定の文書の中で見出しへリンクを張るときと同じ規則で作る（[ほかの決定を指すときは、見出しへリンクを張る](decision-documents.ja.md#ほかの決定を指すときは見出しへリンクを張る)）。

マーカーの形が誤っているとき（中が空か区切りだけ、同じ行に "]" が無い、":" の無い1件がある、":" の前が行き先の形でない、":" の後が指紋の形でない）は、check が invalid_marker の誤りを出す。行き先の形は正しいが、その決定が今は無いだけなら、形の誤りでなく古いマーカーとして扱う（[古いマーカーは guide_stale の注意にし、終了コードと complete を変えない](#古いマーカーは-guide_stale-の注意にし終了コードと-complete-を変えない)）。

### 確認すること

- C-core-guides-14 括弧の内側、":" の前後に空白のあるマーカーを、check が空白の無いものと同じに読む
- C-core-guides-15 指紋の無い1件、大文字の指紋、":" の前が行き先の形でない1件（例: パスか見出しの行き先の名前が無いもの）を持つマーカーには、check が invalid_marker の誤りを出す
- C-core-guides-16 中が空か区切りだけのマーカーと、同じ行に "]" の無いマーカーには、check が invalid_marker の誤りを出す
- C-core-guides-17 1つのマーカーに並べた2件を、check が1件ずつ照らし、指紋の違う1件だけに guide_stale を出す

## 古いマーカーは guide_stale の注意にし、終了コードと complete を変えない

状態: 実装済み

### 問題

ガイドが遅れているだけで CI が落ちるのは困る。一方で、放置されたガイドがいつでも見えるようにしたい。また、仕様から決定を消したなら、それを説明していた節は古い。

### 決めたこと

形の正しいマーカーの1件について、行き先の決定が無いとき、または行き先の決定の今の指紋が1件に書かれた指紋と違うとき、check はその1件ごとに guide_stale の注意を出す。指摘はマーカーの行を指す。kotowari はマーカーが受け持つ範囲（節）を決めない。

guide_stale の detail は、行き先、1件に書かれた指紋、今の指紋を、空白で区切った文字列にする。行き先の決定が無いときの今の指紋は "-" にする。注意の1行だけで、どの行き先を何に書き換えるかまで分かる。

注意なので、終了コードと status の complete を変えない。complete を決めるものを変えずに保つ。注意は check と status の数に残り続けるので、放置されたガイドはいつでも見える。

### 見送った案

- 古いマーカーを誤りにする。ガイドが遅れているだけで CI が落ちる。
- 行き先の決定が無いマーカーを、テストのマーカーと同じ unresolved_reference の誤りにする。仕様から決定を消しただけで CI が落ち、古いマーカーを注意にしたことと食い違う。

### 確認すること

- C-core-guides-18 指紋が今の決定と違う1件には、マーカーの行に guide_stale の注意が1件出て、detail は行き先、書かれた指紋、今の指紋の順になる
- C-core-guides-19 無い文書、無い見出し、決定でない見出し（題名、節）を指す1件には、今の指紋を "-" にした guide_stale の注意が出て、unresolved_reference は出ない
- C-core-guides-20 ほかに誤りが無く guide_stale だけがあるとき、check の終了コードは0で、status の complete は true のままになる

## ガイドを書く場面と見直す場面を、kotowari の skill に置く

状態: 実装済み

### 問題

マーカーの細かさは、機械で止めるほどの問題ではない。試作では、症状ひとつの節は1つのマーカーに1〜4件で回り、横断する節では7〜11件に膨らんだ。細かく割るのは書き方の問題である。ガイドの文章がどの決定を説明しているかは、機械には判定できないので、マーカーの付け忘れは kotowari では見つけられない。見直しの手順は、マーカーの属する節を読むことなので、マーカーと節の結び付きを書き方で決めておかないと、見直す範囲が決まらない。

### 決めたこと

kotowari は、マーカーが受け持つ範囲、マーカーの細かさ、マーカーの置き場、マーカーの付け忘れを検査しない。代わりに、kotowari の skill に、ガイドを書く場面と見直す場面を置き、次の決まりと手順を書く。

- マーカーは、それが受け持つ節の見出しの隣に1つ置く
- 1つのマーカーの件数は数個までを目安にし、それより多くなる節は分ける
- 書くときと見直すときに、節の内容に対応する決定を kotowari query で確かめて、マーカーに足す
- guide_stale の detail の今の指紋をマーカーに書き写す前に、その節を見直す

### 確認すること

- C-core-guides-21 （読んで確認）kotowari の skill に、ガイドを書く場面と見直す場面があり、マーカーを受け持つ節の見出しの隣に1つ置くこと、1つのマーカーの件数を数個までの目安にすることが書いてある
- C-core-guides-22 （読んで確認）kotowari の skill に、節の内容に対応する決定を kotowari query で確かめてマーカーに足す手順と、guide_stale の今の指紋を書き写す前に節を見直す手順が書いてある
