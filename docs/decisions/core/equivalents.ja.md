# 等価の一覧

[English](equivalents.md) | 日本語

等価の一覧の置き場と形、変異の結果との一致の取り方、一覧の1件への指摘を扱う。等価は、変異を入れても利用者から観測できる振る舞い（出力と終了コード）が変わらない、という人か LLM の判断である。見逃しと時間切れの指摘と集計は[変異の結果の検査](mutants.ja.md)で、結果のファイルの読み取りは[変異テストの結果の読み取り](mutants-input.ja.md)で決める。パスの正規化は[設定ファイルの値のパスは、比べる前と出力の前に正規化する](base-directory.ja.md#設定ファイルの値のパスは比べる前と出力の前に正規化する)で、設定の鍵の値の検査は[設定ファイルが YAML として読めないか、キーと値が決まりに合わなければ、設定の誤りで停止する](config.ja.md#設定ファイルが-yaml-として読めないかキーと値が決まりに合わなければ設定の誤りで停止する)で決める。

## 等価の判断は、設定の mutants.equivalents が指す YAML の一覧に置く

状態: 実装済み

### 問題

変異テストの見逃しには、変異を入れても振る舞いが変わらないもの（等価）がある。その判断と理由をどこに残すかを決める必要があった。

cargo-mutants の除外の設定（.cargo/mutants.toml）に置くと、除外した変異は測られず、理由はコメントで誰も検査しない。道具の設定に判断を置くと、道具を替えたときに失う。一覧は数十から百件の機械的な一覧で、人が読む決定の文書とは性質が違う。

一覧が無いか壊れているせいで普段の check が止まるのは、責務が混ざっている。壊れているのは一覧のファイルなので、直す人が見るべきパスはそちらである。

### 決めたこと

等価と判断した見逃しは、kotowari の側のファイル1つに、変異と分類と理由の一覧で持つ。変異テストは除外なしで走らせ、kotowari が一覧に載った見逃しを指摘から外す。

一覧の置き場は、設定の鍵 "mutants.equivalents" で指す。値は一覧のファイルのパス（1つの文字列、基準のディレクトリからの相対）で、既定は無い。一覧は YAML の並びである。

| 一覧のファイルの状態 | "kotowari mutants" の振る舞い |
|---|---|
| 設定に "mutants.equivalents" の鍵が無い | 一覧を0件として続ける |
| 指す先が空（0バイトか注釈だけ） | 一覧を0件として続ける。設定ファイルが空のときの扱いに揃える |
| 指す先が無いか読めない | 読めないファイルを理由に停止する |
| 指す先が UTF-8 でない | UTF-8 でないファイルを理由に停止する |
| YAML として読めないか、最上位が並びでない | 設定の誤りを理由に停止し、詳細に一覧のファイルの相対パスと誤りの説明を出す |

"kotowari check" は、鍵の値の型を見るだけで、指す先のファイルを読まず、有無も見ない。

### 見送った案

- .cargo/mutants.toml の除外の設定と、理由のコメントに置く。除外した変異は測られず、理由は誰も検査せず、道具を替えると失う。
- 人が読む判断の文書（Markdown）に混ぜる。数十から百件の機械的な一覧で、人が読む文書とは性質が違う。

### 確認すること

- C-core-equiv-1 設定に "mutants.equivalents" の鍵が無いとき、または指す先が0バイトか注釈だけ（注釈の間の空行を含む）のとき、"kotowari mutants" は一覧を0件として続ける
- C-core-equiv-2 "mutants.equivalents" の指す先が無いと、終了コード2で停止し、標準エラーの1行目が "unreadable file: " と一覧のファイルのパスで始まる
- C-core-equiv-3 一覧の最上位が並びでないと、終了コード2で停止し、標準エラーの1行目が "config error: " と一覧のファイルの相対パスで始まる
- C-core-equiv-4 "mutants.equivalents" の指す先が無くても、"kotowari check" は停止しない

## 一覧の1件は、ファイル、変更の説明、行の文面で変異を同定する

状態: 実装済み

### 問題

行番号は、コードを直すたびにずれる。行番号を外した名前は重なる（変異804件のうち382件が、ほかと重なっていた）。行の文面で取れば、行が動いただけでは外れず、その行を書き換えたときだけ外れて、判断のし直しに倒れる。

結果を取ったあとにソースを変えると、結果が指すファイルが無い、または行がファイルの行数を超える、ということが起きる。このときは一致しない側に倒すのが安全である。見逃しは誤りとして出て、一覧の側は注意が出るので、黙って飛ばすことにはならない。

### 決めたこと

一覧の1件は、"file"（ソースのパス）、"change"（変更の説明）、"text"（変異が入る行の元の文面）、"class"（分類）、"why"（理由）を持つ。行の文面の鍵を line にしないのは、行番号と紛らわしいためである。

結果が「見逃した」の変異の結果と、形の正しい1件は、次の3つがすべて成り立つときに一致する。

- "file" に正規化を掛けたものが、変異の結果のファイルと同じ文字列である
- "change" が、変更の説明と同じ文字列である
- "text" が、変異の結果のファイルの今の内容のその行の文面と、どちらも前後の半角空白とタブを除いて同じ文字列である

除く空白は半角空白とタブの2つだけで、全角空白は文面の一部として残す。書き換えの検出として安全なためである。行の区切りは、kotowari がほかのファイルの行を数えるときと同じで（[kotowari は、"\n"、"\r\n"、単独の "\r" を、それぞれ1つの行の終わりに数える](ir-document.ja.md#kotowari-はnrn単独の-r-をそれぞれ1つの行の終わりに数える)）、行の終わりの "\r\n" の "\r" は文面に含めない。"file" の正規化は、書き方の違いだけで一致が外れないようにするためで、比べるときにだけ掛ける。

同じファイルに同じ文面の行が複数あり、同じ変更が入るときは、1件がどの行の見逃しにも一致する。

一致した見逃しは指摘にせず、集計の survived に数えず equivalent に数える。一覧で外せるのは見逃しだけである。

変異の結果のファイルが無い、読めない、UTF-8 でない、または行がそのファイルの行数を超えるときは、停止しない。その変異の結果はどの1件にも一致せず、見逃しなら結果の行のまま mutant_survived を出す。

### 見送った案

- 行番号で同定する。直すたびにずれる。
- ファイルと関数と変更の説明だけで同定する。名前が重なる。

### 確認すること

- C-core-equiv-5 一覧の1件に一致する見逃しには mutant_survived が出ず、集計の survived に数えられず equivalent に数えられる
- C-core-equiv-6 文面の行が動いただけなら一致したままで、その行の文面を書き換えると一致しなくなり mutant_survived が出る
- C-core-equiv-7 "file" が違う1件は、同じ行に同じ文面があっても一致しない
- C-core-equiv-8 "file" を "./src/a.rs" と書いた1件でも、ソースの字下げがタブでも、行の終わりに "\r" があっても一致する
- C-core-equiv-9 同じ文面の行が2つあり、両方の行に同じ変更の見逃しがあれば、1件がどちらにも一致し、equivalent は2になる
- C-core-equiv-10 見逃しの行がファイルの行数を超えるとき、またはファイルが UTF-8 でないときは、停止せず、一致しないので mutant_survived が出る

## 文面がソースから無くなった1件には、equivalent_stale の注意を出す

状態: 実装済み

### 問題

一覧の1件が古くなったことを知らせたい。変異テストを差分だけで走らせると、結果に入るのは一部の変異だけになる。結果に現れるかどうかで古さを判定すると、一覧のほとんどが誤って古いと言われる。ソースに対して判定すれば、結果が全体でも一部でも同じに動き、道具にも依存しない。

指摘を見た人や LLM は、detail の文字列で一覧のファイルを検索して、該当の1件を探す。

### 決めたこと

形の正しい1件の "text" と、前後の半角空白とタブを除いて同じ文面の行が、"file" のファイルに1つも無いとき、その1件に equivalent_stale の注意を出す。ファイルが無い、読めない、UTF-8 でないときも、文面が無いものとして出す。結果のファイルにその変異が現れるかは見ない。注意なので終了コードは変えない。

equivalent_stale の指摘は、path が一覧のファイル、line が無し（null）、detail が一覧に書かれたままの "file" と "change" を ": " でつないだ文字列である。正規化は掛けない。

### 見送った案

- 以前の決定: 一覧にあって結果に現れない1件に注意を出す。差分だけの実走では結果が一部で、誤って古いと言われるので、ソースに対して判定することにした。

### 確認すること

- C-core-equiv-11 1件の "text" の行が "file" のファイルのどこにも無いと、path が一覧のファイル、line が null、detail が書かれたままの "file" と "change" を ": " でつないだ equivalent_stale の注意が出る（"./src/a.rs" と書いた1件では、detail も "./src/a.rs" で始まる）
- C-core-equiv-12 "file" のファイルが UTF-8 でないと、その1件に equivalent_stale の注意が出る
- C-core-equiv-13 1件の文面がソースにあれば、その1件がどの見逃しにも一致しなくても、equivalent_stale は出ない

## 形の誤った1件は equivalent_invalid の誤りにし、どの見逃しも外さない

状態: 実装済み

### 問題

形のおかしい1件に、指摘を黙らせる力を与えたくない。形の崩れ方で扱いを分けると、黙って読み飛ばす口ができる。

見逃しを調べるときは、「等価」（変異しても振る舞いが変わらない）、「未検査」（テストが見ていない）、「欠陥の疑い」（元のコードがおかしい）の3つに分ける。直すべき状態を一覧で黙らせられると、一覧が先送りの置き場になる。見逃しを抱えたまま出すかは、人が件数と中身を見て決める。

### 決めたこと

一覧の1件が次のどれかに当たるとき、その1件に equivalent_invalid の誤りを出し、その1件はどの変異の結果とも一致させない。

- 鍵と値の組でない
- "file"、"change"、"text"、"class"、"why" のどれかの鍵が無い
- この5つ以外の鍵を持つ
- 値が文字列でない
- "why" が、前後の半角空白とタブを除いて空である
- "class" が "equivalent" でない。一覧に書ける分類は等価だけで、「未検査」と「欠陥の疑い」は一覧で指摘を消せない
- "file" が絶対パスか、".." の要素を含む。基準のディレクトリの外は読まない

equivalent_invalid の指摘は、path が一覧のファイル、line が無し（null）、detail が一覧に書かれたままの "file" と "change" を ": " でつないだ文字列である。"file" と "change" が無いか文字列でなければ、その側は空の文字列にする。形の誤った1件は正規化できない場面がある。

形の誤った1件には equivalent_invalid だけを出し、equivalent_stale は出さない。直すべきは形の方で、2つ出すと雑音になる。

同じ内容の1件が2つ以上あること自体は検査しない。形の誤りは1件ごとに出す。

### 確認すること

- C-core-equiv-14 "why" が空白だけ、"class" が "equivalent" でない、5つ以外の鍵を持つ、"file" が基準のディレクトリの外を指す、のいずれかの1件には、path が一覧のファイルで line が null の equivalent_invalid の誤りが出る
- C-core-equiv-15 形の誤った1件は、それに合う見逃しを外さず（mutant_survived が出る）、equivalent_stale も出さない
- C-core-equiv-16 equivalent_invalid の detail は書かれたままの "file" と "change" を ": " でつなぎ、"file" の鍵が無い1件では ": " の前が空になる
- C-core-equiv-17 形の誤った同じ内容の1件が2つあれば、equivalent_invalid の誤りも2件出る
