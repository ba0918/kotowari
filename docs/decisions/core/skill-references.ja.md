# スキルの references と本体の一致

[English](skill-references.md) | 日本語

kotowari のスキルの references（"agent/skills/kotowari/references/" の文書）に写した本体の値や形が、本体と一致していることの検査を扱う。この検査は kotowari の振る舞いではなく、このリポジトリのテストが行う。突き合わせる相手は本体のコードが持つ値で、仕様の中の表ではない。設定の鍵と既定の値そのものは[設定のキーは表のものだけにし、書かなかったキーは表の既定の値にする](config.ja.md#設定のキーは表のものだけにし書かなかったキーは表の既定の値にする)で決める。

## スキルの references に写した値は、このリポジトリのテストが本体のコードと突き合わせる

状態: 実装済み

### 問題

スキルの references には、指摘の種類、設定の既定、停止の文言を、本体から写して載せている。本体を変えたときに references が古くなり、そのずれを人手で見つけて直していた。

テストにはマーカーが要り、マーカーは仕様の ID を指すので、この突き合わせの契約も仕様に置く。突き合わせる相手は、実行されるものであるコードにする。仕様の表とコードは既存のテストが合わせているので、references とコードが合えば、仕様とも合う。

### 決めたこと

このリポジトリのテストが、次の3つを本体のコードと突き合わせる。

- "agent/skills/kotowari/references/findings.md" の指摘の種類の表の1列目の集合が、本体のコードが出す指摘の種類の集合と等しい。
- "agent/skills/kotowari/references/config.md" の設定の既定が、本体のコードが持つ設定の既定と等しい（比べ方は[設定の既定は、setup の手順の YAML を本体の読み込みに通して既定と比べる](#設定の既定はsetup-の手順の-yaml-を本体の読み込みに通して既定と比べる)）。
- "agent/skills/kotowari/references/findings.md" の停止の文言の表の1列目の集合が、本体のコードが停止の理由として標準エラーの1行目に出す文言の集合と等しい。表の2列目は読まない。

### 確認すること

- C-core-skillref-1 findings.md の指摘の種類の表の1列目の集合が、本体のコードが出す指摘の種類の集合と等しいことを、テストが確かめる
- C-core-skillref-2 findings.md の停止の文言の表の1列目の集合が、本体のコードが停止の理由として標準エラーの1行目に出す文言の集合と等しいことを、テストが確かめる

## 設定の既定は、setup の手順の YAML を本体の読み込みに通して既定と比べる

状態: 実装済み

### 問題

config.md の既定は、人が読むための表と、setup の手順1の YAML のブロックの両方に書いてある。表は人向けのままにする。どちらで確かめるかを決めた理由は残っていない。

ただし、設定ファイルに書かなかった鍵は既定で埋まるので、読んだ結果を既定と比べるだけでは、ブロックから鍵が欠けても気づけない。また、既定の無い鍵（変異テストの等価の一覧の置き場など）は、値を書けば既定と等しくならず、空の値を書けば設定の誤りで停止するので、比べる YAML に書く意味が無い。

### 決めたこと

config.md の既定は、表ではなく、setup の手順1にある YAML のコードブロックで確かめる。表は人向けのままにし、機械では読まない。

テストは、そのブロックに、既定のある設定の鍵がすべて書かれていることを先に確かめ、そのあと、そのブロックを設定ファイルとして本体のコードで読んだ結果が、本体のコードが持つ設定の既定の値と等しいことを確かめる。既定の無い鍵は、このブロックに書かない。

### 見送った案

- 既定の無い鍵にも既定を与えて、ブロックに書けるようにする。既定を持たないと決めた決定を覆すことになり、設定のファイルの無いプロジェクトが停止する。

### 確認すること

- C-core-skillref-3 config.md の setup の手順1の YAML のブロックに既定のある鍵がすべて書かれていて、それを設定ファイルとして本体のコードで読んだ結果が設定の既定と等しいことを、テストが確かめる

## テストが目印にする表の1列目の見出しは、Kind と Message にする

状態: 実装済み

### 問題

スキルの references を英語にすると、日本語の列名（「種類」「文言」）を目印にしてきたテストの約束が成り立たなくなる。

### 決めたこと

"agent/skills/kotowari/references/findings.md" で、このリポジトリのテストが目印にする表の1列目の見出しを、指摘の種類の表は `Kind`、停止の文言の表は `Message` にする。`Kind` は、指摘の JSON の "kind" に揃えた。停止の文言は標準エラーの1行目の文字なので `Message` にした。ほかの列の見出しは、英語で自由に訳してよい。

### 確認すること

- C-core-skillref-4 findings.md に、1列目の見出しが `Kind` の表と `Message` の表があり、テストがその表の1列目を読む
