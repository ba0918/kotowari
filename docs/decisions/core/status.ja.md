# 揃っているかの集計

[English](status.md) | 日本語

"kotowari status" が、check と同じ読み取りと検査の結果を集計し、揃っているか（complete）を数と真偽で出すところを扱う。complete が何で決まるかは[人に戻す問題は、話題の文書の「未決」の節に書く](decision-documents.ja.md#人に戻す問題は話題の文書の未決の節に書く)、決定の状態ごとの数を出すことは[状態は実装する側が変え、まだ作らない決定は「提案」のまま置く](confirmations.ja.md#状態は実装する側が変えまだ作らない決定は提案のまま置く)で決める。

## status は check と同じものを読んで同じ検査をし、指摘の代わりに数と complete を出す

状態: 実装済み

### 問題

check は1件ずつの指摘を、list は1件ずつの決定と行を出す。その上に立って、「この仕様はいま揃っているか」を、数と、まとめて分かる状態（complete の真偽）で答えるコマンドが要る。利用者は、実データで作った見本を見て、この形で合意した。どの数を足すか、やめるかは、使いながら判断する。

数は check の指摘から作るので、check と同じ検査を走らせないと出せない。揃っているかの判定の規則が check と status の2か所にあると、食い違う。

### 決めたこと

"kotowari status" は、"kotowari check" と同じ設定と置き場から、決定の文書、テストのファイル、ガイド、全体像の元データを読む。"surface.rules" が空の一覧でなければ、面のファイル、面の規則のファイル、未記載の面の一覧も読む。そのうえで check と同じ検査を行い、指摘は出さずに、集計を1つ標準出力に出す。

complete の決め方は、[人に戻す問題は、話題の文書の「未決」の節に書く](decision-documents.ja.md#人に戻す問題は話題の文書の未決の節に書く)で決めたもの（check の誤りが0で、どの話題の文書にも「未決」の項目が無いこと）だけにし、status 独自の判定の規則は持たない。check の注意は、誤りではないので complete を妨げない。そこに無い基準が要るなら、check に足す。

"kotowari status" は、check が停止する条件（設定の誤り、読めないファイル、引数の誤り）が成り立つとき、check と同じ理由と文言で停止する。

### 確認すること

- C-core-status-1 "kotowari status" は指摘の1件ずつを出さず、"findings" の群には誤りと注意の数だけが入る
- C-core-status-2 check に誤りがあれば、"kotowari status" の "complete" は false になる
- C-core-status-3 設定ファイルが YAML として読めないとき、"kotowari status" は終了コード2で、標準エラーの1行目が "kotowari check" と同じである
- C-core-status-4 ガイドの置き場がテストのファイルの置き場と重なっているとき、"kotowari status" は check と同じく設定の誤りで停止する

## 終了コードは、complete なら 0、そうでなければ 1 にする

状態: 実装済み

### 問題

CI で "kotowari status" を1つ走らせるだけで、揃っているかを判定できるようにしたい。

### 決めたこと

"kotowari status" は、"complete" が true なら終了コードを0に、false なら1にする。停止は2である。

### 見送った案

- 読み取りだけのコマンドとして、終了コードを常に0にする。list と違い status は判定を持つので、判定を終了コードに映す。

### 確認すること

- C-core-status-5 "complete" が true なら "kotowari status" の終了コードは0、false なら1である

## 集計は、テストのマーカー、ガイド、全体像、面、指摘の数を群ごとに出す

状態: 実装済み

### 問題

status が何を数えるかを決める必要があった。ガイドと全体像の元データは、glob の誤りで0件になっても黙らないように、読んだ数を出す。全体像の元データはガイドと同じ扱いにする。仕様に無い面は誤りなので complete はそれで false になるが、未記載の面の一覧に頼っている量を見えるようにするために、面の数も出す。

### 決めたこと

集計は、次の群を持つ。群の名前と鍵は英語にし、JSON と "text" で同じ語を使う。

| 群 | 鍵 | 中身 |
|---|---|---|
| tests | marks、files | テストのマーカーの数と、読んだテストのファイルの拡張子ごとの数 |
| guides | files、marks | 読んだガイドの数と、ガイドのマーカーの数 |
| overview | files、marks | 読んだ全体像の元データの数と、そのマーカーの数 |
| surface | total、specified、unspecified | 面の数、そのうち決定の文書に書かれた面の数、未記載の面の一覧に載った面の数 |
| findings | error、notice | check の誤りの数と、注意の数 |
| complete | （値だけ） | true か false |

決定の状態ごとの数の群は[状態は実装する側が変え、まだ作らない決定は「提案」のまま置く](confirmations.ja.md#状態は実装する側が変えまだ作らない決定は提案のまま置く)で、確認することの行の数は[確認することの行の数を、テストのあるもの、無いもの、読んで確認のものに分けて出す](#確認することの行の数をテストのあるもの無いもの読んで確認のものに分けて出す)で決める。

### 確認すること

- C-core-status-6 "tests" の群に、テストのマーカーの数と、読んだテストのファイルの拡張子ごとの数が出る
- C-core-status-7 "guides" の群と "overview" の群に、それぞれ読んだファイルの数とマーカーの数が出る
- C-core-status-8 "surface" の群に、面の数、決定の文書に書かれた面の数、未記載の面の一覧に載った面の数が出る
- C-core-status-9 "findings" の群に、check の誤りの数と注意の数が分けて出る

## 確認することの行の数を、テストのあるもの、無いもの、読んで確認のものに分けて出す

状態: 提案

### 問題

古い集計は、要求ごとにテストのあるものと無いものの数と、テストで確かめない要求に確かめ方があるかの数を出していた。利用者は実データで作った見本を見てこの形に合意し、どの数を足すか、やめるかは使いながら判断するとした。新しい形では、テストを数える単位は確認することの行になり（[check は、確認することの行ごとに、それを指すテストがあるかを数える](confirmations.ja.md#check-は確認することの行ごとにそれを指すテストがあるかを数える)）、テストで確かめない行は頭に「（読んで確認）」と書く（[テストで確かめない行は、頭に「（読んで確認）」と書く](confirmations.ja.md#テストで確かめない行は頭に読んで確認と書く)）。今の status が新しい形について出すのは、決定の状態ごとの数だけで、確認することの行にどれだけテストが付いているかは数で見えない。

### 決めたこと

"kotowari status" の集計に、確認することの行の数を、次の3つに分けて出す。

- テストで確かめる行のうち、それを指すテストのある行の数
- テストで確かめる行のうち、それを指すテストの無い行の数
- 頭に「（読んで確認）」と書いた行の数

### 確認すること

- C-core-status-13 "kotowari status" の集計に、確認することの行のうちテストのある行の数、テストの無い行の数、「（読んで確認）」の行の数が分かれて出て、「（読んで確認）」の行はテストのある行にも無い行にも数えない

## documents の群は、読んだ決定の文書の数と行数を数える

状態: 提案

### 問題

status は、読んだ文書の数と行数を出す。仕様は決定の文書だけで持つので、数える相手を決定の文書にする必要がある。

### 決めたこと

"documents" の群の "files" と "lines" は、読んだ決定の文書の数と、その行数の合計にする。

### 確認すること

- C-core-status-10 "documents" の群の "files" と "lines" が、読んだ決定の文書の数と行数の合計になる

## 出力は json と text の2つにし、text は群ごとに1行にする

状態: 実装済み

### 問題

"text" と JSON の対応を、読む人が覚えなくて済むようにしたい。桁揃えの空白は値の桁で変わり、契約にしにくい。kotowari が決める固定の語は、停止の文言と JSON の鍵が英語なので、それに揃える。

### 決めたこと

"kotowari status" の "--format" は "json" と "text" の2つだけを受け、既定を "json" にする。"json" では、最上位が群の鍵だけの JSON を1つ出す。

"text" では、群ごとに "群名 鍵=値 鍵=値" の形の1行を出す。鍵の語は JSON と同じで、値の間は1つの半角空白で区切り、桁揃えの空白は入れない。"complete" の行は "complete true" か "complete false" である。

### 確認すること

- C-core-status-11 "text" では、群ごとに "群名 鍵=値" を1つの半角空白で並べた1行が出て、"complete" の行は "complete true" か "complete false" である
- C-core-status-12 "json" の出力の最上位の鍵は、群の名前と "complete" だけである
