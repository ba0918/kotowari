# 設定

[English](config.md) | 日本語

設定ファイルの場所、キーと既定の値、値の読み方、置き場が無いときと設定の誤りでの停止を扱う。設定の値のパスを何からの相対で読み、どう正規化するかは[設定ファイルの値のパスと、出力の "path" は、基準のディレクトリからの相対にする](base-directory.ja.md#設定ファイルの値のパスと出力の-path-は基準のディレクトリからの相対にする)で、"--config" の指す先が無いときの停止は[受けないオプション、知らないコマンド、余計な位置引数、値の誤ったオプションは、引数の誤りで停止する](cli.ja.md#受けないオプション知らないコマンド余計な位置引数値の誤ったオプションは引数の誤りで停止する)で決める。キーごとの値の意味は、そのキーを使う話題で決める。

## 設定ファイルは基準のディレクトリの .kotowari/config.yaml に置き、--config で別のファイルを指せる

状態: 実装済み

### 問題

kotowari が何を読むかを、どこに書かせるかを決める必要がある。".kotowari/" のディレクトリに置けば、依存が増えてもそのディレクトリの中に足せて管理しやすく、LLM にその設定ファイルを読ませることもできる、と利用者が判断した。"--config" のパスをカレントディレクトリからの相対で読む理由は残っていない。

### 決めたこと

"kotowari plan" でないコマンドは、"--config" が無ければ、基準のディレクトリ（[相対パスの基準は、上に向かって探した最初の .kotowari/ のあるディレクトリにする](base-directory.ja.md#相対パスの基準は上に向かって探した最初の-kotowari-のあるディレクトリにする)）の ".kotowari/config.yaml" を設定ファイルとして読む。"--config" があれば、その値をカレントディレクトリからの相対パスとして読み、そのファイルを設定ファイルにする。"kotowari plan" は設定を読まない。

リポジトリ直下の "kotowari.toml" は、設定ファイルとして読まない。

### 見送った案

- 設定をリポジトリ直下の "kotowari.toml" に置く。依存が増えたときに ".kotowari/" の中に足せるほうが管理しやすい。

### 確認すること

- C-core-config-1 "--config" が無いとき、基準のディレクトリの ".kotowari/config.yaml" が設定ファイルとして読まれる
- C-core-config-2 "--config" のパスはカレントディレクトリからの相対として読まれ、check、list、query、status、overview build は、どれもそのファイルの設定を使う
- C-core-config-3 リポジトリ直下に、置き場を変える値を書いた "kotowari.toml" を置いても、読まれない

## 設定ファイルが無いか空なら、既定の値で動く

状態: 実装済み

### 問題

設定ファイルを書かないプロジェクトでも、kotowari を使い始められるようにする。理由は残っていない。

### 決めたこと

"--config" を付けずに設定ファイルが無いとき、kotowari は既定の値で動く。設定ファイルが空（0バイトか、注釈だけ）のときは、"--config" で指したものでも、既定の値で動く。

### 確認すること

- C-core-config-4 設定ファイルが無いとき、check は既定の値で動く
- C-core-config-5 0バイトの設定ファイルと、注釈だけの設定ファイルは、既定の値として読まれる

## 設定のキーは表のものだけにし、書かなかったキーは表の既定の値にする

状態: 実装済み

### 問題

テストを探す場所や、ガイドと面のファイルの置き場は、プロダクトによって違う。設定で変えられるようにする、と利用者が判断した。キーごとの既定の値の理由は、そのキーを使う話題にある。

### 決めたこと

設定のキーは、次の表のものだけにする（決定の文書の置き場のキーは[決定の文書の置き場は decisions.documents で指して既定を docs/decisions にし、古い形の置き場のキーは無くす](#決定の文書の置き場は-decisionsdocuments-で指して既定を-docsdecisions-にし古い形の置き場のキーは無くす)で決め、無くすキーは[行数と要求の数の上限のキー limits.lines と limits.requirements は無くす](#行数と要求の数の上限のキー-limitslines-と-limitsrequirements-は無くす)で決める）。書かなかったキーは、表の既定の値にする。

| キー | 値 | 既定 |
|---|---|---|
| tests.files | glob の一覧。テストのファイルを探す場所（[テストのファイルは tests.files の glob で選ぶ](test-discovery.ja.md#テストのファイルは-testsfiles-の-glob-で選ぶ)） | "src/\*\*/\*.rs"、"tests/\*\*/\*.rs" |
| tests.rust.attributes | "#[test]" に足して数える属性のパスの一覧（[Rust では、属性のパスの末尾が test の関数を必ず数え、属性とマクロを設定で足す](test-queries.ja.md#rust-では属性のパスの末尾が-test-の関数を必ず数え属性とマクロを設定で足す)） | 空の一覧 |
| tests.rust.macros | テストを含むマクロの名前の一覧（同上） | 空の一覧 |
| tests.rules | ast-grep のルールの YAML ファイルのパスの一覧。glob は使えない（[設定の tests.rules で問い合わせを足し、同梱の問い合わせは外せない](query-rules.ja.md#設定の-testsrules-で問い合わせを足し同梱の問い合わせは外せない)） | 空の一覧 |
| guides.files | glob の一覧。ガイドの置き場（[ガイドは guides.files の glob で選び、check と status だけが読む](guides.ja.md#ガイドは-guidesfiles-の-glob-で選びcheck-と-status-だけが読む)） | 空の一覧 |
| mutants.equivalents | 等価の一覧のファイルのパス（1つの文字列）（[等価の判断は、設定の mutants.equivalents が指す YAML の一覧に置く](equivalents.ja.md#等価の判断は設定の-mutantsequivalents-が指す-yaml-の一覧に置く)） | 無し（等価の一覧は0件） |
| surface.files | glob の一覧。面のファイルの置き場（[面は、設定の surface.files と surface.rules で、ast-grep の規則に当たった節としてコードから取り出す](surface.ja.md#面は設定の-surfacefiles-と-surfacerules-でast-grep-の規則に当たった節としてコードから取り出す)） | 空の一覧 |
| surface.rules | ast-grep のルールの YAML ファイルのパスの一覧。glob は使えない。空の一覧でなければ面の検査を行う | 空の一覧 |
| surface.unspecified | 未記載の面の一覧のファイルのパス（1つの文字列）（[まだ仕様にしていない面は、理由を付けて未記載の面の一覧に載せれば誤りにしない](surface-unspecified.ja.md#まだ仕様にしていない面は理由を付けて未記載の面の一覧に載せれば誤りにしない)） | 無し（未記載の面の一覧は0件） |
| vague_words | 曖昧語の一覧（曖昧語を当てる節は[用語集は人が読む文書として残し、用語の検査はやめる](decision-documents.ja.md#用語集は人が読む文書として残し用語の検査はやめる)） | "適切に"、"必要に応じて"、"通常は"、"など" の4語 |
| overview.files | glob の一覧。全体像の元データの置き場（[全体像の元データは、リポジトリにコミットして保守し、overview.files の glob で選ぶ](overview-data.ja.md#全体像の元データはリポジトリにコミットして保守しoverviewfiles-の-glob-で選ぶ)）。"overview" を書くときは必須 | "overview" が無ければ、全体像の元データを読まない |
| overview.toc | 目次のファイルのパス（1つの文字列）（[一覧の束ね方と並びは、overview.toc の指す目次のファイル1つに書く](overview-toc.ja.md#一覧の束ね方と並びはoverviewtoc-の指す目次のファイル1つに書く)）。"overview" を書くときは必須 | "overview" が無ければ、目次を読まない |
| languages | 言語タグの一覧（[言語の一覧は、設定の languages で決める](translation-pairs.ja.md#言語の一覧は設定の-languages-で決める)） | 無し（"en" だけの一覧とみなす） |
| labels | 言語タグごとの、UI の文字の鍵から文字列への対応表（[UI の文字は、英語を kotowari が持ち、ほかの言語は設定の labels に書く](overview-languages.ja.md#ui-の文字は英語を-kotowari-が持ちほかの言語は設定の-labels-に書く)） | 無し（英語の UI の文字は kotowari が持つ） |

全体像は、"overview" のキーを書いたときだけ有効にする。全体像の元データの置き場があるだけでは有効にしない。黙って既定で有効にしないためである。

### 見送った案

- 全体像の元データの置き場（".kotowari/overview/"）があれば、"overview" のキーが無くても自動で有効にする。黙って既定で有効にすることになる。

### 確認すること

- C-core-config-6 設定ファイルにキーを書かなければ、各キーは表の既定の値になる
- C-core-config-7 表のキーに書いた値は、書いたとおりに読まれる

## 決定の文書の置き場は decisions.documents で指して既定を docs/decisions にし、古い形の置き場のキーは無くす

状態: 提案

### 問題

仕様は決定の文書だけで持ち、check は IR の置き場と、判断の記録と ADR の置き場を読まなくなる（[決定の文書は docs/decisions に置き、古い形の文書は凍結した木へ移す](decision-documents.ja.md#決定の文書は-docsdecisions-に置き古い形の文書は凍結した木へ移す)と[新しい版で一度に切り替え、古い形を読む仕組みは作らない](form-switch.ja.md#新しい版で一度に切り替え古い形を読む仕組みは作らない)）。読まないキーを受けたままにすると、書いた人は効いていると誤解する。古い形を読む仕組みは作らないと、利用者が決めている。

### 決めたこと

決定の文書の置き場は、設定の "decisions.documents" のキーに、ディレクトリのパス（1つの文字列）で書く。既定は "docs/decisions" にする。

古い形の置き場のキー "ir"、"decisions.records"、"decisions.adr" は無くす。設定ファイルに書かれていれば、表に無いキーとして、設定の誤りで停止する。

### 確認すること

- C-core-config-8 設定に "decisions.documents" が無いとき、check は "docs/decisions" の下の決定の文書を読む
- C-core-config-9 設定ファイルに "ir"、"decisions.records"、"decisions.adr" のどれかがあると、設定の誤りで停止する

## 行数と要求の数の上限のキー limits.lines と limits.requirements は無くす

状態: 提案

### 問題

決定の文書では、行数の上限の注意（too_many_lines）を出さない。要求の数の上限の注意（too_many_requirements）は、要求が無くなるので意味を失う。上限の値を書くキーを受けたままにすると、書いた人は効いていると誤解する。

### 決めたこと

設定のキー "limits.lines" と "limits.requirements" は無くす。設定ファイルに書かれていれば、表に無いキーとして、設定の誤りで停止する。値が負の数か0のときの停止も、このキーと一緒に無くなる。

### 確認すること

- C-core-config-27 設定ファイルに "limits.lines" か "limits.requirements" があると、設定の誤りで停止する

## 決定の文書の置き場が無いか、ディレクトリでないか、読めなければ、読めないファイルで停止する

状態: 実装済み

### 問題

置き場の書き誤りを、読む文書が0件の状態として黙って通すと、検査したつもりで何も検査していないことになる（[読めない入力と壊れた入力は、停止か誤りの指摘にし、黙って読み飛ばさない](cli-environment.ja.md#読めない入力と壊れた入力は停止か誤りの指摘にし黙って読み飛ばさない)）。置き場が無いときを、設定の誤りでなく読めないファイルの停止にした理由は残っていない。

### 決めたこと

"kotowari check" は、決定の文書の置き場の指す先が無いとき、ディレクトリでないとき、読めないときは、読めないファイル（unreadable file）を理由に停止する。

"tests.files"、"guides.files"、"surface.files"、"overview.files" の走査で、読めないディレクトリか、先の無いシンボリックリンクに出会ったときも、同じ理由で停止する。置き場によって規則が違うと覚えにくいので、どの置き場の走査も同じにする。

### 確認すること

- C-core-config-10 決定の文書の置き場の指す先が無いか、ディレクトリでないか、読めなければ、check は unreadable file を理由に停止する
- C-core-config-11 "tests.files"、"surface.files"、"overview.files" の走査で、読めないディレクトリか先の無いシンボリックリンクに出会うと、check は unreadable file を理由に停止する

## 設定ファイルが YAML として読めないか、キーと値が決まりに合わなければ、設定の誤りで停止する

状態: 実装済み

### 問題

知らないキーがあれば、動かずに誤りを返す、と利用者が決めた。設定の誤りを黙って読み飛ばしたり、黙って既定の値にしたりすると、書いた人は設定が効いていると誤解する（[読めない入力と壊れた入力は、停止か誤りの指摘にし、黙って読み飛ばさない](cli-environment.ja.md#読めない入力と壊れた入力は停止か誤りの指摘にし黙って読み飛ばさない)）。

"/" で始まる glob の要素は、基準のディレクトリからの相対パスに当たらず、何にも当たらない。拒んでも、動いていた設定は壊れない。絶対パスかどうかを先頭の "/" だけで見分けるのは、対象の OS が Linux と macOS だからである（[対象の OS は Linux と macOS で、Windows ではパスの区切りの正規化だけを約束する](cli-environment.ja.md#対象の-os-は-linux-と-macos-でwindows-ではパスの区切りの正規化だけを約束する)）。Windows のドライブ文字まで見ると、Linux と macOS で書ける相対パス（"a:b"）を絶対パスとして拒むことになる。

"vague_words" の空の文字列は語として意味を持たず、受けると壊れた設定を黙って通すことになる。空の文字列を停止にした理由は記録に残っていない。

キーの重複で停止したとき、YAML のライブラリの文言と複数行の抜粋をそのまま出すと、どのキーを直せばよいかが読みにくい。説明の文は契約ではないが、直す手がかりになる。

### 決めたこと

次のどれかに当たれば、kotowari は設定の誤り（config error）を理由に停止する。

| 設定の誤り | 補足 |
|---|---|
| 設定ファイルが YAML として読めない | |
| 表に無いキー | どの階層に書いても |
| 同じキーの2回目 | 説明は "duplicate key: <キー>" の1行にし、ライブラリの文言や複数行の抜粋を出さない |
| 値が null のキー（"tests:" だけの行） | 空の一覧は受ける（[一覧のキーは一覧だけを受け、書いた一覧で既定を置き換え、空の一覧は要素の無い一覧にする](#一覧のキーは一覧だけを受け書いた一覧で既定を置き換え空の一覧は要素の無い一覧にする)） |
| 型の違う値 | |
| 絶対パスの値（先頭が "/" のもの） | "tests.files"、"guides.files"、"surface.files"、"overview.files" の glob の要素も含む。絶対パスかどうかは先頭の "/" だけで見分け、"a:b" のように Windows のドライブ文字に似た値は絶対パスとして拒まない |
| "vague_words" の空の文字列の要素と、同じ語の2回目 | |
| "tests.files"、"guides.files"、"surface.files"、"overview.files" の、glob として読めない要素 | |
| "overview" を書いたのに、"overview.files" か "overview.toc" が無い | |

### 確認すること

- C-core-config-12 YAML として読めない設定ファイルと、表に無いキー（最上位の "limit:"、入れ子の中の知らないキー）は、設定の誤りで停止する
- C-core-config-13 同じキーが2回あると、標準エラーは "config error: " で始まり "duplicate key: <キー>" を含む1行になる
- C-core-config-14 値が null のキーと、型の違う値は、設定の誤りで停止する
- C-core-config-15 先頭が "/" の値と glob の要素は、設定の誤りで停止する
- C-core-config-16 "tests.files"、"guides.files"、"surface.files"、"overview.files" の、glob として読めない要素は、設定の誤りで停止する
- C-core-config-17 "vague_words" に同じ語が2回あると、設定の誤りで停止する
- C-core-config-18 "overview" を書いたのに "overview.files" か "overview.toc" が無いと、設定の誤りで停止する
- C-core-config-25 "vague_words" に空の文字列の要素があると、終了コード2で停止し、標準出力に何も出さない
- C-core-config-26 先頭が "/" でない値は、"a:b" のように Windows のドライブ文字に似ていても、絶対パスとして拒まれない

## 一覧のキーは一覧だけを受け、書いた一覧で既定を置き換え、空の一覧は要素の無い一覧にする

## glob の "**" は再帰で読み、隠しディレクトリにはパスの成分で名指ししたときだけ入る

状態: 実装済み

### 問題

glob の "**" をどこまで辿るか、隠しディレクトリ（名前が "." で始まるディレクトリ）をどう扱うかを決める必要がある。隠しディレクトリを除く理由は残っていない。

全体像の元データは ".kotowari/overview/" に置く。".kotowari/" は、設定やキャッシュのような、人が直接読まない道具のデータの置き場で、元データはその仲間だからである。隠しディレクトリを除いたままでは、元データを読めない。

波括弧の中で名指しした隠しディレクトリまで名指しに数えるには、波括弧の展開を kotowari が自前で持つ必要がある。既定の値はパスの成分で名指ししていて、困る利用者がいない。

### 決めたこと

kotowari は、glob の "**" を再帰として読む。隠しディレクトリには、glob が名指ししても入らない。例外は "overview.files" で、パスの成分で名指しした隠しディレクトリ（".kotowari/overview/*.md" の ".kotowari" と "overview"）の下は読む。広い "**" だけでは、名指ししていない隠しディレクトリに入らない。波括弧の中だけで名指しした隠しディレクトリは、パスの成分による名指しに数えない。

隠しファイルは、glob が当てれば読む。ディレクトリのシンボリックリンクは辿らない。

### 確認すること

- C-core-config-22 "**" はサブディレクトリまで再帰で当たり、隠しディレクトリの下のファイルには当たらない
- C-core-config-23 glob が当てた隠しファイルは読まれる
