# 使い手と作り

[English](cli-scope.md) | 日本語

kotowari を誰が使うか、kotowari がどこに書き出してよいか、コードをどう置くかを扱う。ライブラリのクレートの責務と依存の向きは[ライブラリのクレート境界](library-crates.ja.md)の話題で、全体像のコマンドが書く置き場の細部は[全体像を作るコマンドと見せるコマンド](overview-commands.ja.md)の話題で決める。

## kotowari は、第一に LLM が使う CLI にする

状態: 実装済み

### 問題

kotowari を、誰が、どこで使う道具にするかを決める必要がある。利用者は、LLM 自身に kotowari を使わせて、仕様を決めてから実装する作業の流れを補助させるつもりでいる。人は確かめるために実行することはあるが、第一の使い手ではない。

### 決めたこと

kotowari は、第一に LLM が使う CLI にする。人が確かめるために実行することもある。使う場は、LLM を使って、壁打ちで仕様を決めてから実装する流れを、自分のリポジトリで回す開発者のリポジトリである。

## kotowari は状態を保存せず、標準出力と標準エラーのほかに書き出さない

状態: 実装済み

### 問題

kotowari のコマンドは、読んで検査し、結果を標準出力と標準エラーに出す。全体像を作るコマンドだけは、ページのファイルを書く必要がある。書く先を設定で変えられると、設定次第で書き出し先が変わり、何も書かないという強い保証に大きな穴が開く。穴は最小にしたい。ほかに書き出さないことそのものを決めた理由は残っていない。

### 決めたこと

kotowari は、状態を保存しない。標準出力と標準エラーのほかに書き出さない。

例外は、"kotowari overview build" と "kotowari overview serve" が、基準のディレクトリの ".kotowari/cache/overview/" の下に書くことと、その下の、自分が作ったファイルを消すことだけにする。書く先は設定で変えられない（[全体像のコマンドは、.kotowari/cache/overview の下のほかに書かず、消さない](overview-commands.ja.md#全体像のコマンドはkotowaricacheoverview-の下のほかに書かず消さない)）。その下のどのファイルを消すかは、[overview build は、毎回すべてを描き、中身の違うファイルだけを書き、作られなくなったファイルを消す](overview-commands.ja.md#overview-build-は毎回すべてを描き中身の違うファイルだけを書き作られなくなったファイルを消す)で決める。ほかのコマンドには例外を作らない。

### 確認すること

- C-core-scope-1 "kotowari check" を実行しても、基準のディレクトリの下と、環境変数 "HOME" と "TMPDIR" が指すディレクトリの下の、ファイルの一覧と中身が変わらない
- C-core-scope-2 全体像の元データがあっても、"kotowari check" と "kotowari status" は何も書かない

## クレートは層が増えるたびに足し、CLI はリポジトリ直下の src/ で持つ

状態: 実装済み

### 問題

コードをどういう単位で分けるかを決める必要がある。層を足すたびにクレートを足すことにした理由は残っていない。ライブラリのパッケージを kotowari という名前にするのは、ライブラリを使う人が `cargo add kotowari` から始められるようにするためである。

### 決めたこと

クレートは、層が増えるたびに足す（クレートの分け方は[用途ごとにパッケージを分け、利用者は用途でパッケージを選ぶ](library-crates.ja.md#用途ごとにパッケージを分け利用者は用途でパッケージを選ぶ)）。CLI は、リポジトリ直下の "src/" で持つ。

リポジトリ直下のパッケージは kotowari-cli で、"src/main.rs" で kotowari のコマンドを提供する。ライブラリのパッケージの名前は kotowari にする。コマンドの名前は kotowari のままにする。

### 見送った案

- 最初から、層の1つとして `crates/kotowari-core` を置く。採らなかった理由は残っていない。

### 確認すること

- C-core-scope-3 （読んで確認）リポジトリ直下のパッケージ kotowari-cli が "src/main.rs" で kotowari のコマンドを提供し、ライブラリは層ごとのクレートに分かれている
