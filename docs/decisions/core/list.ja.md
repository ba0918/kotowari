# 決定と確認することの一覧

[English](list.md) | 日本語

"kotowari list" が、決定の文書の決定と確認することの行を、それを指すテストと一緒に、人と LLM が読める形で出すところを扱う。何を読むかは check と同じで、指摘は出さない。1件を詳しく読むことは[1件の読み取り](query.ja.md)、数と揃っているかは[揃っているかの集計](status.ja.md)で決める。

## list は check と同じものを読み、指摘を出さず、読めた決定と確認することの行をすべて出す

状態: 実装済み

### 問題

check は、仕様とテストのマーカーの対応をすでに組み立てているのに、それを人と LLM が読める形で出す口が無かった。仕様とテストの対応は、手で書いた表で保つしかなく、手で保つ表は腐る。同じデータの別の切り口として出すなら、新しい状態も外部の依存も増えない。

LLM が一覧を読んだあとで、足りない情報を取りに別のコマンドを呼び直すと、読み込みの往復が増える。1回の list で要ることが揃うようにする。指摘と一覧の1件は別物なので混ぜない。指摘を出すのは check の仕事で、list は読み取りなので、誤りがあることを理由に出力を止める理由も無い。

### 決めたこと

"kotowari list" は、"kotowari check" と同じ設定と置き場から、決定の文書とテストのファイルを読む。読めた決定と、形の正しい ID を持つ確認することの行を、すべて標準出力の "items" に出す。指摘は出さず、終了コードを0にする。決定の文書に check の誤りがあっても、読めた決定と行は出す。

1回の list で、決定とテストの対応を読むのに要ることが揃うようにし、さらに詳しいことは [1件の読み取り](query.ja.md#query-は-id-を1つ受けその-id-の決定か確認することの行をlist-の1件に本文を足して出す)で取る。"items" の1件の形は、check の指摘（"findings"）とは別の形にする。

### 見送った案

- 仕様とテストの対応を出す trace を、list とは別のコマンドにする。list の出力に含まれる情報と同じになる。
- 仕様とテストの対応を手で書いた表を残し、list と無関係にする。手で保つ表が1つ残る。

### 確認すること

- C-core-list-1 "kotowari list" は、設定の置き場の決定の文書のすべての決定と、形の正しい ID を持つ確認することの行を出し、形の誤った ID の行は出さない
- C-core-list-2 決定の文書に check の誤りがあっても、"kotowari list" は終了コード0で読めた決定と行を出し、出力に指摘を出さない

## 確認することの行にはそれを指すテストを、決定には指紋を付ける

状態: 実装済み

### 問題

1回の list で要ることが揃うように、1件が何を持つかを決める必要があった。テストのマーカーの有無は、テストの言語に依らず check が数えている。問い合わせの無い言語では、テストの名前だけが取れない。同じテストに同じ ID のマーカーが2つあるときに、テストごとに1件にすると、どの行を "line" にするかの決まりがもう1つ要る。

ガイドのマーカーは、決定の見出しと、その決定の指紋を書く（ガイドの古さの見方は、[ガイドは、決めたことと確認することが変わったら古いとする](languages-and-guides.ja.md#ガイドは決めたことと確認することが変わったら古いとする)で決める）。書く値を取る口が要る。

### 決めたこと

"items" の1件は、どれも ID（"id"）、種類（"kind"）、名前（"name"）、場所（"path" と "line"）を持つ。"kind" の値は、決定なら "decision"、確認することの行なら "confirmation" とする。"path" は[基準のディレクトリからの相対パス](base-directory.ja.md#設定ファイルの値のパスと出力の-path-は基準のディレクトリからの相対にする)である。

確認することの行の1件は、その行が「（読んで確認）」の行かどうか（"by_reading"）と、その行の ID を含むマーカーのあるテストの並び（"tests"）を持つ。"tests" の1件は、テストのファイルの "path"、マーカーのある行の "line"、テストの名前の "name" を持つ。同じテストに同じ ID のマーカーが複数あれば、マーカーの出現ごとに1件にする。問い合わせの無い言語のテストも同じく載せ、名前を取れないテストの "name" は null にする（[テストの名前は、問い合わせが捕まえた文字から取る](test-discovery.ja.md#テストの名前は問い合わせが捕まえた文字から取る)）。

決定の1件は、ガイドのマーカーに書く指紋（"fingerprint"）を持つ。

### 確認すること

- C-core-list-3 確認することの行の "tests" には、その行の ID を含むマーカーの出現ごとに1件ずつ、テストのファイル、マーカーの行、テストの名前が入る
- C-core-list-4 問い合わせの無い言語のテストと、名前を取れないテストは、"name" が null で "tests" に載る
- C-core-list-5 「（読んで確認）」の行の "by_reading" は true で、ほかの確認することの行は false である
- C-core-list-6 決定の1件の "fingerprint" は、ガイドのマーカーがその決定を指すときに書く指紋と同じ値である

## 並びはパスの順、同じパスの中は行の順にする

状態: 実装済み

### 問題

check の出力と同じ順なら、読み手が迷わない。

### 決めたこと

"items" の1件は "path" の昇順に、同じ "path" の中は "line" の昇順に並べる。1件の "tests" も、"path" の昇順、同じ "path" の中は "line" の昇順に並べる。

### 確認すること

- C-core-list-7 "items" は "path" の昇順、同じ "path" の中は "line" の昇順に並び、1件の "tests" も同じ順に並ぶ

## 出力は json と text の2つにし、絞り込みのオプションは持たない

状態: 実装済み

### 問題

出力の形式は、1つ増えるごとに契約が増える。人に見やすい形は別に検討することにして、最初は最低限の形にした。出力して見づらければ、利用者が変更を求める。

絞り込みのオプションを持つと、1回の list で要ることを揃えるという狙いから外れる。1件に絞って読むのは query の仕事である。

### 決めたこと

"kotowari list" の "--format" は "json" と "text" の2つだけを受け、既定を "json" にする（check と揃える）。絞り込みのオプションは持たない。全件を出し、絞るのは読む側か "kotowari query" で行う。

"json" では、最上位が "items" の JSON を1つ出す（言語が2つ以上のときに足す "translations" は、[次の決定](#言語が2つ以上なら対ごとの-blob-hash-も出す)で決める）。

"text" では、"items" の1件を1行で "ID 検証 名前 パス:行 tests=数" の形に、半角空白で区切って出す。"検証" の欄は、「（読んで確認）」の行では "reading"、ほかでは "-" にする。その直後に、"tests" の1件ごとに、2つの半角空白で字下げした "パス:行 名前" の行を続ける。名前が null なら "-" と書く。

### 見送った案

- 最初から yaml の形式も足す。形式は1つ増えるごとに契約が増える。見やすさを検討したあとで、要るなら足す。

### 確認すること

- C-core-list-8 言語が1つのとき、"json" の出力の最上位の鍵は "items" だけである
- C-core-list-9 "text" では1件を "ID 検証 名前 パス:行 tests=数" の1行で出し、「（読んで確認）」の行の検証の欄は "reading"、ほかは "-" で、その下にテストの1件ごとに字下げした "パス:行 名前" の行が続き、名前が null なら "-" と書く

## 言語が2つ以上なら、対ごとの blob hash も出す

状態: 実装済み

### 問題

対の一致の記録には、両側の内容の識別子（blob hash）を写す。LLM がそれを1回の実行で得られるようにしたい。ところが list はガイドと全体像の元データを読まないので、その置き場の対の hash を出すには、置き場を辿る必要があった。

### 決めたこと

設定の言語の一覧（"languages"）の言語が2つ以上のとき、"json" の最上位に "translations" を足す。"translations" は対ごとの1件の並びで、1件は先頭の言語の側のパス（"path"）と、言語ごとの1件の並び（"sides"）を持つ。言語ごとの1件は、言語タグ（"language"）、その側のパス（"path"）、その側の blob hash（"blob"）を持つ。言語が1つなら "translations" を出さない。

"text" では、"items" の行のあとに、対を1行ずつ、先頭の言語の側のパスに続けて、言語ごとに "言語タグ=hash" を並べて出す。

このために、言語が2つ以上のときは、ガイド、全体像の元データ、目次の置き場を check と同じに辿る。置き場が読めないときは、check と同じに停止する。中身は検査しない。

### 確認すること

- C-core-list-10 言語が2つ以上のとき、ガイド、全体像の元データ、目次の対ごとに、言語ごとのパスと blob hash が "translations" に出て、"text" では対ごとに1行で出る
- C-core-list-11 言語が2つ以上のとき、ガイドの置き場について check が停止する設定では、"kotowari list" も check と同じ標準エラーで停止し、言語が1つなら同じ設定でも停止しない

## 決定の文書の対も translations に出す

状態: 実装済み

### 問題

決定の文書も、多言語の対で持てるようにする（[決定の文書も、多言語の対で持てる](languages-and-guides.ja.md#決定の文書も多言語の対で持てる)）。対の一致の記録に写す hash を1回の実行で得られるようにするという理由は、決定の文書の対にもそのまま当たる。

### 決めたこと

言語の一覧の言語が2つ以上のとき、"translations" に、決定の文書の置き場の対も1件ずつ出す。

### 確認すること

- C-core-list-12 言語が2つ以上のとき、決定の文書の対ごとに、言語ごとのパスと blob hash が "translations" に出る

## list は check と同じ条件で停止し、ガイドと面は読まない

状態: 実装済み

### 問題

list は check と同じ読み取りなので、受けるものと止まり方も check と同じにする。一方で、list はガイドを要らない。決定の指紋は決定の文書だけから決まる。面を読んで数を出すのは check と status である。

全体像の元データも、言語が1つのときの list には要らない。読むと、全体像の元データの置き場の重なりや読めない元データのファイルで、決定と行の一覧を出すだけの list まで止まる。理由は記録に残っていない。

### 決めたこと

"kotowari list" は、"--format"、"--config"、"--help"、"--version" の4つのオプションだけを受ける。"kotowari check" が停止する条件（設定の誤り、読めないファイル、引数の誤り）が成り立つとき、check と同じ理由と文言で停止する。

ただし "kotowari list" はガイドを読まず、ガイドの置き場と読み込みによる停止はしない。面のファイル、面の規則のファイル、未記載の面の一覧も読まず、その読み込みによる停止はしない。言語が1つのときは、全体像の元データも読まず、その置き場と読み込みによる停止はしない。言語が2つ以上のときに置き場を辿ることは、[言語が2つ以上なら、対ごとの blob hash も出す](#言語が2つ以上なら対ごとの-blob-hash-も出す)で決める。

### 確認すること

- C-core-list-13 設定ファイルが YAML として読めないとき、"kotowari list" は終了コード2で、標準エラーの1行目が "kotowari check" と同じである
- C-core-list-14 "kotowari list" に "--tool" を付けるか、位置引数を足すと、引数の誤りで停止する
- C-core-list-15 言語が1つのとき、ガイドのファイルが読めなくても、ガイドの置き場がテストのファイルの置き場と重なっていても、"kotowari list" は停止しない
- C-core-list-16 未記載の面の一覧のファイルが無くても、面のファイルが読めなくても、"kotowari list" は停止しない
- C-core-list-17 言語が1つのとき、全体像の元データの置き場がガイドの置き場と重なっていても、元データのファイルが UTF-8 でなくても、"kotowari list" は停止しない
