# 文字コードとコードブロックの境界

[English](ir-input.md) | 日本語

読むファイルの先頭の BOM と、閉じないコードブロックの扱いを扱う。コードブロックの中を読まないことそのものは[決定の文書のコードブロックの中は、決定の形としても引用としても読まない](ir-document.ja.md#決定の文書のコードブロックの中は決定の形としても引用としても読まない)で決める。

## 先頭の UTF-8 の BOM は読み飛ばし、UTF-8 でないファイルとして停止しない

状態: 実装済み

### 問題

読むファイルの先頭に UTF-8 の BOM があるときに、それを文字として読むか、文字コードの誤りとするか、読み飛ばすかを決める必要があった。読み飛ばすと決めた理由は残っていない。

### 決めたこと

kotowari が読むファイルの先頭に UTF-8 の BOM があるときは、それを読み飛ばして読み、UTF-8 でないファイルとして停止しない。決定の文書、設定ファイル、テストのファイル、変異の結果のソースのどれにも当てる。

### 確認すること

- C-core-input-1 設定ファイル、テストのファイル、変異の結果のソースの先頭に BOM があっても、check と mutants は停止せず、BOM の無いときと同じく読む
- C-core-input-2 決定の文書の先頭に BOM があっても、check は停止せず、1行目の題名を題名として読む

## 閉じないコードブロックは unclosed_code_block の誤りにし、開始から文書の終わりまでを読まない

状態: 実装済み

### 問題

コードブロックが閉じられずに文書が終わると、Markdown の読み取りは、開始から文書の終わりまでをコードブロックとして読む。何も出さなければ、閉じないコードブロックのあとにある決定と確認することの行が黙って数えられなくなり、実装済みの決定の確認することにテストが無くても check が通る。形に合わない入力を黙って飛ばすことになる（[読めない入力と壊れた入力は、停止か誤りの指摘にし、黙って読み飛ばさない](cli-environment.ja.md#読めない入力と壊れた入力は停止か誤りの指摘にし黙って読み飛ばさない)）。Markdown の読み取りは閉じないコードブロックを検出しないので、kotowari の側で検出する。

### 決めたこと

決定の文書のコードブロックが閉じられずに終わるときは、開始の行を "line"、開始の行の文字をそのまま（字下げを含む）detail にして、unclosed_code_block の誤りを出す。誤りなので、check の終了コードは1になる。

文書の直下のコードブロックが閉じられずに文書が終わるときは、開始の行から文書の終わりまでを検査の対象から外す。その中の見出しは決定にせず、一覧の形の行は確認することの行にしない。開始の行より前の決定と確認することは、そのまま読む。

### 確認すること

- C-core-input-3 決定の文書のコードブロックが閉じられずに終わると、開始の行を "line"、開始の行の文字を detail にした unclosed_code_block の誤りが出て、check の終了コードは1になる
- C-core-input-4 文書の直下の閉じないコードブロックの開始の行から文書の終わりまでにある見出しと確認することの形の行は、決定と確認することの行に数えず、開始の行より前の決定と確認することの行は数える
