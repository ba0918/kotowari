# 全体像を作るコマンドと見せるコマンド

[English](overview-commands.md) | 日本語

"kotowari overview build" が全体像の元データから参照の表と古い節を求めて描画のエンジン（kotowari-markdown-view）に渡し、全体像のファイルを書くまでと、"kotowari overview serve" がそれを手元で見せるまでを扱う。元データの形と検査は[全体像の元データ](overview-data.ja.md)で、2つのコマンドが受けるオプションは[コマンドと終了](cli.ja.md)で、書き出してよい場所の例外は[使い手と作り](cli-scope.ja.md)の[kotowari は状態を保存せず、標準出力と標準エラーのほかに書き出さない](cli-scope.ja.md#kotowari-は状態を保存せず標準出力と標準エラーのほかに書き出さない)で決める。先頭の言語でない言語のページと、言語ごとの参照の本文は、[言語ごとの全体像と UI の文字](overview-languages.ja.md)の[全体像は、言語の一覧の言語ごとに、その言語の側から書く](overview-languages.ja.md#全体像は言語の一覧の言語ごとにその言語の側から書く)と[ほかの言語のページでは、参照の本文をそのページの言語の側の決定の文書から取る](overview-languages.ja.md#ほかの言語のページでは参照の本文をそのページの言語の側の決定の文書から取る)で決める。

## overview build は、毎回すべてを描き、中身の違うファイルだけを書き、作られなくなったファイルを消す

状態: 実装済み

### 問題

全体像は、一覧と、全体像の文書ごとのページを持つ。全部を1つのファイルにまとめると、規模が大きくなったときに扱いにくく、変わったファイルだけを出し直すこともできない。一方で、一覧はすべての文書に依存し、参照先の決定が変わると多くのページが変わるので、変わった元データだけからは、出し直すページを正しく決められない。

描いた HTML は、元データから決まった描画でいつでも作り直せる。コミットすると二重に管理することになり、GitHub で HTML を開いても描画されない。ページを分け、見た目を1か所で揃えたい。名前の重なる元データを誤りにする理由は残っていない。

消す範囲を落とすと、置き場の下に元データから作ったのでないファイルがあるとき、それを消すかどうかが決まらない。置き場の下のファイルをすべて build が作ったものとみなす理由は、記録に残っていない。

### 決めたこと

"kotowari overview build" は、すべての全体像の元データを毎回メモリの中で描き、出来上がった中身が既にあるファイルと違うものだけを書き直す。もう作られないページのファイルは消す。描画を省くための依存関係の記録は持たず、状態を持たずに済ませる。

".kotowari/cache/overview/" の下のファイルは、すべて build が作ったものとして扱う。今回の build が作らなかったファイルは、元データから作ったものでなくても消す。

書く先は、基準のディレクトリの ".kotowari/cache/overview/" で、描いた HTML はコミットしない。一覧を "index.html"、全体像ごとのページを元データと同じ名前の "<話題>.html"、スタイルを共通の "style.css" の1つにして各ページから参照する。

ファイル名から ".md" を除いた名前がほかの元データと同じ元データと、その名前が "index" か "style" の元データは、check と status が overview_name_conflict の誤りにする。

### 見送った案

- 描いた HTML もコミットする。元データからいつでも作り直せるので、二重に管理することになる。
- 一覧とすべてのページを1つの HTML にまとめて、標準出力に出す。規模が大きくなると扱いにくく、変わったファイルだけを出し直せない。
- 元データごとの依存関係を記録して、描画を省く。出し直すページを正しく決められない。

### 確認すること

- C-core-ovcmd-1 1回目の "kotowari overview build" は、".kotowari/cache/overview/" の下に "index.html"、元データごとの "<話題>.html"、"style.css" を書く
- C-core-ovcmd-2 2回目の build は、中身の変わったページだけを書き、変わらないページを書き直さない
- C-core-ovcmd-3 元データを消してから build すると、そのページのファイルが消える
- C-core-ovcmd-24 名前の同じ2つの元データと、名前が "index" か "style" の元データには、check が overview_name_conflict の誤りを出す
- C-core-ovcmd-25 ".kotowari/cache/overview/" の下に元データから作ったのでないファイル（"stray.txt"）があると、build はそれを消し、"removed" に出す

## 全体像のコマンドは、.kotowari/cache/overview の下のほかに書かず、消さない

状態: 実装済み

### 問題

kotowari は標準出力と標準エラーのほかに書き出さないが、全体像を作るコマンドだけは例外にした（[kotowari は状態を保存せず、標準出力と標準エラーのほかに書き出さない](cli-scope.ja.md#kotowari-は状態を保存せず標準出力と標準エラーのほかに書き出さない)）。書く先を固定して、設定次第で書き出し先が変わらないようにし、何も書かないという保証の穴を最小にしたい。

### 決めたこと

"kotowari overview build" と "kotowari overview serve" は、基準のディレクトリの ".kotowari/cache/overview/" の下のほかにファイルを書かず、消さない。書く先を設定で変えられるようにしない。

### 確認すること

- C-core-ovcmd-4 "kotowari overview build" は、".kotowari/cache/overview/" の下のほかにファイルを書かず、置き場の中のシンボリックリンクを辿って外にも書かない

## 置き場かその上がシンボリックリンクかディレクトリでなければ、何も書かずに cache error で停止する

状態: 実装済み

### 問題

全体像の置き場か、その上のディレクトリがシンボリックリンクだと、書き込みと削除がリンクの先、つまり基準のディレクトリの外に届く。レビューで、実際に外のファイルが消えた。シンボリックリンクは、複製したリポジトリにコミットできる。置き場に書けないときに、読めないファイルとして止めると、読みの失敗と取り違える（停止の理由は[停止の理由は、英語の固定の文言で示す](cli-environment.ja.md#停止の理由は英語の固定の文言で示す)で決める）。

### 決めたこと

"kotowari overview build" と "kotowari overview serve" は、基準のディレクトリの ".kotowari"、".kotowari/cache"、".kotowari/cache/overview" のどれかがシンボリックリンクか、ディレクトリでない別の種類のファイルなら、ファイルを1つも書かず消さずに、置き場の誤り（cache error）を理由に停止する。詳細は、そのパスにする。

置き場の作成、その下のファイルの列挙、ファイルの書き込み、削除に失敗したときも、置き場の誤りを理由に停止し、詳細をそのパスと OS の誤りの文にする。置き場の作成・書き込み・削除の失敗と、列挙の失敗を、同じ理由に揃える。

### 確認すること

- C-core-ovcmd-5 ".kotowari/cache/overview" かその上が、外のディレクトリへのシンボリックリンクなら、build は cache error で停止し、外のディレクトリの中身を変えない
- C-core-ovcmd-6 置き場かその上がディレクトリでないファイルなら、build は cache error で停止し、そのファイルを変えない
- C-core-ovcmd-7 置き場の下を列挙できないときと、ファイルを書けないときは、build が cache error で停止し、詳細にそのパスと OS の誤りの文が出る

## 元データか目次に誤りがあれば、何も書かずに overview error で停止する

状態: 実装済み

### 問題

壊れたページを半分だけ出すより、止めて直させたい。誤りの中身は check が出すので、build が同じものを二重に出す必要は無い。

元データか目次の対の側が欠けているか、骨組みが食い違っていると、ほかの言語のページをその言語の側から描けない。この停止を落とすと、そのまま書き出しうる。serve の検査、ポートの確保、書き込みの順を落とすと、誤りのある元データで先にポートの誤りが出たり、ポートを使えないのに置き場を書いたりしうる。順を決めた理由は、記録に残っていない。

### 決めたこと

全体像の元データか目次に、check が出す誤りが1件以上あるとき、"kotowari overview build" と "kotowari overview serve" はファイルを1つも書かず消さずに、元データの誤り（overview error）を理由に停止する。詳細は、誤りの件数と "kotowari check" で詳しく見られる案内にする（"overview error: 3 errors in overview data; run kotowari check" の形）。誤りの中身は build では出さない。

全体像の元データか目次の対に、translation_missing か translation_structure_mismatch の誤りがあるときも、同じく何も書かずに overview error で停止する。

"kotowari overview serve" は、元データの検査、ポートの確保、書き込みの順に行う。元データに誤りがあれば、ポートを確保する前に止まる。ポートを確保できなければ、置き場に何も書かずに止まる。

目次の誤りの中身と、目次の誤りでも止まることは、[全体像の目次](overview-toc.ja.md)の[全体像のページは、目次にちょうど1回ずつ置く](overview-toc.ja.md#全体像のページは目次にちょうど1回ずつ置く)で決める。止まるときの理由と詳細は、この決定のとおりにする。

### 確認すること

- C-core-ovcmd-8 誤りのある元データで "kotowari overview build" を実行すると、終了コード2、標準エラーの1行目が "overview error: <件数> errors in overview data; run kotowari check" で止まり、置き場のファイルの一覧と中身が実行の前と変わらない
- C-core-ovcmd-9 誤りのある元データで "kotowari overview serve" を実行すると、build と同じく overview error で止まる
- C-core-ovcmd-26 言語が2つ以上で、目次の対の側どうしの骨組みが食い違うと、"kotowari overview build" は終了コード2で止まり、置き場を作らない
- C-core-ovcmd-27 誤りのある元データで、指定のポートがほかのプロセスに使われているとき、serve は port error でなく overview error で止まる
- C-core-ovcmd-28 ポートが使えずに serve が止まるとき、".kotowari/cache/" は作られない

## overview build は、書いたファイル、消したファイル、書かなかったファイルの数を出す

状態: 実装済み

### 問題

build を実行した LLM が、何が変わったかを確かめられるようにしたい。

### 決めたこと

"kotowari overview build" は、書き終えたとき、"--format"（既定は json、ほかに text）に従って、書き直したファイル（written）、消したファイル（removed）、変わらなかったファイルの数（unchanged）を出す。パスは基準のディレクトリからの相対にする。json は "written"、"removed"、"unchanged" の鍵を持つ JSON にし、text は1つのファイルを1行で出す。

### 確認すること

- C-core-ovcmd-11 "kotowari overview build --format json" は、"written"、"removed"、"unchanged" の鍵を持つ JSON を出し、パスは基準のディレクトリからの相対になる
- C-core-ovcmd-12 "--format text" では、書いたファイルと消したファイルが1行に1つずつ出る

## 参照の表には、参照ごとに参照先の本文を入れる

状態: 提案

### 問題

描画のエンジンは kotowari を知らず、決定の文書を読まない。参照を描くには、参照の文字列から表示名、本文、状態への対応（参照の表）を、kotowari の側が決定の文書を読んで作り、エンジンに渡す必要がある。また、kotowari はリポジトリの公開先を知らず、serve は全体像の置き場の下しか配らないので、ページの中の参照から、ページの外にある参照先へリンクを張れない。参照先の本文が見られれば足りる（描き方は[参照はページの外へリンクせず、選ぶとその場で本文を開く](../view/rendering.ja.md#参照はページの外へリンクせず選ぶとその場で本文を開く)）。

参照の状態は、予定を含めて見せることを、ページの上で見分けられるようにするためにある。新しい形では、覆した決定は消して見送った案に移すので「置き換え済み」の元が無く、後回しの宣言も無い。

### 決めたこと

"kotowari overview build" は、すべての全体像の元データの部品の中の参照の1つずつについて、表示名、本文、状態を持つ参照の表の1件を作り、描画のエンジンに渡す。参照先は決定の文書の決定か、確認することの行で（[全体像の元データは、決定の文書を指す](languages-and-guides.ja.md#全体像の元データは決定の文書を指す)）、本文には参照先の中身を入れる。エンジンは、表を引いて描くだけにする。

参照の表の状態は、参照先の決定の状態から決める。状態が「提案」の決定と、その確認することの行を指す参照は「後回し」にし、「実装済み」のものは「今のもの」にする。「置き換え済み」の状態の参照は作らない。

### 確認すること

- C-core-ovcmd-13 部品の参照ごとに、参照の表に1件が入り、同じ参照が何度出ても1件になる
- C-core-ovcmd-14 部品の参照が決定の見出しか確認することの ID を指すと、参照の表のその1件の本文に、参照先の中身が入る
- C-core-ovcmd-29 状態が「提案」の決定とその確認することの行を指す参照は、参照の表で後回しの状態になり、「実装済み」の決定とその行を指す参照は今のものの状態になり、置き換え済みの状態の参照は無い

## マーカーが古い節は、古い節として描画に渡す

状態: 実装済み

### 問題

全体像の節のうち、元になった決定が変わったあと、まだ見直していない部分を、読む人が見分けられるようにしたい。描画のエンジンは決定の文書を知らないので、古いかどうかは kotowari の側が計算して渡す。処理は効率よく行う。直す作業は実装のループではなく、次にその話題に触れた壁打ちが行う（[全体像を書く工程](overview-workflow.ja.md)の[cycle と実装は、全体像の元データを直さない](overview-workflow.ja.md#cycle-と実装は全体像の元データを直さない)）。

### 決めたこと

"kotowari overview build" は、全体像の元データの "## " の見出しの節ごとに、その節の中に guide_stale の注意を受けるマーカーが1件以上あれば、その節を古い節として描画のエンジンに渡す。マーカーがいつ古くなるかは、[全体像の元データは、決定の文書を指す](languages-and-guides.ja.md#全体像の元データは決定の文書を指す)で決める。

### 確認すること

- C-core-ovcmd-15 節の中に guide_stale を受けるマーカーがある節だけが、古い節として描画のエンジンに渡り、今の指紋のマーカーだけの節とマーカーの無い節は渡らない

## overview serve は、起動時に build と同じく書き、127.0.0.1 の1つのポートで置き場のファイルを配る

状態: 実装済み

### 問題

作った HTML を人が見るには、面倒な手順が要る。build と組で、見せるコマンドが欲しい。最小の作りで、閲覧の手間を無くしたい。作り直しは、serve の起動し直しか、別の build で反映できる。serve は閲覧のための入口で、出すべきものは URL だけである。

### 決めたこと

"kotowari overview serve" は、起動したときに "kotowari overview build" と同じ描画と書き込みを1回行い、".kotowari/cache/overview/" の下のファイルを、"127.0.0.1" の1つのポートで HTTP で配る。外のネットワークには公開しない。ポートの既定は "4590" で、"--port" で変えられる。

起動したら、標準出力に "http://127.0.0.1:<ポート>/" の URL の1行だけを出し、割り込み（Ctrl-C）まで配り続ける。リクエストごとのログは出さない。

### 確認すること

- C-core-ovcmd-16 "kotowari overview serve --port 4591" を起動すると、標準出力が "http://127.0.0.1:4591/" の1行だけになり、"/" と "/style.css" に置き場のファイルの中身が返る
- C-core-ovcmd-17 "--port" を付けなければ、serve はポート "4590" で配る
- C-core-ovcmd-18 割り込み（Ctrl-C）で serve が終わる

## overview serve のポートが使えなければ、ほかのポートを試さずに port error で停止する

状態: 実装済み

### 問題

ポートが使用中のときに、黙って別のポートに逃げると、示した URL と実際がずれる。また、使っている HTTP のクレートは、接続の受け付けに一度失敗すると受け付けを再開しないので、生きたまま何も配らなくなり、配り続けることを守れない。黙って固まるより、止めて知らせたい。

### 決めたこと

"kotowari overview serve" は、"127.0.0.1" の指定のポートを使えないとき、ほかのポートを試さずに、ポートの誤り（port error）を理由に停止する（終了コード2）。詳細は "127.0.0.1:<ポート>" と OS の誤りの文にする。配っている間に接続の受け付けに失敗したときも、同じくポートの誤りを理由に停止する。

### 見送った案

- 受け付けに失敗したら、サーバを作り直して続ける。

### 確認すること

- C-core-ovcmd-19 ほかのプロセスが使っているポートで serve を起動すると、終了コード2、標準エラーの1行目が "port error: 127.0.0.1:<ポート>" で始まって止まる
- C-core-ovcmd-20 配っている間に接続の受け付けに失敗すると、serve は port error で止まる

## overview serve は、置き場の外のファイルとディレクトリの一覧を返さない

状態: 実装済み

### 問題

serve は手元で全体像を見るためのサーバで、全体像の置き場の外を読ませない。リクエストの読み取りと、置き場の外のファイルを読ませない道の検査は安全に関わるので、自作せず、実績のあるクレートに任せる。

### 決めたこと

"kotowari overview serve" は、".kotowari/cache/overview/" の下のファイルだけを配る。その外を指すリクエストの道（".." の成分、絶対パス、シンボリックリンクを辿った先が外になるもの）には、外のファイルの中身を返さず、404 を返す。ディレクトリの一覧は返さない。HTTP のサーバには、小さな HTTP サーバのクレートを1つ使う。

### 見送った案

- 標準ライブラリだけで簡易サーバを自作する。リクエストの読み取りと道の検査は安全に関わる。

### 確認すること

- C-core-ovcmd-21 "/../config.yaml" と "/%2e%2e/config.yaml" のリクエストには 404 が返り、置き場の外のファイルの中身は返らない
- C-core-ovcmd-22 置き場の外を指すシンボリックリンク、ディレクトリ、絶対パスのリクエストには 404 が返る

## overview serve は、手元の Host のリクエストにだけ答える

状態: 実装済み

### 問題

serve は、外のサイトの名前で届いたリクエストを通さないようにしたい。出力する URL は "127.0.0.1" だが、手で "localhost" と打つ人もいる。どちらも手元の名前で、外のサイトの名前を通さないことが目的に足りる。

### 決めたこと

"kotowari overview serve" は、Host ヘッダーの値が "127.0.0.1:<ポート>" か "localhost:<ポート>"（ポートは待ち受けているもの、名前の英字の大小は問わない）のリクエストだけに答える。それ以外のリクエスト（Host ヘッダーが無いものを含む）には、ファイルがあるかどうかを確かめる前に、本文の無い 403 を返し、リクエストごとに何も出力しない。同じ応答にすれば、置き場にどんなファイルがあるかも外に漏れない。

### 見送った案

- "127.0.0.1:<ポート>" だけに答える。手で localhost と打つと開けない。
