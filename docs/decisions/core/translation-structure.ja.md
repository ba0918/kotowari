# 対の骨組みと切り替えの行とリンク

[English](translation-structure.md) | 日本語

対の側どうしで一致しなければならない骨組み、対の各側に置く切り替えの行、対の側の中のリンクの検査、対を揃える LLM の手順を扱う。言語の一覧、対の側の見分け方、一致の記録は[対の読み方と一致の記録](translation-pairs.ja.md)で決める。

## 対の側どうしは、自然言語の文のほかの骨組みが一致しなければならない

状態: 実装済み

### 問題

対のどの言語も対等とし、どの言語で先に書いてもよいことにした。そのためには、訳しても変わらないもの（自然言語の文のほか）が、どの側でも同じでなければならない。文のほかは訳しても変わらないので、機械で確かめられる。意味が同じかは機械では確かめられないので、レビューで確かめる。

リンクの行き先の "#" より後は、見出しの文から作られることが多く、訳すと変わる。目次は群の題名という文を持ち、言語ごとの全体像の一覧のページに要る。

### 決めたこと

対の側どうしでは、自然言語の文のほかがすべて一致しなければならない。一致しなければ、translation_structure_mismatch の誤りを、一致しない側に出す。意味が同じかは検査しない。

文書の種類ごとに、一致しなければならないものと、訳してよい文は次のとおりとする。決定の文書の骨組みは[決定の文書も、多言語の対で持てる](languages-and-guides.ja.md#決定の文書も多言語の対で持てる)で決める。

| 文書 | 一致しなければならないもの | 訳してよい文 |
|---|---|---|
| ガイド | 見出しの深さと並び、ガイドのマーカー、コードブロックの中身、表の行と列の数、リンクの行き先 | 見出しと本文の文、表のセルの文 |
| 全体像の元データ | 部品の種類と並び、部品の文でない欄、ガイドのマーカー | 部品の文の欄 |
| 全体像の目次 | 群の入れ子の形と、各項目が指す文書 | 群の題名と目次の題名 |

全体像の部品のどの欄が文かは、部品の種類（[部品の種類は、view が持つ8種の固定の一覧にする](../view/parts.ja.md#部品の種類はview-が持つ8種の固定の一覧にする)）ごとに決めておく。

リンクの行き先は、ほかの言語の側を指していれば、その対の先頭の言語の側を指すものと読み替えてから比べる。比べるのは行き先のパスだけで、"#" より後は比べない。アンカーが正しいかはレビューで見る。

切り替えの行は、骨組みに入れない。

### 確認すること

- C-core-pairstruct-1 ガイドの対の側どうしが、見出しと本文と表のセルの文だけで違うとき、check は translation_structure_mismatch を出さない
- C-core-pairstruct-2 ガイドの対の側どうしで、見出しの深さか並び、ガイドのマーカー、コードブロックの中身、表の行か列の数のどれかが違えば、check が translation_structure_mismatch の誤りを出す
- C-core-pairstruct-3 全体像の元データの対の側どうしで、部品の文の欄だけが違えば translation_structure_mismatch は出ず、部品の文でない欄（例えば status の部品の "state"）が違えば出る
- C-core-pairstruct-4 全体像の目次の対の側どうしで、群の題名と目次の題名だけが違えば translation_structure_mismatch は出ず、群の入れ子か項目の指す文書が違えば出る
- C-core-pairstruct-5 リンクの行き先が、相手の側ではその言語の側を指し、"#" より後だけが違うときは translation_structure_mismatch が出ず、行き先のパスが違えば出る

## ガイドの対の各側は、題名の直後に切り替えの行を持つ

状態: 実装済み

### 問題

GitHub で開かれるのは、接尾辞の無い先頭の言語の側である。ほかの言語の側へのリンクが無いと、ほかの言語の読み手が自分の言語の側へ辿り着けない。読めない言語の文書に来た読み手でも、自分の言語の名前なら見つけられる。全体像の元データは題名のあとに部品と HTML のコメントしか置けず、目次は YAML で題名が無い。どちらも人が GitHub で開くものではなく、描いたページには言語のリンクが付く。

### 決めたこと

ガイドの対の各側は、題名の直後の行に、すべての言語を並べた切り替えの行を持つ。自分の言語は文字だけでリンクにせず、ほかの言語はその言語の側へのリンクにする。言語の名前は、その言語自身で書き、設定の UI の文字（"labels.<言語タグ>" の "language_name"。[UI の文字は、英語を kotowari が持ち、ほかの言語は設定の labels に書く](overview-languages.ja.md#ui-の文字は英語を-kotowari-が持ちほかの言語は設定の-labels-に書く)）から取る。全体像を使わないプロジェクトでも、言語の一覧の英語のほかの言語には "labels.<言語タグ>" を書く。

切り替えの行が無いか、形が違うか、指す先が違えば、translation_switcher_invalid の誤りを出す。全体像の元データと目次の対は、切り替えの行を持たない。

切り替えの行は、骨組みの比較と、[リンクの言語の検査](#ガイドと全体像の元データの中のリンクは同じ言語の側を指す)から外す。

### 見送った案

- 言語の名前だけを "languages" の側に持ち、UI の文字は全体像の設定の下に残す。UI の文字の置き場が2つに割れる。

### 確認すること

- C-core-pairstruct-6 ガイドの対の各側の題名の次の行が正しい切り替えの行なら、check は translation_switcher_invalid を出さない
- C-core-pairstruct-7 ガイドの対の側の題名の次の行が切り替えの行でなければ、check がその側に translation_switcher_invalid の誤りを出す
- C-core-pairstruct-8 全体像の元データの対には、題名の次が切り替えの行でなくても、check は translation_switcher_invalid を出さない
- C-core-pairstruct-9 切り替えの行の中のリンクは、側どうしで数が合わなくても translation_structure_mismatch にならず、ほかの言語の側を指していても link_language_mismatch にならない

## 決定の文書の対の各側も、題名の直後に切り替えの行を持つ

状態: 実装済み

### 問題

決定の文書も、GitHub で開かれるのは接尾辞の無い先頭の言語の側である。ほかの言語の側へのリンクが無いと、ほかの言語の読み手が自分の言語の側へ辿り着けない。

話題の文書は、題名と、その話題が何を扱うかの段落で始める（[1つの決定は、問題・決めたこと・見送った案・確認することの文章で書く](decision-documents.ja.md#1つの決定は問題決めたこと見送った案確認することの文章で書く)）。切り替えの行をその段落に数えると、段落の無い文書が誤りにならない。

### 決めたこと

決定の文書の対の各側も、[ガイドの対と同じ切り替えの行](#ガイドの対の各側は題名の直後に切り替えの行を持つ)を題名の直後に持つ。無いか、形が違うか、指す先が違えば、translation_switcher_invalid の誤りを出す。

切り替えの行は、題名と話題の段落の間に置く。題名のあとの段落の検査は、切り替えの行を飛ばして、その次の段落を見る。切り替えの行だけで話題の段落が無ければ、話題の段落が無い誤り（topic_lead_missing）にする。

### 確認すること

- C-core-pairstruct-10 決定の文書の対の側の題名の次の行が正しい切り替えの行でなければ、check がその側に translation_switcher_invalid の誤りを出す
- C-core-pairstruct-16 決定の文書の対の両方の側が、題名と切り替えの行のあとに話題の段落を持たなければ、check は topic_lead_missing の誤りを出し、切り替えの行を話題の段落として数えない

## ガイドと全体像の元データの中のリンクは、同じ言語の側を指す

状態: 実装済み

### 問題

ほかの言語の側へのリンクは、読み手を自分の読めない言語の文書へ落とす。リンクを書くのは LLM なので、決まりを書くだけでは同じリンクが戻ってくる。

### 決めたこと

ガイドと全体像の元データの対の各側で、切り替えの行の外にある Markdown のリンクを検査する。外の URL とページの中へのリンク（"#" で始まるもの）は検査しない。リンクの行き先が対の側で、その言語がリンクのある側の言語と違うとき、link_language_mismatch の誤りを出す。

### 確認すること

- C-core-pairstruct-11 英語のガイドの側から、ほかの対の日本語の側へのリンクがあると、check が link_language_mismatch の誤りを出す
- C-core-pairstruct-12 同じ言語の側へのリンク、外の URL へのリンク、"#" で始まるページの中へのリンクには、check は link_language_mismatch を出さない

## 決定の文書の中のリンクも、同じ言語の側を指す

状態: 実装済み

### 問題

決定の文書も、ほかの言語の側へリンクすると、読み手を自分の読めない言語の文書へ落とす。

### 決めたこと

決定の文書の対の各側のリンクにも、[ガイドと同じリンクの言語の検査](#ガイドと全体像の元データの中のリンクは同じ言語の側を指す)を行う。ガイドや全体像の元データから決定の文書の対の側へのリンクも、同じ言語の側を指さなければ link_language_mismatch の誤りにする。

### 確認すること

- C-core-pairstruct-13 決定の文書の対のある側から、同じ対のほかの言語の側へのリンクがあると、check がその側に link_language_mismatch の誤りを出す
- C-core-pairstruct-14 英語のガイドの側から、決定の文書の日本語の側へのリンクがあると、check が link_language_mismatch の誤りを出す

## 決定の文書とその対の側から、凍結した木へのリンクは誤りにする

状態: 提案

### 問題

切り替える前の古い形の文書（判断の記録と ADR を含む）は、凍結した木（"docs/frozen/"）へ移り、今の決まりの根拠として読まないものとして置く（[決定の文書は docs/decisions に置き、古い形の文書は凍結した木へ移す](decision-documents.ja.md#決定の文書は-docsdecisions-に置き古い形の文書は凍結した木へ移す)）。これまでは、文書から判断の記録と ADR の置き場へのリンクを、link_to_record の誤りにしていた。凍結した木へのリンクを誤りにする理由は、これのほかに記録に残っていない。

### 決めたこと

決定の文書の、先頭の言語の側とほかの言語の側のどちらからでも、凍結した木（"docs/frozen/"）の下を指すリンクは、check の誤りにする。

### 確認すること

- C-core-pairstruct-17 決定の文書の先頭の言語の側か、ほかの言語の側に、"docs/frozen/" の下の文書へのリンクがあると、check がその側に誤りを出す

## 対を揃える手順は、kotowari の skill が持つ

状態: 実装済み

### 問題

対の側を書き、直すのは LLM である。一致の記録の blob hash は git の blob hash なので、その中身が一度も git に入っていなければ、前の文を取り出せない。

### 決めたこと

kotowari の skill に、対を揃える手順を書く。対のどれかの側を直したら、同じ変更でほかのすべての側も直す。直すときは、一致の記録の blob hash から前の文を git で取り出し、差分だけを訳す。取り出せなければ、相手の側を全文から訳し直す。直したあと、"kotowari list" の "translations" の値で一致の記録を書き直す。"languages" に英語のほかの言語を足すときは、"labels.<言語タグ>" を書く。

### 確認すること

- C-core-pairstruct-15 （読んで確認）kotowari の skill に、対のどれかの側を直したら同じ変更でほかのすべての側を直すこと、一致の記録の blob hash から前の文を git で取り出して差分だけを訳し、取り出せなければ全文から訳し直すこと、直したあと "kotowari list" の "translations" の値で一致の記録を書き直すこと、"languages" に英語のほかの言語を足すときは "labels.<言語タグ>" を書くことが書いてある
