# コマンドと終了

[English](cli.md) | 日本語

kotowari のコマンド、コマンドごとに受けるオプション、引数の誤り、停止したときの出力、終了コードを扱う。"--help" と "--version" の扱いと、停止の理由の文言と詳細は[使い方の表示と対象の環境](cli-environment.ja.md)の話題（[停止の理由は、英語の固定の文言で示す](cli-environment.ja.md#停止の理由は英語の固定の文言で示す)ほか）で、設定ファイルの場所と "--config" の読み方は[設定ファイルは基準のディレクトリの .kotowari/config.yaml に置き、--config で別のファイルを指せる](config.ja.md#設定ファイルは基準のディレクトリの-kotowariconfigyaml-に置き--config-で別のファイルを指せる)で決める。

## kotowari のコマンドは7つで、check の1つで仕様の検査とテストとの対応の検査を両方行う

状態: 実装済み

### 問題

kotowari を作り始めたときは、コマンドを check の1つに絞り、人向けの文書の生成、影響範囲の追跡、計画と実装のループへの受け渡しは作らないとした。

そのあと、コマンドを必要になった分だけ足した。仕様とマーカーとテストの対応は check がすでに組み立てていて、それを読める形で出すのは同じデータの別の切り口であり、新しい状態も外部依存も増えない。そこで、読み取りのコマンド（list、query、status）を足した。変異テストの結果は、check に混ぜると、push の前に毎回0件を求められる check が、古い結果のファイルのずれた行を指したまま push を止める。変異テストは十数分かかり毎回は回せないので、結果を読む別のコマンドにし、どの結果を読んだかを引数で明示する。計画書は、check が位置引数を受けないことと、計画書の指摘が status の完了の判定に響くことから、ファイルを1つ受ける別のコマンドにした。全体像は、作った HTML を人が見るのに手間がかかるので、作るコマンドと見せるコマンドを組にした。壁打ちの承認から呼ぶので、別のツールを入れさせず、kotowari の1つのバイナリの下位のコマンドにした。

### 決めたこと

kotowari のコマンドは、"kotowari check"、"kotowari list"、"kotowari mutants"、"kotowari plan"、"kotowari query"、"kotowari status"、"kotowari overview" の7つだけにする。"kotowari check" の1つのコマンドで、仕様の文書の検査と、テストとの対応の検査を両方行う。

"kotowari overview" は、静的な HTML を作る "build" と、作ってから簡易サーバを立てて見せる "serve" の2つの下位のコマンドを持つ（振る舞いは[全体像を作るコマンドと見せるコマンド](overview-commands.ja.md)）。

### 見送った案

- 変異テストの結果を check に混ぜ、設定のキーで結果のファイルを指す。古い結果のファイルを check が読むと、ずれた行を指したまま push を止める。
- 影響範囲の追跡（trace）を独立のコマンドにする。list の出力に含まれる情報と同じである。
- 計画書の置き場を check の設定に足し、仕様と一緒に検査する。pre-commit で自動で回るが、計画書の指摘が status の完了の判定に響き、広がりすぎる。
- 全体像のコマンドを "kotowari render" か "kotowari generate" にする。採らなかった理由は残っていない。

### 確認すること

- C-core-cli-1 7つのコマンド（"overview" は "build" と "serve"）はどれもコマンドとして動き、ほかの語（"mutate"）を1つ目の位置引数にすると引数の誤りで停止する

## コマンドごとに受けるオプションを決め、オプションと位置引数はどの順に書いてもよい

状態: 実装済み

### 問題

第一の使い手は LLM なので、出力の形は "--format" で選ばせる。コマンドが受けるオプションを決めておかないと、効かないオプションを付けた人が、効いていると誤解する。"kotowari plan" は設定を読まないので、"--config" を受けて黙って無視すると、付けた人が効いていると思い込む。"kotowari overview serve" は閲覧のための入口で、出すのは URL だけなので "--format" を受けない。

位置引数を取るのは query、mutants、plan で、query だけが順を問われるのは覚えにくい。

### 決めたこと

コマンドごとに、受けるオプションを次の表のとおりにする。表に無いオプションは、そのコマンドでは受けない（[受けないオプション、知らないコマンド、余計な位置引数、値の誤ったオプションは、引数の誤りで停止する](#受けないオプション知らないコマンド余計な位置引数値の誤ったオプションは引数の誤りで停止する)）。

| コマンド | 受けるオプション |
|---|---|
| check | "--format"、"--config"、"--help"、"--version"、"--allow-test-findings" |
| list、query、status | "--format"、"--config"、"--help"、"--version" |
| mutants | "--tool"、"--format"、"--config"、"--help"、"--version" |
| plan | "--format"、"--help"、"--version" |
| overview build | "--format"、"--config"、"--help"、"--version" |
| overview serve | "--port"、"--config"、"--help"、"--version" |

"--allow-test-findings" の振る舞いは[check に --allow-test-findings を付けると、テスト側の指摘を終了コードに数えない](test-side-findings.ja.md#check-に---allow-test-findings-を付けるとテスト側の指摘を終了コードに数えない)、"--tool" は[kotowari mutants は道具の名前を --tool で必ず受け、結果のファイルをちょうど1つ受ける](#kotowari-mutants-は道具の名前を---tool-で必ず受け結果のファイルをちょうど1つ受ける)で決める。

どのコマンドでも、オプションはコマンドの前にも後にも書け、位置引数とオプションの順も問わない。

### 確認すること

- C-core-cli-2 check、list、query、status、mutants、plan、overview build のオプションは、コマンドの前にも、コマンドの後にも、位置引数の後にも書ける
- C-core-cli-3 check は "--allow-test-findings" を、コマンドの前にも後にも受ける

## 受けないオプション、知らないコマンド、余計な位置引数、値の誤ったオプションは、引数の誤りで停止する

状態: 実装済み

### 問題

kotowari は、読めない入力や契約に合わない入力を黙って通さない（[読めない入力と壊れた入力は、停止か誤りの指摘にし、黙って読み飛ばさない](cli-environment.ja.md#読めない入力と壊れた入力は停止か誤りの指摘にし黙って読み飛ばさない)）。引数も同じで、受けないものを黙って無視すると、付けた人が効いていると誤解する。引数の誤りのそれぞれを、なぜ停止にしたかの理由は、ほかには残っていない。

### 決めたこと

"--help" も "--version" も無いとき（あるときは[--help と --version は、ほかの引数より先に受け、使い方か版を出して終わる](cli-environment.ja.md#--help-と---version-はほかの引数より先に受け使い方か版を出して終わる)）、次のどれかに当たれば、kotowari は引数の誤りを理由に停止する。

| 引数の誤り | 例 |
|---|---|
| 引数が1つも無い。オプションだけがあって、1つ目の位置引数が無い | "kotowari"、"kotowari --format text" |
| 1つ目の位置引数が、7つのコマンドのどれでもない | "kotowari foo" |
| 知らないオプション | "kotowari check --verbose" |
| そのコマンドが受けないオプション（前の決定の表に無いもの） | "mutants" でないコマンドの "--tool"、"overview serve" でないコマンドの "--port"、"overview serve" の "--format"、"check" でないコマンドの "--allow-test-findings"、"plan" の "--config" |
| 値を取るオプションに値が無い。同じオプションが2回ある。"--format" の値が知らない値 | "kotowari check --format"、"kotowari check --format xml" |
| "--config" の指す先が無いか、ディレクトリである | "kotowari check --config ." |
| "check"、"list"、"status" の後に位置引数がある | "kotowari check extra" |
| "overview" の後の位置引数が、"build" か "serve" のちょうど1つでない。"--port" の値がポート番号として読めない | "kotowari overview"、"kotowari overview serve --port x" |

"mutants" の引数の誤りは[kotowari mutants は道具の名前を --tool で必ず受け、結果のファイルをちょうど1つ受ける](#kotowari-mutants-は道具の名前を---tool-で必ず受け結果のファイルをちょうど1つ受ける)で決める。"query" の位置引数の誤りは[位置引数がちょうど1つの ID でないか、その ID が無ければ、引数の誤りで停止する](query.ja.md#位置引数がちょうど1つの-id-でないかその-id-が無ければ引数の誤りで停止する)で、"plan" の位置引数の誤りは[kotowari plan は設定を読まず、引数と読めないファイルの扱いを mutants に揃える](plan.ja.md#kotowari-plan-は設定を読まず引数と読めないファイルの扱いを-mutants-に揃える)で決める。

### 確認すること

- C-core-cli-4 知らないオプション（"--verbose"）を付けると、引数の誤りで停止する
- C-core-cli-5 1つ目の位置引数が7つのコマンドのどれでもないと、引数の誤りで停止する
- C-core-cli-6 引数が1つも無いときと、オプションだけで1つ目の位置引数が無いときは、引数の誤りで停止する
- C-core-cli-7 そのコマンドが受けないオプション（"check"、"list"、"query"、"status"、"plan" の "--tool"、"overview build" の "--port"、"overview serve" の "--format"、"check" でないコマンドの "--allow-test-findings"）を付けると、引数の誤りで停止する
- C-core-cli-8 値の無いオプション、同じオプションの2回目、"--format" の知らない値は、引数の誤りで停止する
- C-core-cli-9 "--config" の指す先が無いか、ディレクトリであれば、引数の誤りで停止する
- C-core-cli-10 "check"、"list"、"status" の後に位置引数があると、引数の誤りで停止する
- C-core-cli-11 "overview" の後の位置引数が "build" か "serve" のちょうど1つでないときと、"--port" の値がポート番号として読めないときは、引数の誤りで停止する

## kotowari mutants は道具の名前を --tool で必ず受け、結果のファイルをちょうど1つ受ける

状態: 実装済み

### 問題

どの道具の結果かを "--tool" で必ず指定させることと、その理由と見送った案は、[変異の結果は道具を知らない形で持ち、cargo-mutants の結果のファイルを表のとおりに写す](mutants-input.ja.md#変異の結果は道具を知らない形で持ちcargo-mutants-の結果のファイルを表のとおりに写す)で決める。ここでは、その引数を受けられないときの扱いを決める。

結果のファイルのパスは、"--config" と同じ読み方にそろえる。

### 決めたこと

"kotowari mutants" は、どの道具の結果かを "--tool" で必ず受ける。今受ける値は "cargo-mutants" だけである。"--tool" が無いとき、値が "cargo-mutants" でないときは、引数の誤りで停止する。

"mutants" の後の位置引数は、結果のファイルのパスをちょうど1つ受ける。0個か2個以上なら、引数の誤りで停止する。パスは、カレントディレクトリからの相対パスとして読む。結果のファイルが形に合わないときの停止（results error）は、[形の合わない結果のファイルでは、結果の誤りで停止する](mutants-input.ja.md#形の合わない結果のファイルでは結果の誤りで停止する)で決める。

### 確認すること

- C-core-cli-12 "kotowari mutants" で "--tool" が無いとき、"--tool" の値が "cargo-mutants" でない（"stryker"）ときは、引数の誤りで停止する
- C-core-cli-13 "kotowari mutants" の後の位置引数が0個か2個以上なら、引数の誤りで停止する

## 停止するときは、標準出力に何も出さず、標準エラーの1行目に理由と詳細を出す

状態: 実装済み

### 問題

停止は、検査の結果ではなく、kotowari が動けなかったことを表す。理由は残っていない。

### 決めたこと

停止するとき、kotowari は標準出力に何も出さず、停止の理由を標準エラーに出す。標準エラーの1行目は、停止の理由の文言、": "、詳細をこの順につないだ形にする（"argument error: unknown command: foo"）。

理由の文言は[停止の理由は、英語の固定の文言で示す](cli-environment.ja.md#停止の理由は英語の固定の文言で示す)、詳細は[停止の詳細は、直す人が見るファイルを基準のディレクトリからの相対パスで示す](cli-environment.ja.md#停止の詳細は直す人が見るファイルを基準のディレクトリからの相対パスで示す)で決める。どの場面でどの理由で停止するかは、その場面を扱う話題で決める（引数の誤りはこの話題、設定の誤りと置き場が無いときは[設定](config.ja.md)の話題、読めない入力と UTF-8 でない入力は[読めない入力と壊れた入力は、停止か誤りの指摘にし、黙って読み飛ばさない](cli-environment.ja.md#読めない入力と壊れた入力は停止か誤りの指摘にし黙って読み飛ばさない)）。

### 確認すること

- C-core-cli-14 停止するとき、標準出力には何も出ず、標準エラーの1行目は「理由の文言: 詳細」の形になる

## 終了コードは、誤りが無ければ0、誤りがあれば1、停止したら2にする

状態: 実装済み

### 問題

kotowari の結果をゲートに使う側は、終了コードで、通すか止めるかを決める。注意は、終了コードを変えない指摘である。終了コードの値をこう決めた理由は残っていない。

### 決めたこと

終了コードは、次の表のとおりにする。

| 終了コード | 場面 |
|---|---|
| 0 | 誤りが無い（注意だけのときを含む）。"--allow-test-findings" を付けた check で、誤りがすべてテスト側の指摘である。"--help" か "--version" で終わった |
| 1 | 誤りが1件以上ある。"--allow-test-findings" を付けた check では、テスト側の指摘でない誤りが1件以上ある |
| 2 | 停止した |

### 確認すること

- C-core-cli-15 誤りが1件以上あれば終了コード1で、注意だけなら終了コード0で終わる
- C-core-cli-16 停止したときは、終了コード2で終わる

## 仕様の文書から構成と中身を写した、人向けの文書は生成しない

状態: 実装済み

### 問題

仕様から機械的に写した人向けの文書は、情報が足りずに読みにくく、仕様と二重に保つことになる。作り始めたときは、人向けの文書を生成するコマンド（render）を作らないと決めていた。そのあと全体像を作ることにしたが、全体像は LLM が書いた元データを描くもので、仕様を写さない。この禁止の意図は、全体像でも保つ。

### 決めたこと

kotowari は、仕様の文書（[仕様は、話題ごとの、今有効な決定の文書だけで持つ](decision-documents.ja.md#仕様は話題ごとの今有効な決定の文書だけで持つ)）から構成と中身を写した、人向けの文書を生成しない。全体像は、LLM が書いた全体像の元データ（[全体像の元データ](overview-data.ja.md)）を描くもので、これに当たらない。

### 見送った案

- 全体像を作るときに、この禁止を消す。仕様を機械的に写さない、という判断まで消える。

### 確認すること

- C-core-cli-17 "render" を1つ目の位置引数にすると、引数の誤りで停止する
