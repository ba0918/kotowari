# 文書の読み方と文書全体の検査

[English](ir-document.md) | 日本語

決定の文書の置き場からどのファイルを読むか、1つの文書の題名と、題名のあとの段落をどこまで見るか、行の数え方、行数と要求の数の上限の注意を無くすこと、コードブロックの中の扱いを扱う。置き場そのものが無いときの停止は設定の話題の[決定の文書の置き場が無いか、ディレクトリでないか、読めなければ、読めないファイルで停止する](config.ja.md#決定の文書の置き場が無いかディレクトリでないか読めなければ読めないファイルで停止する)で、先頭の BOM と閉じないコードブロックは[文字コードとコードブロックの境界](ir-input.ja.md)で決める。

## 決定の文書の置き場は深さに制限なく辿り、小文字の .md のファイルだけを読む

状態: 実装済み

### 問題

置き場をどう分けるかは、要件による。概念の多い領域は深く、単純なものは浅く分けたい。辿る深さに制限があると、分け方が道具の都合で決まる。

一方で、読まない入力は列挙したものだけにし、黙って飛ばさない（[読めない入力と壊れた入力は、停止か誤りの指摘にし、黙って読み飛ばさない](cli-environment.ja.md#読めない入力と壊れた入力は停止か誤りの指摘にし黙って読み飛ばさない)）。ディレクトリのシンボリックリンクは循環を作りうるので辿らない。ファイルのシンボリックリンクは循環を作らず、読まないと利用者が共有した文書が黙って消える。

ディレクトリでも通常のファイルでもないもの（ソケット、名前付きパイプ、デバイス）を読もうとすると、読み取りが返らずに check が固まりうる。読まないことにした理由のうち、記録に残っているのはこれだけである。

### 決めたこと

決定の文書の置き場の下のディレクトリを、深さに制限なく辿る。拡張子が小文字の ".md" のファイルだけを読み、".MD" のファイルは読まない。空のディレクトリには何も出さない。

隠しディレクトリとディレクトリのシンボリックリンクは、どの深さでも辿らない。ファイルのシンボリックリンクは読む。先の無いシンボリックリンクと、種類を取れない要素に出会ったときは、読めないファイル（unreadable file）を理由に停止する。ディレクトリでも通常のファイルでもないもの（ソケット、名前付きパイプ、デバイス）は、名前が ".md" で終わっても読まず、指摘も停止も出さない。

まとまりのフォルダに置く用語集 "CONTEXT.md" の扱いは、[用語集は人が読む文書として残し、用語の検査はやめる](decision-documents.ja.md#用語集は人が読む文書として残し用語の検査はやめる)で決める。

### 確認すること

- C-core-document-1 置き場の下のサブディレクトリを深さに制限なく辿って決定の文書を読み、空のディレクトリには何も出さない
- C-core-document-2 拡張子が大文字の ".MD" のファイルは読まない
- C-core-document-3 隠しディレクトリとディレクトリのシンボリックリンクの下の文書は、どの深さでも読まず、指摘も停止も出ない
- C-core-document-4 ファイルのシンボリックリンクは読み、先の無いシンボリックリンクがあれば、check は unreadable file を理由に停止する
- C-core-document-13 置き場の下に ".md" で終わる名前のソケットがあっても、check はそれを読まず、指摘も停止も出さずに、ほかの文書を読む

## 決定の文書の題名は1つにし、2つ目からの題名は multiple_titles の誤りにする

状態: 実装済み

### 問題

2つ目以降の "# " の題名を黙って読み飛ばすと、形に合わない入力を黙って通すことになる（[読めない入力と壊れた入力は、停止か誤りの指摘にし、黙って読み飛ばさない](cli-environment.ja.md#読めない入力と壊れた入力は停止か誤りの指摘にし黙って読み飛ばさない)）。指摘を読む人が知りたいのは、消すべき方の題名である。

### 決めたこと

決定の文書に題名が2つ以上あるときは、2つ目以降の題名ごとに1件の multiple_titles の誤りを出す。

題名が無い文書の扱いは、[1つの決定は、問題・決めたこと・見送った案・確認することの文章で書く](decision-documents.ja.md#1つの決定は問題決めたこと見送った案確認することの文章で書く)と、[題名の無い決定の文書の missing_title は、detail を文書名にする](findings.ja.md#題名の無い決定の文書の-missing_title-はdetail-を文書名にする)で決める。

### 確認すること

- C-core-document-5 題名が2つ以上ある決定の文書には、2つ目以降の題名ごとに multiple_titles の誤りが1件ずつ出る

## 題名のあとの段落は、あるかだけを見て、中身と行数と責務の分離は見ない

状態: 実装済み

### 問題

文書の責務の分離は、意味の判断である。粒度で大事なのは文量より、責務が分離できているかで、分離できていないから決めることが増え、文量が膨らむ。CLI が見られるのは、文書が何を扱うかが書いてあることまでである。分離そのものは、問題を探すレビューで、その文書の範囲の外のことが混じっていないかを問うて見る。

### 決めたこと

check は、題名のあとに話題が何を扱うかの段落があるかだけを見る（[1つの決定は、問題・決めたこと・見送った案・確認することの文章で書く](decision-documents.ja.md#1つの決定は問題決めたこと見送った案確認することの文章で書く)）。その段落の中身と行数は検査しない。文書の責務の分離は判定しない。

### 確認すること

- C-core-document-6 （読んで確認）check のコードが、題名のあとの段落があるかだけを見て、その中身と行数を検査せず、文書の責務の分離を判定していない

## kotowari は、"\n"、"\r\n"、単独の "\r" を、それぞれ1つの行の終わりに数える

状態: 実装済み

### 問題

kotowari は行番号を指摘に出す。文書を読む Markdown の読み取りは、CommonMark に合わせて単独の "\r" を行の区切りに数える。kotowari の側の数え方がこれと違うと、単独の "\r" を含む文書で2つの行番号がずれ、指摘の行や閉じないコードブロックの範囲がずれる（閉じないコードブロックより前の項目が落ちることを実測した）。テストのファイルだけ数え方が違っても、マーカーの行番号がずれる。

### 決めたこと

kotowari が行を数えるときは、"\n"、"\r\n"（1つの行の終わり）、単独の "\r" を、それぞれ1つの行の終わりに数える。最後の行に改行が無くても、その行を1行に数える。中身が空の文書は0行に数える。

この数え方は、kotowari が行番号を出すファイルのすべてに使う。決定の文書、テストのファイル、変異の結果のソース（[一覧の1件は、ファイル、変更の説明、行の文面で変異を同定する](equivalents.ja.md#一覧の1件はファイル変更の説明行の文面で変異を同定する)）が当たる。

### 確認すること

- C-core-document-7 行の区切りは、"\n"、"\r\n"、単独の "\r" をそれぞれ1つの行の終わりにし、"\r\n" を2行に数えず、最後の行に改行が無くてもその行を数える
- C-core-document-8 テストのファイルの行を "\r\n" か単独の "\r" で区切っても、マーカーへの指摘の行番号は区切ったあとの行になり、detail に "\r" が残らない
- C-core-document-9 決定の文書の行を単独の "\r" で区切っても、決定の文書への指摘の行番号は区切ったあとの行になる

## 決定の文書の確認することの本文と決定の指紋も、同じ行の数え方で取る

状態: 実装済み

### 問題

確認することの行の本文と、決定の「決めたこと」と「確認すること」の指紋を、単独の "\r" を行の区切りに数えない別の分け方で取ると、単独の "\r" で区切った文書では、query の本文が空になり、指紋が空の中身の指紋になる。指紋が空のままだと、決めたことを書き換えてもガイドが古いと出ない。

### 決めたこと

確認することの行の本文と、決定の指紋も、[kotowari は、"\n"、"\r\n"、単独の "\r" を、それぞれ1つの行の終わりに数える](#kotowari-はnrn単独の-r-をそれぞれ1つの行の終わりに数える)のとおりに分けた行から取る。状態の行も、同じ分け方で読む。

決定の文書の行数の合計を status に出すことは、[documents の群は、読んだ決定の文書の数と行数を数える](status.ja.md#documents-の群は読んだ決定の文書の数と行数を数える)で決める。

### 確認すること

- C-core-document-10 単独の "\r" で行を区切った決定の文書でも、確認することの行の本文（query の "body"）と決定の指紋が、"\n" で区切った同じ文書と同じになる
- C-core-document-14 単独の "\r" で行を区切った決定の文書でも、状態の行を読み、状態を数える

## 行数と要求の数の上限の注意 too_many_lines と too_many_requirements は無くす

状態: 提案

### 問題

古い形では、文書の行数が上限を超えると too_many_lines の注意を、要求の数が上限を超えると too_many_requirements の注意を出していた。決定の文書では行数の上限の注意を出さないことにし、要求の数の上限の注意も、要求が無くなるので無くす。理由は残っていない。

古い形の文書を読むコードは、まだこの2つの注意を出している。

### 決めたこと

check は、決定の文書の行数と決定の数がどれだけ多くても、too_many_lines と too_many_requirements の注意を出さない。この2つの指摘の種類は、古い形の文書を読むコードと一緒に無くす。上限を書く設定のキーを無くすことは、[行数と要求の数の上限のキー limits.lines と limits.requirements は無くす](config.ja.md#行数と要求の数の上限のキー-limitslines-と-limitsrequirements-は無くす)で決める。

### 確認すること

- C-core-document-11 行数が多く、決定の数の多い決定の文書にも、check は too_many_lines と too_many_requirements の注意を出さない

## 決定の文書のコードブロックの中は、決定の形としても引用としても読まない

状態: 実装済み

### 問題

決定の文書の中のコードブロックを、文書の形や検査の対象として読むかを決める必要があった。これまでの仕様の文書でも、コードブロックの中は検査の対象から外していた。理由は残っていない。

### 決めたこと

決定の文書のコードブロックの中は、検査の対象から外す。コードブロックの中の見出しは決定の見出しにせず、一覧の形の行は確認することの行にしない。面の名前の引用にも数えない（[面の名前が、決定の「決めたこと」か「確認すること」に引用されていれば、その面は仕様にある](surface.ja.md#面の名前が決定の決めたことか確認することに引用されていればその面は仕様にある)）。確認することの行の下に書いたコードブロックは、その行の名前に入れない。

閉じないコードブロックの扱いは、[閉じないコードブロックは unclosed_code_block の誤りにし、開始から文書の終わりまでを読まない](ir-input.ja.md#閉じないコードブロックは-unclosed_code_block-の誤りにし開始から文書の終わりまでを読まない)で決める。

### 確認すること

- C-core-document-12 コードブロックの中に書いた "## " の見出しと、確認することの形の行は、決定と確認することの行に数えない
- C-core-document-15 確認することの行の下に書いたコードブロックの中身は、list と query のその行の "name" に入らない
