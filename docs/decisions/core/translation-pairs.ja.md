# 対の読み方と一致の記録

[English](translation-pairs.md) | 日本語

文書を言語ごとの対で持つときに、言語の一覧をどう読むか、どの文書を対にし、対の側をどう見分けるか、欠けた側、一致の記録と blob hash、古い側、対を既にある検査でどう扱うかを扱う。側どうしで一致しなければならない骨組み、切り替えの行、リンクの検査は[対の骨組みと切り替えの行とリンク](translation-structure.ja.md)で決める。決定の文書を対で持つこと自体と、その骨組みは[決定の文書も、多言語の対で持てる](languages-and-guides.ja.md#決定の文書も多言語の対で持てる)で決める。

## 言語の一覧は、設定の languages で決める

状態: 実装済み

### 問題

文書を何語で持つかを決める場所が要る。言語はプロジェクトの性質で、全体像だけの設定ではない。走らせた人の環境（ロケールやエージェントの設定）で決めると、人や環境によって結果が変わる。

### 決めたこと

言語の一覧は、設定の最上位の "languages" の鍵に書く（例: `[en, ja]`）。一覧の最初の言語を先頭の言語とし、接尾辞の無いファイルを先頭の言語の側とする。鍵が無ければ、英語だけの1言語として扱う。

"languages" は1言語だけでもよい。言語が1つのときは対を読まず、対の検査をしない。日本語だけのプロジェクトも "languages: [ja]" と書けば、全体像の UI を日本語にできる（[UI の文字は、英語を kotowari が持ち、ほかの言語は設定の labels に書く](overview-languages.ja.md#ui-の文字は英語を-kotowari-が持ちほかの言語は設定の-labels-に書く)）。

### 見送った案

- 言語をエージェントの設定やロケールから決める。C.UTF-8 の環境のように利用者の言語を表さないことがあり、人ごとに変わる。

### 確認すること

- C-core-pairs-1 "languages" の言語が1つか、鍵が無いとき、check は対を読まず、translation_missing、translation_record_invalid、translation_stale、translation_structure_mismatch、translation_switcher_invalid、link_language_mismatch の指摘を出さず、言語タグの接尾辞の付いたファイル（例えば "a.en.md"）もただの文書として読む
- C-core-pairs-2 "languages" の鍵が無ければ、言語の一覧は英語の1つになり、鍵があれば書いた順の一覧になる

## 言語タグの形が違うか重なっていれば、停止する

状態: 実装済み

### 問題

言語タグは、ファイル名の接尾辞と設定の鍵に使われる。形の決まりを決めた理由は残っていない。

### 決めたこと

言語タグは、小文字の英字、数字、"-" だけからなる。"languages" に、空の文字列か、ほかの文字を含むタグがあるとき、または同じタグが2回以上あるとき、kotowari は設定の誤りで停止する。

### 確認すること

- C-core-pairs-3 "languages" に、空のタグ、大文字や "_" や空白を含むタグ、同じタグの重なりがあると、kotowari は設定の誤りで停止する

## ガイド、全体像の元データ、目次は、言語の一覧のすべての言語の側を持つ

状態: 実装済み

### 問題

外の人に読ませる文書には英語が要るが、利用者は英語が読めないので、文書は言語ごとに持つしかない。一部の文書だけに訳があると、読み手は途中で原語の文書に落ちる。書くのは LLM なので、全部を訳すのは手間の問題ではない。対が揃っていないことは、読み手が原語に落ちることに直結する。

### 決めたこと

言語が2つ以上のとき、ガイド、全体像の元データ、全体像の目次（"overview.toc" の指すファイル）を対として読む。決定の文書の対は[決定の文書も、多言語の対で持てる](languages-and-guides.ja.md#決定の文書も多言語の対で持てる)で、用語集の対は[用語集も対にする](#用語集も対にする)で決める。

対にする文書は、言語の一覧のすべての言語の側を持たなければならない。欠けた側があれば、translation_missing の誤りを出す。先頭の言語の側が無く、ほかの言語の側だけがあるときも、translation_missing の誤りにする。

### 見送った案

- 欠けた側を許し、注意にとどめる。少しずつ訳せるが、読み手が途中で原語に落ちる問題が残る。

### 確認すること

- C-core-pairs-4 先頭の言語の側があり、ほかの言語の側が無ければ、check が translation_missing の誤りを出す
- C-core-pairs-5 ほかの言語の側だけがあり、先頭の言語の側が無ければ、check が translation_missing の誤りを出す

## 対の側は、ファイル名と設定だけで見分ける

状態: 実装済み

### 問題

対の側を、言語のディレクトリを作らずに、同じディレクトリに並べて見せたい。どのファイルがどの対のどの言語の側かが、ファイル名と設定だけで一意に決まる必要がある。

### 決めたこと

対の側は同じディレクトリに置く。先頭の言語の側は接尾辞の無い名前（"foo.md"）、ほかの言語の側は拡張子の前に言語タグを入れた名前（"foo.en.md"、目次なら "toc.en.yaml"）にする。

ファイル名の接尾辞は、言語の一覧のうち先頭以外の言語タグのときだけ、対の側として読む。先頭の言語の接尾辞の付いた "foo.ja.md"（先頭が ja のとき）、一覧に無い言語の "foo.fr.md"、言語が1つのプロジェクトの "foo.en.md" は、どれもただの文書として読む。言語を一覧から外して残ったファイルにも、専用の指摘は作らない。間違った名前は、ほかの指摘で見つかる（例えば、対の側が欠けたことの translation_missing）。

### 確認すること

- C-core-pairs-6 先頭の言語のタグか、言語の一覧に無いタグの接尾辞を持つファイルは、対の側でなく、名前の一部として読まれ、そのファイルを先頭の言語の側とする対の、ほかの言語の側が無ければ translation_missing の誤りが出る

## 一致の記録は、最後に同じ中身だと確かめたときの各側の blob hash を持つ

状態: 実装済み

### 問題

対の側の片方だけが直されたことを、機械で見つけたい。最後に側どうしが同じ中身だと確かめたときの状態を、どこかに残す必要がある。記録を1か所にまとめると、別々のブランチで別々の対を直したときに衝突しやすい。git の blob hash で残せば、最後に一致を確かめたときの文を git から取り出して、差分だけを訳し直せる。

### 決めたこと

一致の記録は、先頭の言語の側の横に "<幹>.i18n.yaml" として置く。中身は、各言語の側のファイル名（ディレクトリを除いた名前）を鍵、その側の blob hash を値とする YAML の対応表である。どの側の hash かは、ファイル名で分かる。

blob hash は、git の blob hash（"git hash-object" がそのファイルに出す値と同じ、40文字の16進）とする。各側の今の blob hash は "kotowari list" が出し（[言語が2つ以上なら、対ごとの blob hash も出す](list.ja.md#言語が2つ以上なら対ごとの-blob-hash-も出す)）、LLM がそれを一致の記録に写す。kotowari は一致の記録を書き込むコマンドを持たない。これは、ガイドのマーカーの指紋を list が出して LLM が写す形と同じである。

一致の記録が無いとき、YAML として読めないとき、鍵の集まりが各言語の側のファイル名とちょうど一致しないとき、値が40文字の16進でないとき、translation_record_invalid の誤りを出す。

### 見送った案

- 一致の記録を1か所にまとめる。別々のブランチで別々の対を直すと衝突しやすい。

### 確認すること

- C-core-pairs-7 一致の記録の値が、すべての側の今の blob hash と同じなら、check は translation_stale も translation_record_invalid も出さない
- C-core-pairs-8 一致の記録が無いか、YAML として読めないか、鍵が各側のファイル名と違うか、値が40文字の16進でないとき、check が translation_record_invalid の誤りを出す
- C-core-pairs-9 kotowari がファイルの blob hash として使う値は、"git hash-object" がそのファイルに出す値と同じである
- C-core-pairs-10 （読んで確認）kotowari のコマンドに、一致の記録を書き込むものが無い

## 側を直して一致の記録を直していなければ、その側を古いとする

状態: 実装済み

### 問題

対の片方の側だけが直されたことを、機械で見つけたい。対が揃っていないことは、読み手が原語に落ちることに直結する。

### 決めたこと

ある側の今の blob hash が、一致の記録にあるその側の値と違うとき、その側に translation_stale の誤りを出す。

### 確認すること

- C-core-pairs-11 一致の記録を書いたあとで片方の側だけを直すと、check がその側に translation_stale の誤りを出す

## ガイドのマーカーの古さは、ガイドの対のどの側にも出す

状態: 実装済み

### 問題

対は、1つの文書の言語ごとの姿として扱う。ガイドのマーカーは骨組みに入るのでどの側にも同じものがあるが、ガイドの古さをどの側に出すかを決める必要があった。どの側にも出すと決めた理由は残っていない。

### 決めたこと

ガイドの対のすべての側をガイドとして読み、ガイドのマーカーの検査と guide_stale の注意を、どの側にも出す。

### 確認すること

- C-core-pairs-12 ガイドの対の両方の側に同じ古いマーカーがあると、check がそれぞれの側に guide_stale の注意を出す

## 全体像の元データのほかの言語の側は、別のページとして数えない

状態: 実装済み

### 問題

対は、1つの文書の言語ごとの姿として扱う。全体像の元データのほかの言語の側を別の元データとして数えると、同じ文書が2つのページとして名前の重なりや目次との照らし合わせにかかる。数えないと決めた理由は、ほかには残っていない。

### 決めたこと

全体像の元データと目次のほかの言語の側は、別の元データとして数えない。ページの名前の重なり（[overview build は、毎回すべてを描き、中身の違うファイルだけを書き、作られなくなったファイルを消す](overview-commands.ja.md#overview-build-は毎回すべてを描き中身の違うファイルだけを書き作られなくなったファイルを消す)）と、目次の名前の照らし合わせ（[全体像のページは、目次にちょうど1回ずつ置く](overview-toc.ja.md#全体像のページは目次にちょうど1回ずつ置く)）は、先頭の言語の側だけで行う。

### 確認すること

- C-core-pairs-13 全体像の元データ "a.md" と "a.en.md" があり、目次の名前の項目が "a" だけのとき、check は overview_name_conflict も overview_toc_page_missing も出さない

## 用語集も対にする

状態: 実装済み

### 問題

用語集は、人が読む文書として、決定の文書の置き場のまとまりのフォルダに置く。外の人に読ませる文書には英語が要るが、利用者は英語が読めないので、文書は言語ごとに持つしかない。用語集は、これまで IR の一部として対にしていた。用語集の中身は check が検査しない（[用語集は人が読む文書として残し、用語の検査はやめる](decision-documents.ja.md#用語集は人が読む文書として残し用語の検査はやめる)）。

### 決めたこと

言語が2つ以上のとき、決定の文書の置き場のまとまりのフォルダにある用語集 `CONTEXT.md` も対として読む。ほかの対と同じく、すべての言語の側（"CONTEXT.<言語タグ>.md"）と一致の記録を持ち、欠けた側、一致の記録の誤り、古い側を、ほかの対と同じ指摘で出す。

用語集の対では、側どうしの骨組みを比べず、側の中のリンクも検査しない。題名の直後の切り替えの行は、決定の文書の対と同じく求める。

### 確認すること

- C-core-pairs-14 言語が2つ以上のとき、決定の文書の置き場のまとまりのフォルダの `CONTEXT.md` に、ほかの言語の側か一致の記録が無ければ、check が translation_missing か translation_record_invalid の誤りを出す
- C-core-pairs-19 用語集の対の側どうしで見出しと表が違い、ほかの言語の側に無い文書へのリンクがあっても、check は translation_structure_mismatch もリンクの誤りも出さない

## 決定の文書の対は、数えることと出力を先頭の言語の側だけで行う

状態: 実装済み

### 問題

対は、1つの文書の言語ごとの姿として扱う。骨組みは[対の側どうしは、自然言語の文のほかの骨組みが一致しなければならない](translation-structure.ja.md#対の側どうしは自然言語の文のほかの骨組みが一致しなければならない)と[決定の文書も、多言語の対で持てる](languages-and-guides.ja.md#決定の文書も多言語の対で持てる)で一致が保証されるので、骨組みにかかる検査は片側で足りる。"kotowari query" と "kotowari list" の出力を読むのは LLM で、どの言語でも読める。

### 決めたこと

決定の文書の対では、確認することの ID の重なり、面が仕様に引用されているかの判定（[面の名前が、決定の「決めたこと」か「確認すること」に引用されていれば、その面は仕様にある](surface.ja.md#面の名前が決定の決めたことか確認することに引用されていればその面は仕様にある)）、"kotowari list" と "kotowari query" の出力を、先頭の言語の側だけで行う。確認することの ID とマーカーの照らし合わせを先頭の言語の側だけで行うことは、[決定の文書も、多言語の対で持てる](languages-and-guides.ja.md#決定の文書も多言語の対で持てる)で決める。list と query には、言語を選ぶオプションを作らない。

### 確認すること

- C-core-pairs-15 決定の文書の対の両方の側に同じ確認することの ID があっても、check は ID の重なりの誤りを出さない
- C-core-pairs-16 "kotowari list" と "kotowari query" は、決定の文書の対について、先頭の言語の側の決定と確認することの行だけを出す
- C-core-pairs-18 面が仕様に引用されているかは、決定の文書の先頭の言語の側だけで判定し、ほかの言語の側にだけ書かれた名前は引用として数えない

## 曖昧語の検査は、決定の文書のどの側の「決めたこと」と「確認すること」にも行う

状態: 実装済み

### 問題

文の検査は、側ごとに文が違うので側ごとに要る。曖昧語の一覧を言語ごとに持たなくても、英語の語を足したければ同じ一覧に足せば済み、日本語の文に英単語の照らし合わせが走っても害は無い。

### 決めたこと

曖昧語の検査（[用語集は人が読む文書として残し、用語の検査はやめる](decision-documents.ja.md#用語集は人が読む文書として残し用語の検査はやめる)）は、決定の文書のどの側の「決めたこと」と「確認すること」にも行う。曖昧語の一覧は言語ごとに持たず、設定の "vague_words" の1つの一覧をどの側にもかける。

### 確認すること

- C-core-pairs-17 決定の文書のほかの言語の側の「決めたこと」か「確認すること」に、設定の "vague_words" の語があると、check がその側に指摘を出す
