# 設定で足す問い合わせ

[English](query-rules.md) | 日本語

設定の "tests.rules" で足す問い合わせの形と読み方、同梱の問い合わせとの関係、ルールのファイルに誤りがあるときの扱いを扱う。同梱の問い合わせは[同梱の問い合わせ](test-queries.ja.md)、問い合わせをファイルに当ててテストを見つける規則は[テストの見つけ方](test-discovery.ja.md)で決める。

## 設定の tests.rules で問い合わせを足し、同梱の問い合わせは外せない

状態: 実装済み

### 問題

何をテストと数えるかは、採用しているテストのライブラリで変わる。Rust では "tests.rust.attributes" で属性を足せるが、同じことが TypeScript、Python、Php のライブラリでも起きる。同梱の問い合わせだけだと、ライブラリが増えるたびに kotowari 本体を直すことになる。

### 決めたこと

kotowari は同梱の問い合わせを設定によらず使い、プロジェクトは設定の "tests.rules" で問い合わせを足せる。関係は足すだけで、設定で同梱の問い合わせを外したり置き換えたりはできない。"tests.rust.attributes" と同じ扱いで、同梱の問い合わせが誤って当たっても、テストのファイルは "tests.files" の glob で絞れるので実害は小さい、と利用者が判断した。

設定に書く正規表現を退けた理由は、行を正規表現で探すと誤検出することだった（[テストは構文木に問い合わせを当てて見つけ、行の正規表現では探さない](test-discovery.ja.md#テストは構文木に問い合わせを当てて見つけ行の正規表現では探さない)）。構文木の節に当てるルールは、これに当たらない。

### 見送った案

- 同梱の問い合わせだけにし、設定で足せないままにする。採用しているライブラリが増えるたびに、kotowari 本体を直すことになる。
- 以前の決定: 設定で問い合わせを足せないことを、禁止として決めておく。足せないと上の問題が起きるので、やめた。

### 確認すること

- C-core-qrules-1 "tests.rules" のルールが当たった節が、テストと数えられる
- C-core-qrules-2 "tests.rules" で同じ言語にルールを足しても、同梱の問い合わせはそのまま効く

## ルールのファイルは、ast-grep のルールの YAML をそのまま読む

状態: 実装済み

### 問題

問い合わせを足すのは使う人なので、ルールの形は使う人との約束になる。kotowari が独自の形を作ると、何が当たるかを kotowari を通さずに確かめられない。

### 決めたこと

"tests.rules" には、ast-grep のルールの YAML のファイルのパスを並べる。ファイルの中身は ast-grep のルールの形をそのまま使い、形を自作しない。ルールのファイルがそのまま "ast-grep scan -r" で試せ、何が当たるかを kotowari を通さずに確かめられる。kotowari の側の約束は、ルールが当たった節をテスト、"$NAME" に入ったものをテストの名前にすることだけである（[テストの名前は、問い合わせが捕まえた文字から取る](test-discovery.ja.md#テストの名前は問い合わせが捕まえた文字から取る)）。

1つのファイルに "---" で区切って複数のルールを並べてよい。各ルールは、その "language" の言語の問い合わせに加わる。"language" は ast-grep と同じく大文字小文字を区別せずに突き合わせ、ast-grep の言語の別名（例: "ts"、"py"）も受ける。TypeScript と Tsx は ast-grep と同じく別の言語で、"language: typescript" のルールは ".tsx" のファイルに当たらない。

"tests.rules" の既定は空の一覧で、値は[基準のディレクトリからの相対パス](base-directory.ja.md#設定ファイルの値のパスと出力の-path-は基準のディレクトリからの相対にする)の一覧にする。glob は使えない。"mutants.equivalents"（[等価の判断は、設定の mutants.equivalents が指す YAML の一覧に置く](equivalents.ja.md#等価の判断は設定の-mutantsequivalents-が指す-yaml-の一覧に置く)）と同じく、パスそのものを書く形にそろえた。

### 見送った案

- 設定ファイルの中にルールを書く。ルールを kotowari を通さずに試しにくい。

### 確認すること

- C-core-qrules-3 "tests.rules" の既定は空の一覧で、値はパスの一覧として読まれる
- C-core-qrules-4 "---" で区切って並べたルールはすべて効き、ルールの "language" の言語（例: "go"）が問い合わせのある言語になる
- C-core-qrules-5 ルールの "language" は大文字小文字を区別せずに突き合わせ（"PY"）、言語の別名（例: "ts"）も受ける
- C-core-qrules-6 "language: typescript" のルールは、".tsx" のファイルに当たらない

## ルールの files と ignores は、ast-grep と同じ読み方で守る

状態: 実装済み

### 問題

ルールを、テストのファイルの一部だけに当てたいことがある。ast-grep のルールの形は "files" と "ignores" でこれを書ける。

### 決めたこと

ルールに "files" か "ignores" があれば、その glob を、テストのファイルの基準のディレクトリからの相対パスに当て、"files" に当たらないか "ignores" に当たるテストのファイルには、そのルールを当てない。glob は ast-grep と同じ読み方にし、"tests.files" の読み方には合わせない。"ast-grep scan" で試したときと同じ結果になる。

### 確認すること

- C-core-qrules-7 "files" のあるルールは当たるファイルにだけ当て、"ignores" に当たるファイルには当てない

## ルールの fix、message、severity、note、metadata は使わない

状態: 実装済み

### 問題

ast-grep のルールには、テストを見つけるのに関係の無い項目（直し方、伝える文、重大度など）がある。これを kotowari がどう扱うかを決める必要がある。

### 決めたこと

ルールの "fix"、"message"、"severity"、"note"、"metadata" は、テストの見つけ方に使わない。"severity" が "off" のルールも当てる。ルールを止めたいときは、"tests.rules" から外す。

### 確認すること

- C-core-qrules-8 "severity: off" のルールも当て、"fix"、"message"、"note"、"metadata" があっても、数えるテストは変わらない

## ルールのファイルに誤りがあれば、設定の誤りとして停止する

状態: 実装済み

### 問題

ルールのファイルが読めないのに黙って読み飛ばすと、足したはずのテストが数えられないまま検査が通る。止めるときは、直すべきルールのファイルが分かる必要がある。

### 決めたこと

次のどれかに当たれば、kotowari は設定の誤りを理由に停止する。今の設定の誤りと同じ扱いにする。

- "tests.rules" のパスのファイルが無い、パスがファイルでない、読めない、UTF-8 でない
- 同じパスが2回並んでいる
- YAML として読めない、ast-grep のルールとして読めない
- ルールの "language" が、[拡張子と言語の対応](test-discovery.ja.md#拡張子と言語の対応は-ast-grep-と同じにし大文字小文字を区別する)の言語に無い

ルールの "id" の重なりは見ない。kotowari はルールの "id" を使わない。

停止するときの詳細は、ルールのファイルの基準のディレクトリからの相対パスと、誤りの説明にする。直すべきなのはルールのファイルなので、そのパスを出すほうが役に立つ。"language" が知らない言語のときの説明は "unknown language: <言語>" の1行にし、ライブラリの文言や複数行の抜粋を出さない。停止の理由の文言は、[停止の理由は、英語の固定の文言で示す](cli-environment.ja.md#停止の理由は英語の固定の文言で示す)で決める。

### 確認すること

- C-core-qrules-9 ルールのファイルが無い、ディレクトリである、UTF-8 でない、YAML として読めない、ルールとして読めない、知らない "language" を持つ、同じパスが2回並ぶ、のどれでも、終了コードは 2 で、標準エラーは "config error" で始まる
- C-core-qrules-10 ルールのファイルで停止するとき、標準エラーはそのルールのファイルのパスを含み、".kotowari/config.yaml" を含まない
- C-core-qrules-11 知らない "language" で停止するとき、標準エラーはルールのファイルと "unknown language: <言語>" を含む1行になる
