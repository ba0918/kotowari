# スキーマの解決

[English](schema-resolution.md) | 日本語

文書の frontmatter の "$schema" が指すスキーマを、どう見つけ、取得し、キャッシュするかを扱う。スキーマに何を書くかは[「スキーマ言語の骨格」の話題](schema-language.ja.md)で決める。ファイルと URL からの読み込みを CLI と外のアプリで共用することは[スキーマと文書の読み込みは、別のクレートに置いて CLI と外のアプリで共用する](library-io.ja.md#スキーマと文書の読み込みは別のクレートに置いて-cli-と外のアプリで共用する)で決める。どの入力で停止するかはこの話題で決め、停止をどう知らせるか（終了コードと停止の理由の名前）は[「CLI と結果の出し方」の話題](cli.ja.md#停止の理由は5つにする)で決める。

## スキーマは文書の位置からの相対パスか URL で指定する

状態: 実装済み

### 問題

mds は、LLM が書いた Markdown の書式を機械的に固定するために、文書の frontmatter の "$schema" が指すスキーマで文書を検査し、値を抽出する。複数のリポジトリで同じ書式を共有するには、スキーマを URL で指せる必要がある。

相対パスに ".." を重ねたとき、前に積んだ ".." を後の ".." で打ち消すと、文書が意図しないスキーマで黙って検証される。これを防ぐ決まりを決めた理由は、記録に残っていない。

### 決めたこと

スキーマの指定は、文書の位置からの相対パスと URL の2つを受ける。指定は次の順で解く。

| 順 | "$schema" の値 | 解き方 |
|---|---|---|
| 1 | 無い、空、空白だけ、文字列でない。または frontmatter がマッピングでない | 停止する（[frontmatter が壊れているか、スキーマを指していない文書は、検査せずに停止する](#frontmatter-が壊れているかスキーマを指していない文書は検査せずに停止する)） |
| 2 | "http://" か "https://" で始まる | URL として取得し、キャッシュに置く（[URL のスキーマは取得した内容をキャッシュに置き、壊れていれば取得し直す](#url-のスキーマは取得した内容をキャッシュに置き壊れていれば取得し直す)、[URL のスキーマを取得できないときと、取得が上限を超えたときは停止する](#url-のスキーマを取得できないときと取得が上限を超えたときは停止する)） |
| 3 | それ以外 | 文書の位置からの相対パスとして読む。読めなければ停止する |

相対パスは、文書の置かれた位置を基準に解く。基準のディレクトリは、相対パスを解くのには使わない。".." を重ねた相対パスは、重ねたとおりに辿り、前の ".." を後の ".." で打ち消さない。

### 確認すること

- C-schema-resolve-1 "$schema" の値が "http://" か "https://" で始まれば URL として、それ以外は相対パスとして読む
- C-schema-resolve-2 相対パスのスキーマは、文書の置かれた位置を基準に解かれる
- C-schema-resolve-13 ".." を重ねた相対パス（例えば "../../wrong.yaml"）は、文書の位置から重ねたとおりに解かれ、重ねた ".." が打ち消されない

## frontmatter が壊れているか、スキーマを指していない文書は、検査せずに停止する

状態: 実装済み

### 問題

スキーマを解けない以上、検査の結果は出せない。部分的な結果を出したり、読めない入力を黙って飛ばしたりすると、検査していない文書が通ったように見える。

"$schema" の値が文字列でないときを停止にした理由は残っていない。

### 決めたこと

frontmatter が YAML のマッピングでないとき、"$schema" の値が空か空白だけのとき、"$schema" の値が文字列でないときは、frontmatter が壊れているとして、部分的な結果を出さずに停止する。

ファイルを対象に指定した文書に "$schema" が無いとき、相対パスのスキーマを読めないときも停止する。ディレクトリを対象にしたときに "$schema" の無い文書をどう扱うかは、[ディレクトリの検査は、$schema を持つ文書だけを検査し、. で始まるディレクトリとシンボリックリンクを辿らない](cli.ja.md#ディレクトリの検査はschema-を持つ文書だけを検査し-で始まるディレクトリとシンボリックリンクを辿らない)で決める。

### 確認すること

- C-schema-resolve-3 frontmatter が YAML のマッピングでない、"$schema" の値が空・空白だけ・null・文字列でない文書は、frontmatter の誤りになり、check、values、ast --schema は検査せずに停止する
- C-schema-resolve-4 ファイルを対象に指定した文書に "$schema" が無いときと、相対パスのスキーマを読めないときは、check、values、ast --schema が停止する

## URL のスキーマは取得した内容をキャッシュに置き、壊れていれば取得し直す

状態: 実装済み

### 問題

URL のスキーマを毎回取得すると、検査が外部に依存する。

キャッシュの置き場は、基準のディレクトリの探し方が既に決まっていたので、それに揃えた。kotowari と mds で基準のディレクトリの目印を揃えると、乱立しがちな隠しディレクトリが1つ減る。".kotowari/cache/" だけでは何のキャッシュか分からないので、用途ごとのサブディレクトリにする。後でキャッシュが増えても責務が混ざらず、1つだけ消すこともでき、.gitignore は1行のまま済む。

### 決めたこと

URL のスキーマは、取得した内容を SHA-256 の名前でキャッシュに置き、次からはキャッシュを読む。キャッシュが壊れていれば、取得し直して回復する。

基準のディレクトリは、カレントディレクトリから上に向かって探し、最初に見つかった ".kotowari/" のあるディレクトリとする。見つからなければカレントディレクトリとする。".mds/" は見ない。

キャッシュは、基準のディレクトリの ".kotowari/cache/schemas/" に置く。".kotowari/cache/" は消しても作り直せるものの置き場で、その直下にはファイルを置かず、用途ごとのサブディレクトリに分ける。

### 見送った案

- ".mds/" も探す互換を持つ。探し方が2通りになり、両方あるときの優先を決める必要が出る。まだ使っている人がほぼいない段階なので、互換は持たない。
- ".kotowari/schema-cache/" のように、用途ごとに ".kotowari/" の直下に置く。キャッシュが増えるたびに、直下の名前と .gitignore の行が増える。

### 確認すること

- C-schema-resolve-5 URL のスキーマは1回目に取得してキャッシュに置かれ、2回目からは取得せずにキャッシュを読む
- C-schema-resolve-6 壊れたキャッシュがあれば、スキーマを取得し直し、取得した内容でキャッシュを書き直して、検査を続ける
- C-schema-resolve-7 キャッシュは、カレントディレクトリより上に ".kotowari/" のあるディレクトリがあればその ".kotowari/cache/schemas/" に置かれてカレントディレクトリの下には置かれず、上のどこにも無ければカレントディレクトリの ".kotowari/cache/schemas/" に置かれる

## キャッシュに書けなくても、取得した内容で検査を続ける

状態: 実装済み

### 問題

キャッシュは取得を省くためのもので、取得した内容は手元にある。キャッシュに書けないときに止めると、読み取り専用の環境で検査が使えなくなる。

### 決めたこと

URL のスキーマをキャッシュに書けないとき（キャッシュのディレクトリを作れないときと、キャッシュに書けないとき）、mds は誤りにも指摘にもせず、取得した内容で検査を続ける。

### 確認すること

- C-schema-resolve-8 キャッシュのディレクトリを作れないときも、キャッシュのファイルを書けないときも、取得したスキーマで検査を続け、誤りにならない

## URL のスキーマを取得できないときと、取得が上限を超えたときは停止する

状態: 実装済み

### 問題

壊れたサーバにメモリを食い潰されたり、応答しないサーバで無期限に止まったりしないための上限が要る。大きなスキーマが使えないことは、利用者から見える振る舞いになる。スキーマを取得できないときに部分的な結果を出すと、検査していない文書が通ったように見える。

### 決めたこと

URL のスキーマを取得できないときは停止する。応答が 4MiB を超えたとき、または取得全体が10秒を超えたときも停止する。

### 確認すること

- C-schema-resolve-9 キャッシュが無く、URL のスキーマのサーバに接続できないときは停止する
- C-schema-resolve-10 応答が 4MiB を超えるとき、または取得全体が10秒を超えるときは停止する
- C-schema-resolve-11 ちょうど 4MiB の応答を時間内に返す URL のスキーマは、停止せずに使われる

## 停止の説明に URL を載せるときは、認証情報を伏せる

状態: 実装済み

### 問題

標準エラーはログや CI の出力へ流れる。取得に失敗した URL をそのまま載せると、"$schema" に書いた認証情報がそこへ複製される。伏せるのは、値を最初に扱う時点でなければ意味がない。

### 決めたこと

停止の説明に URL を載せるとき、mds はその URL の authority にある認証情報を伏せる。

### 確認すること

- C-schema-resolve-12 認証情報を含む URL のスキーマの取得に失敗すると、標準エラーに認証情報は出ず、URL は認証情報を伏せた形で出る。認証情報の無い URL と、パスに "@" を含む URL は、そのまま出る
