# 文書の骨格

[English](document-structure.md) | 日本語

題名、前置部、節、項目という文書の骨格を、スキーマがどう検証するかを扱う。見出しの下に並ぶ行の読み分けと制約は[見出しの下の行の規則](block-rules.ja.md)で、宣言していない見出しと行を許すかどうかは[「閉じた世界と開いた世界」](closed-world.ja.md)の話題で、出現回数の指摘が数えた規則種別を持つことは[出現回数の指摘に、数えたノードの規則種別を持たせる](cli.ja.md#出現回数の指摘に数えたノードの規則種別を持たせる)で決める。

## 見出しの骨格は、題名・節・項目の3段で閉じる

状態: 実装済み

### 問題

見出しの入れ子をどこまで許すかを決める必要がある。対象にする文書の形は3段で足りる。任意の深さの入れ子は、規則と抽出の両方を複雑にする。

### 決めたこと

スキーマが宣言できる見出しの深さは、題名（深さ1）、節（深さ2）、項目（深さ3）の3段だけにする。再帰的な任意の深さの入れ子は持たず、項目の下にさらに見出しのノードを宣言する手段は持たない。

深さ4以上の見出しは、指摘にする。

### 確認すること

- C-schema-doc-1 深さ4以上の見出しは、heading_level_mismatch の指摘になる
- C-schema-doc-2 （読んで確認）スキーマの言葉に、項目の下に見出しのノードを宣言する手段が無い

## スキーマが題名を宣言したときだけ、題名をちょうど1つ求める

状態: 実装済み

### 問題

「常に題名をちょうど1つ求める」とすると、閉じた世界では、題名を宣言しないスキーマの題名は宣言していない見出しになり、2つの決まりが両立しない。題名を持たない形式の文書も書けるようにしたい。

### 決めたこと

スキーマが題名を宣言したとき、文書が題名をちょうど1つ持つことを求める。題名が無いときは、missing_title の指摘を1件出す。

題名を宣言しないスキーマは、題名を求めない。文書に題名があれば、宣言していない見出しになる（[既定は閉じた世界にし、宣言していない見出しと行を指摘にする](closed-world.ja.md#既定は閉じた世界にし宣言していない見出しと行を指摘にする)）。

### 見送った案

- 題名を宣言しないスキーマでも、題名を求める。題名を持たない形式を表せなくなる。

### 確認すること

- C-schema-doc-3 題名を宣言したスキーマで、題名の無い文書には missing_title の指摘が1件出て、その指摘は行番号を持たない
- C-schema-doc-4 題名を宣言しないスキーマでは、題名の無い文書で "kotowari-mds check" の終了コードが 0 になり、題名のある文書では、閉じた世界でその題名が宣言していない見出しの指摘になる

## 2つ目以降の題名は、題名ごとに1件の指摘にする

状態: 実装済み

### 問題

指摘を読む人が知りたいのは、消すべき方の題名である。題名がいくつあっても1件しか出さないと、3つ目以降の題名が知らされない。

### 決めたこと

題名が2つ以上あるときは、2つ目以降の題名ごとに multiple_titles の指摘を1件ずつ出す。指摘には、その題名の行番号と生の行を持たせる。

### 確認すること

- C-schema-doc-5 題名が2つ以上ある文書では、2つ目以降の題名ごとに multiple_titles の指摘が1件ずつ出て（題名が3つなら2件）、それぞれの行番号と生の行は、その題名の行とその文字そのままである

## 題名が2つ以上あっても、1つ目の題名を正規表現と照合する

状態: 実装済み

### 問題

題名が複数あることと、題名が正規表現に合わないことは、別の問題である。片方を出したら、もう片方を隠す理由は無い。隠すと、2つ目の題名を消したあとで初めて、1つ目の誤りに気づくことになる。

### 決めたこと

スキーマが題名に正規表現を宣言したときは、題名が2つ以上あっても1つ目の題名を照合し、合わなければ title_pattern_mismatch の指摘も出す。

### 見送った案

- 題名が複数あるときは、正規表現と照合しない。

### 確認すること

- C-schema-doc-6 題名に正規表現を宣言したスキーマでは、1つ目の題名が合わなければ、題名が2つ以上あっても、その行に title_pattern_mismatch の指摘が出て、2つ目の題名の行には multiple_titles の指摘が出る

## 2つ目以降の題名は、それまでの節と項目を終える

状態: 実装済み

### 問題

抽出の要素の範囲（[要素の最後の行は、次の同じ深さか浅い見出しの手前の行にする](extraction.ja.md#要素の最後の行は次の同じ深さか浅い見出しの手前の行にする)）は、すでに題名を区切りにしていて、項目の最後の行は題名の手前だった。それなのに、文書の木を組むときだけ、題名の後の行を前の項目に入れていた。区切り方を1つにそろえる。

### 決めたこと

2つ目以降の題名は、それまでの節と項目を終える。その後の行は、次の節までは前置部の行として読む。

### 見送った案

- 後の行を前の項目に入れる今の組み方を残し、要素の範囲の方を変える。題名の後の行が、前の項目の本文として出る。

### 確認すること

- C-schema-doc-7 項目の文の後に2つ目の題名とその後の行を持つ文書では、"kotowari-mds values --format json" で、項目の文の要素は2つ目の題名より前の行だけになる

## 前置部には、その内側のノードに規則と抽出を宣言する

状態: 実装済み

### 問題

前置部は、題名の後、最初の節より前の部分で、フィールド行、文、箇条書き、表、コードブロックを置ける。抽出を宣言できるノードを表にしたとき、前置部も並べていたが、実装の前置部には抽出の鍵が無く、書いた時点でスキーマの誤りになっていた。実物を確かめずに類推で並べた誤りとして直した。

### 決めたこと

前置部そのものには、抽出の鍵を持たせない。前置部の抽出と規則は、その内側のノード（フィールド行、文、箇条書き、表、コードブロック）に宣言する。

### 確認すること

- C-schema-doc-8 前置部の内側に宣言した表とコードブロックは宣言していない行の指摘にならず、前置部の表に宣言した抽出は、宣言したヘッダの名前を鍵にした行ごとの値を返す
- C-schema-doc-9 前置部そのものに抽出を書いたスキーマは、停止になる

## 節は、見出しの文字で見分ける

状態: 実装済み

### 問題

検査の既定は閉じた世界で、書式を固定するのが目的なので、宣言していない節を黙って通すと目的を果たさない。節が宣言と同じかは、見出しの文字で見分ける。ところが、強調、太字、リンク、コードの中の文字は名前に残すのに、打ち消し線だけは中の文字ごと捨てていた。そのため、宣言した名前と同じ見出しが宣言していない節になり、必須の節の欠落も出ていた。

### 決めたこと

節は、見出しの文字で見分け、スキーマが宣言した名前と一致しない節を指摘にする。見出しの文字は、インラインの記法を除いた文字とし、打ち消し線の中の文字も残す。

### 確認すること

- C-schema-doc-10 スキーマが宣言した名前と一致しない節の見出しは、宣言していない見出しの指摘になり、宣言した節が無ければ、その節が欠けた指摘になる
- C-schema-doc-11 "Ax" の節を宣言したスキーマで、"A" と打ち消し線で囲んだ "x" からなる見出しの節を持つ文書は、"kotowari-mds check" の終了コードが 0 になる

## 項目の見出しは、":" の前を ID、後を名前として読む

状態: 実装済み

### 問題

項目は、ID と名前を持つ深さ3の見出しである。見出しのどこまでを ID とし、ID の形をどう縛るかを決める必要がある。理由は残っていない。

### 決めたこと

項目の見出しは、次のとおりに読む。

| 順 | 見出しの形 | 読み方 |
|---|---|---|
| 1 | 区切りのコロンが無い | ID の形に合わない指摘 |
| 2 | コロンがあり、その前がスキーマの正規表現に合う | 先頭から ":" の直前までを ID、その後を名前として読む |
| 3 | コロンがあり、その前が正規表現に合わない | ID の形に合わない指摘 |

ID の形に合わない指摘は、invalid_id にする。

### 確認すること

- C-schema-doc-12 ":" の無い項目の見出しと、ID がスキーマの正規表現に合わない項目の見出しは、invalid_id の指摘になる

## 項目を宣言していない節の中の、深さ3の見出しは指摘にする

状態: 実装済み

### 問題

検査の既定は閉じた世界で、書式を固定するのが目的なので、宣言していない見出しを黙って通すと目的を果たさない。理由は、閉じた世界の理由のほかは残っていない。

### 決めたこと

項目を宣言していない節の中に深さ3の見出しがあるときは、その見出しと、その内側の行を指摘にする。開いた世界でも同じにする（[開いた世界は、宣言していない構造とその内側だけを許す](closed-world.ja.md#開いた世界は宣言していない構造とその内側だけを許す)）。

### 確認すること

- C-schema-doc-13 項目を宣言していない節の中の深さ3の見出しは、開いた世界でも、宣言していない見出しの指摘になり、その内側の行も宣言していない行の指摘になる

## スキーマは、節を挟まない文書の直下の項目を "document.item" に宣言できる

状態: 実装済み

### 問題

節を挟まずに項目を並べる文書（kotowari の問題の記録がそうだった）を、その形のまま読みたい。スキーマの言葉では、項目を節の下にしか宣言できなかった。宣言しないスキーマの振る舞いは変えない。

### 決めたこと

スキーマは、文書の直下の項目を "document.item" に、節の下の "item" と同じ形で宣言できる（根のノードとして受けることは[スキーマは YAML で書き、題名・前置部・節・文書の直下の項目を根に置く](schema-language.ja.md#スキーマは-yaml-で書き題名前置部節文書の直下の項目を根に置く)で決める）。宣言したときは、最初の節より前にある深さ3の見出しをその項目として読み、前置部を、最初の節か項目の手前で終える。同じ文書に、節の下の項目と文書の直下の項目の両方があってもよい。

### 確認すること

- C-schema-doc-14 "document.item" と節の下の "item" の両方を宣言したスキーマでは、前置部の文の後の、節を挟まない深さ3の見出しの項目と、節の下の項目のどちらも、"kotowari-mds check --format json" で指摘が出ず、"kotowari-mds values --format json" の値に出て、前置部の文の値には文書の直下の項目の行が入らない

## 文書の直下の項目を宣言しないスキーマでは、最初の節より前の深さ3の見出しを、前置部を宣言したか閉じた世界のときだけ指摘にする

状態: 実装済み

### 問題

文書の直下の項目を宣言しないスキーマで、最初の節より前にある深さ3の見出しをどう扱うかを決める必要がある。節の中の宣言していない項目（[項目を宣言していない節の中の、深さ3の見出しは指摘にする](#項目を宣言していない節の中の深さ3の見出しは指摘にする)）と同じ扱いにしたいが、そのまま持ち込むと、開いた世界の決まりまで持ち込んでしまう。開いた世界は、宣言していない構造とその内側を許し、宣言済みの前置部・節・項目の中だけは許さない（[開いた世界は、宣言していない構造とその内側だけを許す](closed-world.ja.md#開いた世界は宣言していない構造とその内側だけを許す)）。

題名より前にある見出しは、題名の無い文書のものも含めて、前置部の外にある。題名の無い文書には題名の欠落の指摘が別に立つので、実害は無い。

### 決めたこと

文書の直下の項目を宣言しないスキーマでは、前置部を宣言したときか閉じた世界のとき、最初の節より前にある深さ3の見出しと、その内側の行（フィールド行も文も）を指摘にする。前置部を宣言しない開いた世界では、宣言していない構造として許す。

題名より前にある深さ3の見出しは、題名の無い文書のものも含めて前置部の外にあるとし、開いた世界では、前置部を宣言していても、その見出しと内側の行を宣言していない構造として許す。

### 確認すること

- C-schema-doc-15 節の下にだけ項目を宣言したスキーマでは、最初の節より前の深さ3の見出しに指摘が出て、前置部を宣言したスキーマでは、開いた世界でも、前置部の中の深さ3の見出しとその内側の行に指摘が出る
- C-schema-doc-16 "open: true" で、文書の直下の項目も前置部も宣言しないスキーマでは、最初の節より前の "### X-1: a" の見出しにも、その下の行にも指摘が出ない
- C-schema-doc-17 "open: true" で、題名と前置部を宣言し、文書の直下の項目を宣言しないスキーマでは、題名の無い文書の最初の節より前の "### a" の見出しとその下の行に指摘が出ず、指摘は題名の欠落の1件だけになる

## 項目が足りないときは、出現回数を書いたかを問わず、下限を割った指摘にする

状態: 実装済み

### 問題

項目には、欠落を表す指摘の種類が無い。既定の出現回数も「ちょうど1個」という出現回数なので、下限の指摘で表すのが一貫する。実装も、項目を常に出現回数で数えていた。

### 決めたこと

項目が足りないときは、出現回数を書いたかどうかを問わず、下限を割ったものとして repeat_min_not_met の指摘にする。出現回数を書かないときの下限は、既定のちょうど1個（[出現回数は5つの書き方で宣言する](schema-language.ja.md#出現回数は5つの書き方で宣言する)）の1である。このとき、節の欠落の指摘 missing_required_section は出さない。missing_required_section は、節の欠落にだけ出る。

### 確認すること

- C-schema-doc-18 出現回数を書かない項目を節に宣言したスキーマでは、項目の無い節の行に repeat_min_not_met の指摘が1件だけ出て、missing_required_section の指摘は出ない

## 深さ4以上の見出しは、それを含む前置部・節・項目の行として読み、"subheading" を宣言しなければ指摘にする

状態: 提案

### 問題

深さ4以上の見出しは、どこにあっても heading_level_mismatch の指摘になる。項目の中に小見出しを置く文書は、小見出しを消すほかに通す手段が無い。小見出しで項目を終えると、小見出しの後の行が、その項目の検査と抽出から外れる。

### 決めたこと

深さ4以上の見出しは、それを含む前置部、節、項目の中の行として読む。そのノードを終えず、後の行も同じノードの行として読む。項目と節の最後の行は、[要素の最後の行は、次の同じ深さか浅い見出しの手前の行にする](extraction.ja.md#要素の最後の行は次の同じ深さか浅い見出しの手前の行にする)のとおりで、深さ4以上の見出しで区切らない。

深さ4以上の見出しを含むノードが "subheading"（[深さ4以上の見出しの規則 "subheading" を、前置部・節・項目に宣言できる](schema-language.ja.md#深さ4以上の見出しの規則-subheading-を前置部節項目に宣言できる)）を宣言していれば、その規則に照らす。宣言していなければ、heading_level_mismatch の指摘にする。"open: true" を宣言したノードの中でも、開いた世界で許す宣言していない構造の中でも、同じにする。

### 見送った案

- 以前の決定: 深さ4以上の見出しは、指摘にする（[見出しの骨格は、題名・節・項目の3段で閉じる](#見出しの骨格は題名節項目の3段で閉じる)の決めたことの2段目）。項目の中の小見出しを通す手段が無いので、やめた。

### 確認すること

- C-schema-doc-20 "subheading" を宣言しないスキーマでは、深さ4以上の見出しは、"open: true" を宣言した項目の中でも、開いた世界の宣言していない節の中でも、heading_level_mismatch になる
- C-schema-doc-21 項目の中の "####" の見出しの後の箇条書きは、同じ項目の箇条書きの規則で照合されて、その項目の抽出に入り、その項目の "end" は、次の "###"、"##" か "#" の見出しの手前の行になる
- C-schema-doc-22 "subheading" を宣言した項目の中の深さ4以上の見出しには、heading_level_mismatch が出ない

## 名前も正規表現も持たない項目の規則が選んだ見出しだけを、":" の前の ID と後の名前に分けて読む

状態: 提案

### 問題

項目の見出しは、どれも ":" の前を ID、後を名前として読み、":" の無い見出しを invalid_id にする。名前で選ぶ項目の規則（[節と項目の規則は、見出しを名前の一覧か正規表現で選ぶ](schema-language.ja.md#節と項目の規則は見出しを名前の一覧か正規表現で選ぶ)）が選んだ "### 問題" のような見出しにも、ID の形を求めることになる。

### 決めたこと

項目の規則のうち、"name" も "pattern" も持たない規則（ID の規則）が選んだ見出しだけを、次のとおりに読む。

| 順 | 見出しの形 | 読み方 |
|---|---|---|
| 1 | 区切りのコロンが無い | ID の形に合わない指摘 |
| 2 | コロンがあり、その前がスキーマの正規表現に合う | 先頭から ":" の直前までを ID、その後を名前として読む |
| 3 | コロンがあり、その前が正規表現に合わない | ID の形に合わない指摘 |

ID の形に合わない指摘は、invalid_id にする。

"name" か "pattern" の規則が選んだ見出しには、ID の形を求めない。その項目の名前は見出しの文字の全体で、その項目は ID を持たない。

### 見送った案

- 以前の決定: 項目の見出しは、どれも ":" の前を ID、後を名前として読む（[項目の見出しは、":" の前を ID、後を名前として読む](#項目の見出しは-の前を-id後を名前として読む)）。名前で選ぶ項目の見出しにも ID の形を求めることになるので、ID の規則にだけ当てる。

### 確認すること

- C-schema-doc-23 ID の規則が選んだ、":" の無い項目の見出しと、ID がその規則の正規表現に合わない項目の見出しは、invalid_id の指摘になる
- C-schema-doc-24 "name: 問題" の項目の規則が選んだ "### 問題" には invalid_id が出ず、その項目の抽出の "of" に "id" と "name" を宣言すると、"name" の値は "問題" になり、"id" の鍵は無い

## スキーマは、節を挟まない文書の直下の項目を "document.items" に宣言できる

状態: 提案

### 問題

節を挟まずに項目を並べる文書（kotowari の問題の記録がそうだった）を、その形のまま読みたい。項目の規則は、節の下では "items" の一覧に書く（[項目の規則は "items" に一覧で書き、"item" のキーは受けない](schema-language.ja.md#項目の規則は-items-に一覧で書きitem-のキーは受けない)）。文書の直下の項目も、同じ形で書けるようにする。宣言しないスキーマの振る舞いは変えない。

### 決めたこと

スキーマは、文書の直下の項目の規則を "document.items" に、節の下の "items" と同じ形の一覧で宣言できる。宣言したときは、最初の節より前にある深さ3の見出しを、その一覧の規則が選ぶ項目として読み、前置部を、最初の節か項目の手前で終える。同じ文書に、節の下の項目と文書の直下の項目の両方があってもよい。

### 見送った案

- 以前の決定: 文書の直下の項目は "document.item" に1つの規則で宣言する（[スキーマは、節を挟まない文書の直下の項目を "document.item" に宣言できる](#スキーマは節を挟まない文書の直下の項目を-documentitem-に宣言できる)）。項目の規則を "items" の一覧にそろえたので、やめた。

### 確認すること

- C-schema-doc-25 "document.items" と節の下の "items" の両方を宣言したスキーマでは、前置部の文の後の、節を挟まない深さ3の見出しの項目と、節の下の項目のどちらも、"kotowari-mds check --format json" で指摘が出ず、"kotowari-mds values --format json" の値に出て、前置部の文の値には文書の直下の項目の行が入らない
