# 閉じた世界と開いた世界

[English](closed-world.md) | 日本語

スキーマに宣言していない見出しと行を、検査でどう扱うかと、どこまで緩められるかを扱う。指摘の形と CLI の `--open` 以外のオプションは[「CLI と結果の出し方」の話題](cli.ja.md)で、ライブラリの検証の指定とスキーマの `open` の組み合わせは[ライブラリの検証は、スキーマの open を打ち消さない](library-extraction.ja.md#ライブラリの検証はスキーマの-open-を打ち消さない)で決める。

## 既定は閉じた世界にし、宣言していない見出しと行を指摘にする

状態: 実装済み

### 問題

mds は、LLM が書いた Markdown の書式を機械的に固定するための道具である。書式を固定するのが目的なので、スキーマに宣言していないものを黙って通すと、目的を果たさない。

### 決めたこと

検査の既定は閉じた世界にする。スキーマに宣言していない見出しは `undeclared_heading` の指摘に、宣言していない行は `undeclared_line` の指摘にする。

題名を宣言しないスキーマの文書にある題名や、題名より前に置いた見出しも、宣言していない見出しとして指摘にする。宣言していない見出しの内側の行も、宣言していない行として指摘にする。箇条書きの子の行をどう宣言するかは、[箇条書きの子の一覧は、宣言した子の規則に照らす](block-rules.ja.md#箇条書きの子の一覧は宣言した子の規則に照らす)で決める。

### 確認すること

- C-schema-closed-1 閉じた世界では、宣言していない節・項目・題名・題名より前の見出しが `undeclared_heading` に、その内側の行と、そのほかの宣言していない行（例えば、前置部や節の中の行と、箇条書きの中の行）が `undeclared_line` になる

## 開いた世界は、宣言していない構造とその内側だけを許す

状態: 実装済み

### 問題

宣言していないものを黙って通すと、書式を固定する目的を果たさない。緩める手段を持っても、それが宣言したはずの決まりまで外してしまうと、同じく目的を果たさない。緩める手段そのものを持つことにした理由は残っていない。

### 決めたこと

緩める手段は、スキーマの最上位の `open: true` と、`check` の `--open` の2つにする。どちらかがあれば開いた世界で検査し、宣言していない構造と、その内側のすべての行を許す。題名より前の見出しも、宣言していない構造の1つとして許す。

緩める手段は、緩める方向にしか働かない。開いた世界でも、次のものは許さない。

- 宣言済みの前置部、節、項目の中に足した、宣言していない構造と行
- 必須のノードの欠落
- 出現回数の違反と、形の違反

前置部を宣言しないスキーマで、最初の節より前にある深さ3の見出しをどう扱うかは、[文書の直下の項目を宣言しないスキーマでは、最初の節より前の深さ3の見出しを、前置部を宣言したか閉じた世界のときだけ指摘にする](document-structure.ja.md#文書の直下の項目を宣言しないスキーマでは最初の節より前の深さ3の見出しを前置部を宣言したか閉じた世界のときだけ指摘にする)で決める。抽出の結果が閉じた世界と開いた世界で変わらないことは、[抽出の結果は、閉じた世界と開いた世界のどちらで検査しても変わらない](extraction.ja.md#抽出の結果は閉じた世界と開いた世界のどちらで検査しても変わらない)で決める。

### 確認すること

- C-schema-closed-2 スキーマが `open: true` を宣言したとき（ディレクトリの検査を含む）と、`check` に `--open` を付けたときは、宣言していない節・前置部の行・題名より前の見出しと、それらの内側の行に指摘が出ない。題名を宣言しないスキーマの題名も同じ
- C-schema-closed-3 開いた世界でも、宣言済みの前置部・節・項目の中に足した、宣言していない見出しと行は指摘になる
- C-schema-closed-4 開いた世界でも、必須のノードの欠落は指摘になる
- C-schema-closed-5 どんな文書でも、開いた世界で出る指摘の集まりは、同じ文書を閉じた世界で検査したときに出る指摘の集まりに含まれる

## 宣言していない行の指摘に、その行をどう読んだかの種別を持たせる

状態: 実装済み

### 問題

宣言していない行の指摘が1つの種類しか持たないと、呼ぶ側は、それがフィールド行だったのか箇条書きだったのかを、指摘の詳細の文言か、生の行の文字を読み直して見分けることになる。詳細の文言に頼ると、言い換えたときに呼ぶ側が黙って壊れる。生の行を読み直すと、行の読み分けの判定を mds と呼ぶ側の2か所に持つことになる。mds は指摘を作る時点で、その行をどう読んだかを知っている。

### 決めたこと

宣言していない行の指摘には、その行を、名前と値の形の一覧の行（フィールド行）、箇条書き、順序付きリスト、文、表、コードブロックのどれとして読んだかを、構造として持たせる。

### 見送った案

- 呼ぶ側が、生の行の先頭の文字を見て種別を決める。行の読み分けの判定を2か所に持つことになる。

### 確認すること

- C-schema-closed-6 `undeclared_line` の指摘は、その行をどう読んだかの種別を持ち、宣言していないフィールド行はフィールド行、箇条書きの行は箇条書き、順序付きリストの行は順序付きリスト、表は表の種別になる（`check --format json` の出力でも同じ）
