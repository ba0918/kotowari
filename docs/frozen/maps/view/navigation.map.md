## あとでリンクにする所

- 冒頭の段落「一覧のページそのものの描き方と、題名・アウトライン・lead の並びは、描画の話題の決定で決める」: 描画の話題（元の `docs/ir/view/rendering.md` の REQ-view-005、REQ-view-006）
- 「一覧のカードには…」の決めたこと「添える文字は UI の文字から取る。数の入る UI の文字は "{n}" をちょうど1つ含み」: 言語の話題（元の `docs/ir/view/languages.md`、UI の文字）。"{n}" の決まり自体は kotowari の設定の検査の話題（localization A8）
- 「一覧のカードには…」の札 "open"、"planned": 部品の話題（元の `docs/ir/view/parts.md` の TBL-view-001、status の札）
- 「目次と食い違った入力も…」の問題「目次と元データの食い違いを検査するのは kotowari の側で、view は渡された入力を検査しない」: core の全体像の目次の検査の話題（overview_toc_* の指摘）と、描画の話題の「描画の入力を検査せず、誤りを出さない」（元の REQ-view-003。ファイルを読み書きしないことと同じ要求の中にある）

## 迷った判断と、どう決めたか

- スクリプトを入れない範囲を「どのページにも」にするか: REQ-view-018 で全ページに広げたのは LLM（overview-index A31）だが、利用者が採った localization A2（「どのページにもスクリプトを入れない決まりは変えない」）と A20（言語の切り替えにスクリプトを使わない）、overview-page-reading A6 が全ページの決まりとして扱っている。利用者が決めた範囲として残した。localization A2 は navigation.md の出典に無い記録の行で、範囲が利用者のものだと見分ける根拠にだけ使い、A2 の中身（明るい配色とダークの切り替えを作らず、OS とブラウザの設定に従う）は、この話題のどの要求にも無いので書かなかった。
- 文書の無い名前を目次の群の見出しの数に入れないこと: 明示したのは LLM（overview-index A35）だが、利用者の A18「目次にあって文書の無い名前は飛ばし」と、A13・A20「その下にあるページの数」から、文書の無い名前はページでなく数に入らない、と読んで、食い違った入力の決定と C-view-navigation-8 に残した。
- 同じ群へのリンクを「最後の節の後」に置くこと: 決めたのは LLM（overview-index A30）だが、利用者が overview-page-reading A7 で「今の位置（最後の節の後）のまま変えない」と採ったので残した。
- 同じ群へのリンクを「直下だけ」にすること: A30（LLM）を落とすと、何を並べるかが曖昧になる。利用者の A14「同じ目次の群に属するほかのページ」と A5「1つのページは階層のちょうど1か所に属する」から、属する群は直下の群に限られる、と読んで「その文書が属する目次の群に同じく属するほかの文書」と書いた。入れ子の群の中を除くという明示の一文は書かなかった。
- 「見送った案」に入れるもの: 記録の rejected の行だけにした。overview-page-reading A4（しきい値を作らない）と A6（スクロールの強調をしない）は、採らなかった案ではなく「しない」と決めた決定なので、「決めたこと」に書いた。
- 目次の群の見出しの UI の文字（A24 の「<数> ページ」など）: 利用者が文字まで決めたが、そのあと UI の文字として設定から取る形になり（localization A5、A9）、具体の文字は設定の値になった。決定には「UI の文字から取る」とだけ書き、具体の文字は書かなかった。
- 1つの元の ID の下に複数のテストがあると、表の形では、テストごとに行き先を分けられない。たとえば REQ-view-019 だけを指すテスト（目次の直下の文書のページの位置）も、表どおりに付け替えると C-view-navigation-6、9、10 の3つを指す。テストの側の名前と中身を見て、行き先を絞るのは付け替えの作業の側に任せる。
