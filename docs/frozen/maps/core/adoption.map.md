## 迷った判断と、どう決めたか

- 利用者の答え（取り込み）で、前の下書きの「利用者に聞くこと」の6つが決まった。問い1（確信が持てない行）: 「未決」の項目にする。問い2（旧資料なし、見えてテスト無し）: そうと示して追認の候補にする。問い3（作らないと答えた記述）: 決定の文書に書かない。問い4（用語の仕分け）: 手順から外す。問い5（すでにある決定）: 書き換えも削除もせず、食い違いは「未決」にしてその決定へリンクする。問い6（追認の重み）: 追認で書いた決定の「問題」に、見直さずに仕様とした、と1文書く。
- 問い5の前の推奨のうち、「実装が無く作る予定があると答えた決定は、状態を「提案」にする」は、答えの「書き換えも削除もせず」に反するので採らなかった。すでにある決定で実装が無いものは、状態が「提案」ならそのとおりで食い違いではなく、状態が「実装済み」なら実装との食い違いとして「未決」になる、と読んだ。だから、すでにある決定について作る予定を聞く行は置かず、一覧のラウンドで人が答えるのは前と同じ2つ（追認の候補で外す行、実装の無い旧資料の記述を作る予定）のままにした。
- contradiction の FLAG を「未決」の項目に読み替えた。decision-documents.ja.md の「人に戻す問題は…」が FLAGS.md を置き換えると明記していて、人が外した行や旧資料と実装の食い違いは、人の期待がどちらかを決めることなので、「未決に書くのは人が決めることだけ」にも当たると判断した。ambiguity も、利用者の答えで「未決」になった。
- 旧資料の判断の記録の決定が実装と一致する行（A20）は、出典の行が無くなっても、「残っている決定は追認より重い」という理由が残るので、一覧で追認を求めずに書く行き先として残した。
- 振る舞いはほぼ同じで、skill の文の名詞（要求、FLAG、IR、記録）だけが変わるものも「提案」にした。kotowari-adopt の skill がまだ書き直されておらず、読んで確かめる行が、今の文では通らないためである。
- requirement_without_test は、今のコードの指摘の名前 confirmation_without_test に読み替えた（`crates/kotowari-core/src/finding.rs`）。
